# D1 - PR #37 copytalk: how it works and why it fails on unseen kinds

_Written by the orchestrator from the Haiku agent's returned result (that agent ran past 200k tokens and never wrote its file)._

## Summary
The PR #37 copytalk talker (branch origin/claude/project-thread-utxkpw, reasoner_ptr/real/english/run_english.py) is a single-pass pointer head over per-token core states: a per-position start/end linear score (no question vector inside the span scorer), a gate over a closed list of 26 answers plus a span class, spans capped at 12 tokens, no autoregression. It reads only the core states h (not the reader output except in the nocore arm, not raw prompt word embeddings), so the answer must come out of the core. Its training data is the 48-question human bank plus 8000 generated examples from six practice families; the generated set has zero how/when/why questions (stub caveat). My substring-based taxonomy, re-run on all 6 seeds' exported rows (2,304 unseen-kind rows), reproduces the brief's 13.6% correct exactly and puts 51.6% of rows in wrong location and 27.0% in boundary errors (brief's categories, from ct_taxonomy.py:19: 47.0 and 31.2; a classifier-rule difference, not a data disagreement). The sharpest new finding is question-insensitivity: on unseen kinds, two different non-yes/no questions about the same passage get the identical span 59% of the time (335/564 pairs), versus 0% on practised heldout (seed 0). The predictions almost never equal the other question's answer (2.7%), so the head picks a near-constant location rather than answering the other question. The nocore arm is even more question-blind (99.5% identical on unseen, 100% on heldout), which fits the reader being a frozen causal LM whose passage states cannot see the question, while the core's blocks are bidirectional and can carry it. On unseen kinds the core mostly does not bind the question to the right position. Training 'where' questions (1,333, one family) all have first-sentence location answers in the three examples printed, while the unseen 'where' asks for the location after a move ('Where is the key now?' -> 'on the shelf'); the copy head gave 'key was in the drawer until Bem moved it to', which fits a first-location-phrase shortcut (untested). Boundary errors are mostly over-long (84.8% longer than gold). The talker head itself is 8,221 parameters (not ~2M as the brief says); the 9,303,405 total includes the 9,007,790-parameter core and an adapter that gets no gradient on this path. The LM-based allptr arm reads raw token embeddings (line 225) through a pretrained 1.2B, which is the likely source of its unseen-kind competence; each candidate fix acts on a different error bucket (listed in findings).

- **[suggested | medium]** Mechanism for location errors (suggested): the span scorer is unary per token, so the core must write 'this token answers this question' into each candidate's state. On unseen kinds it mostly does not (59% identical spans across questions; 2.7% matches to the other question's answer); the training stems never taught how/when/why binding, and 'where' was taught only as first-sentence phrases.
  - evidence: Combines the shown findings above with the code at run_english.py:177 and :208.
- **[suggested | low]** Mechanism for boundary errors (suggested, untested): the end head is a unary score, so with no phrase-end supervision beyond one canonical string per training example, it tends to extend to a clause boundary within the 12-token cap. Unseen answers are shorter and more often single-word (35% vs 20% in training), which the training prior does not match.
  - evidence: tax.py boundary-length result (84.8% too long); answer-length stats above; find_span labels at run_english.py:97-120.
- **[suggested | medium]** Fix options and what each changes mechanically (all suggested, untested): (1) answer-type conditioning adds a stem-dependent term to start/end logits; how/when/why have zero training rows, so those conditioning vectors stay untrained; expect gains only on what/which. (2) Question-keyed span scoring (bilinear or attention with a pooled question vector) makes each candidate's score depend on the question; it targets the 59% identical-span rate directly, and should lower identical pairs and raise the other-question-answer rate if it works. (3) Joint start/end scoring with a length prior changes only boundary errors (27-31% of rows) and leaves location untouched. (4) Reading notes exposes per-loop-step core states; helps only if the question binding appears at intermediate steps, which can be probed by the same pair test at steps 1-4. (5) A pretrained token-level path (as in allptr, run_english.py:225, which feeds raw token embeddings to a pretrained 1.2B LM) supplies question-to-passage reading that a 256-d core-state head lacks; the one-seed shuffled-core lesion (73.2%, RESULTS-CT) suggests allptr does not need the core on unseen kinds.
  - evidence: Code lines cited above; allptr lesion and numbers from RESULTS-CT.md (one seed, not re-measured here).
- **[shown | high]** The PR's 'label-free' and EmbeddingGemma-2 reader plan is not what this experiment tests: this is LiquidAI/LFM2.5-1.2B-Instruct as frozen reader (run_english.py:33, 55), so these results belong to the English-QA experiment, not to the planned 271M reader stack.
