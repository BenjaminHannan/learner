## Revised priorities (after Ben's review, 2026-09-19) — read this first

The 40-item "Tier A" below is a catalogue, not a plan. The plan is this focused sequence. **Scope note:** everything about cards, choosing and second lookups comes from the *small card experiments* (synthetic-vocabulary toy ladder, often with privileged supplied cards, 1-2 seeds). The *village-model (Core) results* (23% held-out etc.) are a separate track; findings do not transfer between them automatically.

**Next milestone:** dependable two-hop reasoning in fresh worlds — correct across seeds, answer changes when the relevant fact changes, answer holds when an irrelevant fact changes.

1. **Make comparisons dependable** — #2 (GPU) to afford #5, #8, #18, #17, #22, #37. Report every seed and the fraction that succeed; five seeds is an initial screen, not a reliability estimate.
2. **Locate the failing operation, then change one thing.** Compare, on two-hop questions: own retrieval / correct first card supplied / both correct cards supplied; record whose card and which relation the second lookup requests. That decides between exposing identity (#4), teaching selection (#9) and repairing the second step (#3, #11, #20). Never add them together.
3. **Bounded fair trial for recurrence** — #1, #26, #35, then weigh accuracy gained against compute added.
4. **#39 retention moves up** — run a small learn-new-villages-without-forgetting experiment as soon as a basic task is learned reliably, before sleep/dreams/knowledge slots. State whether retained knowledge lives in weights or stored cards; compare under explicit storage and replay budgets.

**Already done by Opus this morning (milestone 3 + continuations, after this sweep's inputs were frozen; toy ladder, supplied cards, 2 seeds):** mean and two-pool cards failed; a direct word-by-word reader fixed reading (512/512) but not choosing (~1/3); factual swap tests (#7-style, with irrelevant-change controls) show answers follow the *value word*, not whose value it is (0-2/256 follow the card), and the entity slots are unused; an address-keyed selector that is *told* where person and relation sit lifts choosing to 466-503/512 and changed-fact pairs from ~1 to 218-247/256, confirmed on fresh worlds — but two-hop combining is unchanged (~38% even with both correct cards supplied). **Claims softened after review:** #41 identical answers across loops do not prove the loops do nothing (states and probabilities can move without changing the winner); #27 ~14 passes over the data do not establish memorisation — fresh-data comparisons test it; #19 a gain from type labels shows supplied task information helps, not that recognition is the sole bottleneck; #23 eight seeds at once only costs ~one run if a single run leaves GPU capacity unused; #95 decoding likely answer words from intermediate states is a diagnostic view, not a faithful transcript of thinking. ## Headline

All 133 verified ideas fit into 100 distinct groups after merging near-duplicates; nothing was dropped, because no idea was a pure duplicate and none scored fit<=2. The sweep converges hard on a handful of measured failures: the Think loop was probably never given a fair trial (gate initialised at exactly zero, residual init scaled for 6 branches while 20 run, no normalisation between loops), the card row hands the decoder only value+age+row_type while the key, entity ids and source tag are written and thrown away, and the ASK loss is order-free so the second hop is never forced to ask for a different relation. A second cluster is pure method hygiene that would make every future number trustworthy: use the idle 5070 Ti, run 5 seeds instead of 1, decay the learning rate at the end, keep the best-on-validation checkpoint, and replace linear probes with causal swap tests before believing the pooling diagnosis. On the data side, question wording is not yet a separable split axis and 13 of 22 question banks have a single train phrasing, so the 23% held-out number cannot currently say what is broken. Several of the strongest items are cheap "make the good part better" moves on things that already work: deep supervision already decodes 8 answers per question that get thrown away, the oracle already knows the full derivation, and generation plus evaluation are nearly free.

## Themes

- The Think loop was never fairly tested: zero gate init, wrong residual scale for the unrolled depth, no inter-loop normalisation, and a readout that hides the drift - four independent bugs all pushing toward 'recurrence is useless'
- The card row is the real bottleneck candidate, not only the pool: key, entity ids, source tag and line index are written to the store and never shown to the decoder, and every diagnostic so far changed the pool instead
- Second-hop failure looks like a loss-shape problem: an order-free set objective is satisfied by one gold card, so nothing ever teaches the second query to name a different relation
- Method hygiene is the cheapest upside in the whole sweep: the GPU is idle, every headline number is one seed, there is no LR decay and no best-on-validation checkpoint
- Probes cannot settle the pooling story; four independent lenses all landed on causal swap / interchange interventions as the test that would
- Question wording is not a separate split axis, so the held-out collapse cannot be attributed; and the model is answering from the wrong answer space, which a tiny question-type head or an oracle type tag would separate in minutes
- Several strengths are being wasted: 8 per-loop answers discarded, the oracle derivation discarded, free generation not used to make more data or bigger eval cells
- Vision items (sleep, VQ codebook, knowledge slots, motivation) are coherent but nearly all C-tier until the measured failures above move

## Cautions

- Before any reward-based or search-based idea, the measured shortcut floor matters: question-blind shortcuts already reach 53.7% where the model scores 32-36%, so 'right answer' is currently a partly hackable reward
- Two ideas had verifier cite='wrong' (think-loops-2, synthetic-data-world-6) - the underlying code-level fix still looks right, but check the cited source before quoting it
- Answer-token upweighting appears three times from three lenses; do it as a float weight, not a boolean mask, and keep it as the control arm for any trace-supervision result, or traces will get credit for gradient placement
- Trace supervision can be filler: build the shuffled/filler control into the experiment from day one
- Do not chain several of the Think-loop fixes at once - they are all one-liners, so run them as separate arms or the seed noise will swallow the attribution
- Almost every A-tier item assumes multi-seed reporting; running them one-seed on CPU reproduces the same 503-vs-27 ambiguity that made the existing numbers hard to read
- Reader-backbone swaps (signed recurrence, matrix state, more attention, Canon, chain attention) all carry transfer risk and touch the one thing that currently works; they belong after the card-row and ASK-loss arms
- $30 cloud cap and the local 5070 Ti mean anything marked local-gpu-hours should be queued overnight, not run interactively
