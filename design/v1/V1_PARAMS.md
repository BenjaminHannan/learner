## 2. Models and flags
- **D** = `PremonitionMini.preset("D","full")`, d_model 128, vocab 7,289, 2,130,516 params. Width unchanged (frozen spec).
- **Creative** = `custom_io` `ledger` B2 (copy=True), d256, 3,302,481 params, parent checkpoint **`B2_s200`** (24,000 updates; file sha256 `94057436d98a485cb4ed0bc750244c2d86a2c744d249106276b15effe94b9d3a`, branch claude/b2-confirm-checkpoints). Why s200: C2b started its W arm from each of s200-s205 (per-parent W first_try 202,208,192,173,214,218 of 512; 39.29% is the 6-parent mean); I fixed the first seed index before looking at any v1 result; same parent for both arms.
- **Join** (`v1/joint.py`): P_dc Linear(128->256), P_cd Linear(256->128), both zero-initialised (weight and bias); each side adds the projected vector as a residual (D: to its register rows; creative: to every controller token). Summaries are EMA (0.99) buffers of the other side's detached state, frozen at evaluation and in sleep. Bridge optimizer AdamW lr 1e-3, wd 0, clip 1.0. In WAKE the creative weights are frozen at the parent (only P_dc trains from the creative skills loss, 16 skills rows/step). Zero-bridge == bridge-off and V1-edits-with-flags-off == original code are tested bit-for-bit on both sides (v1/tests/test_joint.py, PASSED 2026-10-21).
- **FLOOR**: D AdamW + join + sleep + G1. **FULL**: FLOOR + Muon (D's 2-D hidden matrices only: `reader.*`, `think.layers.*`, `decoder.*` Linear weights and `writer.key/value`; embeddings (tied head), norms, biases, gates, heads.*, binder, `decoder.cross_gate` and 1-row matrices stay AdamW; the grouping is printed and saved as `grouping.json`) + S2 (`decoder_raw_cards=True`, 0 parameters). Muon is NOT applied to the creative module: its parent is already trained and wake keeps it frozen, and its sleep uses C2b's tuned fresh-AdamW recipe (an untested optimizer swap there is out of scope; flagged to the coordinator).
- **Defer: OFF in both arms.** (Spec: on only if the bit-equality harness passes on the v1 config; the coordinator ruled default OFF with no new review rounds; the port is not in this tree.)
- **G1 (creative side only, coordinator ruling)** = K-FAC hard lock (energy 0.99, soft=None) measured at the start of every weight-changing creative stage on the model's own old answers (diary), all Linear/Conv1d [W|b] changes projected after each optimizer step; every other parameter (embeddings, LayerNorm, output bias) frozen; + **30 x mean KL(parent || model)** over 32 diary rows per update (`v1/g1.py`, ledger heads: op, operand pointers, mode, answer pointer, word pointer, GEN copy distribution). Parent = frozen B2_s200 with the bridge as attached. Diary = 4,096 skills TRAIN prompts (seeded shuffle, seed 0) with the parent's own greedy answers; K-FAC statistics use the first 1,024 diary rows (CPU-only statistics code; implementation choice, noted in KNOWN_ISSUES). No D-side KL.
- **Sleep** = C2b's W path (`v1/creative_sleep.py` = `creative/c2b.py train_parent` without the R/H/M arms): warm-up (2,048 add/mult rows, 4 visits, lr 3e-4, skills replay) -> N' -> pool temperature on creative DEV -> night 1 (search 32 tries + 480, W1 records, lr 1e-3, 32 visits) -> night 2 from W1 -> `W2.pt`. G1 on in all four weight-changing stages.

## 3. Training constants (identical for both arms)
- Seed 0; **step budget: 12,000 wake steps** (about 6.5 epochs of the 95,000-visit TRAIN at 55,000 tokens per batch). If the Gate S projection for an arm exceeds its cap, steps are cut (not model size, per the consult) by the largest S that fits, recorded in the Gate S report before any arm starts; both arms get the same S.
- AdamW betas (0.9, 0.99), eps 1e-8, weight decay 0.1 on matrices, lr 1e-3 with 100 warmup steps then constant, grad clip 1.0, bf16 autocast on CUDA, D batch = up to 55,000 tokens / 48 visits, curriculum gold 0-5% / teacher 5-30% / own thereafter (p_own to 0.75 by 60%) driven by STEP share. No FLOP calibration.
- Checkpoint every 5% of steps (atomic, sha256, keep 3) with exact resume; dev eval every 5%.
- Memory guard = 0.9 x detected card memory (`v1/guard.py`), never a constant. Pinned image `v1/PINS.json` (torch 2.7.1, CUDA 12.8). Code ships as `v1/pack.sh` tarball + COMMIT file.

## 4. Working definition and rules (spec + consult, verbatim where quoted)
- W1: sealed main-task accuracy at least 10 points above the best no-learning baseline. **Baseline fixed here** (`v1/baselines.py`): the larger of "always answer the most frequent TRAIN answer" and "always answer the most frequent answer of the scored set", computed on DEV; DEV value 8.95% (answer ids [828, 2]) => **W1 needs sealed accuracy >= 18.95%**. Accuracy = `premonition.train.validate` exact-match answer accuracy.
- W2: creative at least 20% first-try on held-out puzzle kinds = greedy first try fits-and-right on `creative/data/c2/test.jsonl` (the sealed 512); the dev analogue is creative `dev.jsonl`.
- Dev split rule (consult d2): about 5% of village TRAIN data (shards 380-399) + the held-out `validation` split (non-sealed held-out kinds) + creative dev (non-sealed held-out puzzle kinds).
- (consult d3, verbatim) **The "working" rule for the single sealed read.** These are my defaults; adjust them before launch, never after.
   - **W1 (main task):** sealed accuracy beats the best no-learning baseline (e.g. most-frequent answer, computed on dev) by at least 10 points.
   - **W2 (creative):** at least 20% on held-out puzzle kinds. That is about half of C2b's 39.29%, allowing for some loss from integration, and still about 36× the no-sleep 0.55%.
   - Both pass: working. Only W1 passes: the brain works but the sleep integration is broken, and that becomes queue item 1. W1 fails: not working.

- **Open-seal rule (consult d4, verbatim; D5):**
  **When the seal may be opened.** Pick the arm with the higher dev main-task accuracy (ties go to full). Open the seal only if that arm meets W1 and W2 on dev. Otherwise the seal stays shut and you debug on dev.

- **Abort rules (consult d5, verbatim; measurement points below).**
   - **A1, instability:** NaN, or loss above 3× its running median for more than 1% of steps. Stop. The full arm gets one relaunch from its last good checkpoint with AdamW, logged as a deviation. A second instability means stop and debug.
   - **A2, not learning:** at 10% of steps, dev loss has not dropped at least 25% from step 0. Stop; this is a wiring problem.
   - **A3, the guard is freezing learning:** at 25% of steps, G1's KL term is more than 50% of total loss in the phases where G1 is active, and dev accuracy rose less than 1 point over the previous 10% of steps. Stop. The only fallback is the next-lower KL weight from Ben's own 4-seed comparison.
   - **A4, spend:** an arm hits its cap. Stop and evaluate the last checkpoint as v1. A v1 trained for fewer steps is still a v1.
   - **A5, box dies:** resume from the last checkpoint on a new box with the same image. This is not a park. If two boxes die in a row, move the run to Ben's PC or Modal.

  How each is measured (definitions only, thresholds untouched): A1 on the logged wake loss every step (running median over the previous 200 steps; counted over all steps so far, needs >= 300 steps); the "relaunch with AdamW" applies to FULL only. A2 on dev loss = mean teacher-mode loss over 8 fixed dev batches, at the first dev eval at or after 10% of wake steps. A3 is applied at the end of the two first G1-active creative stages (warm-up, N'): mean KL-term share of total loss after the first 25% of the stage > 50% AND creative dev first-try rose < 1 point over the stage; the "next-lower KL weight from Ben's own 4-seed comparison" fallback is 10. A4 uses elapsed wall-clock x the box price against the arm cap. A5: resume from the last checkpoint on a new box with the same image; two deaths in a row => PC or Modal.
- Budget (spec): FULL <= $20, FLOOR <= $20, >= $10 of the $50 Vast week kept in reserve; Modal about $5; each Vast rental needs Ben's own click.
- After the arms: dev eval at every checkpoint, E0 as a post-run diagnostic only, KL-share summary, floor-vs-full comparison, then the open-seal rule. The sealed read happens once, only if the chosen arm meets W1 and W2 on dev; never re-read (`v1/sealed_read.py` refuses a second read and refuses without the dev pass recorded).
