Labels: shown = measured in this repo; suggested = reasoned; untested = a plan or a guess.

## What it is
- One change from q33: size. B2 grown deep at width 256 from 2 blocks to 8 blocks (10,254,105 parameters with the
  copy talker, counted on branch `claude/custom-reader-talker-4x309r` at 085431a7f; B2-S is 3,302,481, shown).
- Same-size plain baseline: plain_tf_steps at width 256 with 13 layers (10,368,768 parameters, within 1.1% of B2's).
- Same data, recipe and machine as q33 (BensPC, the 200k skills rows, 24,000 updates, batch 256, lr 1e-3, bf16,
  final eval). No web text, no new code. Seeds 200 and 201, compared with q33's runs on the same seeds:
  B2-S 73.00 / 74.27 and plain_tf_steps-3M 66.82 / 67.09 pooled-5 (shown).
- It also measures the deep 10M shape's real seconds per update and peak memory on the PC, which addendum C needs.

## Readout, fixed now
Pooled-5 = micro exact over dev in_dist + answer + frame + vocab + variant (6,040 rows), as in PASS-MARKS.md.
- **Encouraging:** B2-10M minus B2-3M >= +3.0 on both seeds, and B2-10M minus plain-10M >= +3.0 on both seeds.
- **Flat:** B2-10M minus B2-3M under +1.0 on both seeds. On today's 5.4M word pieces of questions that points at data,
  the limit the web text is meant to fix (PR #18 found +1.9 for a 4x core on fixed data, shown).
- Anything else is unclear. Two seeds are below the project's 6-seed noise rule, so no reading here is a verdict; the
  sealed 8a ladder decides.
- Also reported: in_dist, variant, chain-5, loops:0 leak, seconds per update, peak memory. If B2-10M goes non-finite,
  one re-run at lr 5e-4 (disclosed).

## Time (suggested)
B2-S ran up to 6.7 updates a second on this PC; a deep 8-block B2 runs 4x the block steps, so about 2-3 hours per B2
run and about 1 hour per plain run. About 4-5 hours in all at two at a time.
