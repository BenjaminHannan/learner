# Step 0 external reviews (2026-09-18)

Two independent adversarial reviews of the Step 0 test bench (`learnlab/`). Review 1's verdict: **FAIL**. Review 2's verdict: **PASS WITH REQUIRED FIXES**; the same bench must not gate Step 1 until the blocker and high findings are fixed. Their probe scripts are in `probes-review1/` (run `probe.py` with the project imports) and `probes-review2/` (run each with `sh probes-review2/run.sh probes-review2/p_<name>.py` from the project root).

## Review 1 findings
| Sev | Where | Problem | Evidence | Fix |
|---|---|---|---|---|
| blocker | ablation.py:71 | Full and lesioned arms are two unconstrained evaluate() calls; same length is the only pairing guarantee. | blocker | 04-architecture.md:13, ablation.py:54 | The architecture requires equal compute, retrieval budget and information, but judge_component receives only score arrays. | No "compute" or "retrieval" accounting anywhere in learnlab. | Baseline results carry audited compute, tokens, retrieved tokens/items, information sources, parameter budget and run IDs; refuse comparison when required budgets differ. |

Also: presence_chance is valid only for its specific null (uniform among distinct candidate tokens present), compares single tokens with whole answer strings (multi-word answers break), and a high presence floor can hide a trivially solvable test; that should be reported as a benchmark-quality warning.

Subtle planted variants review 1 ran: mutation + exception → missed; same-value Parameter replacement → missed; a requires_grad change → missed; mutate then revert → missed; a generator skipping record() → missed; family membership evolving → missed; target always first → missed; answer encoded only by word order → missed; 30% direct answer leak → caught; target last 60% of the time → caught; no-op component + drifting evaluation → passes wrongly; a lesion that fails to restore → passes wrongly and contaminates state. **These should become Step 0 regression tests.**

## Missing coverage required before Step 1 (both reviews)
- Baseline slots with item IDs, required slots per component, and budget fields (tokens, updates, FLOPs, parameters, retrieved items/tokens, information sources, run IDs).
- Deterministic evaluation over fixed item IDs with RNG control, a repeatability check, and a mandatory lesion-restoration check.
- Exact / permutation statistics, a minimum n, and an explicit minimum meaningful effect.
- Leak detectors that handle held-out-name, capitalised and multi-token answers; position, question-only, target-line, order-aware and metadata detectors; a per-detector null; significance tests; a benchmark-quality warning.
- A counterfactual-pair generator with a pair metric (both correct) and its chance level.
- A toy rule family that exercises the `rule_family` axis, with a planted cross-family leak.
- An immutable, versioned, saved split manifest; split-specific views; provenance on examples; an independent text audit; a check at consumption.
- A check that evaluation inputs never contain the answer (kept from the old project).
- Stronger read-only auditing: identity, requires_grad, version counters, `.grad`, optimizer/RNG state, every module's mode, the exception path, a derived-buffer allowlist.
- Precisely defined forgetting (both variants reported).
