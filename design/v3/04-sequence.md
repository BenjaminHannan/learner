## Shared statistical and resource contract

**Untested:** every learning contrast uses 16 paired seeds with independent data streams across pairs, 32 jobs total. Use seeds derived from `(v3, track, slot, replication=0..15, purpose)` with the declared SHA-256 derivation, not the historical seeds 0–39. Require ≥12 meaningful wins/16, primary margin ≥3 pp unless specified otherwise, zero invalid runs omitted, no mean one-hop/READS degradation exceeding 2 pp and no increase in stuck count. Failing the no-harm rule fails advancement even if the primary gain is positive. A newly introduced output/generator contract uses the analogous fresh reading/one-hop cells, not nonexistent legacy fields.

**Shown:** exact sign-screen size/power are 0.03841 / 0.79825 when meaningful-win probability is 0.8; see 03 for assumptions. This screens common, fairly large effects. Non-inferiority requires a separate paired interval: one-sided 95% bootstrap lower bound above −2 pp, with worlds nested in seed pairs and resampling algorithm fixed in the manifest; sixteen seeds may be inconclusive. Do not replace an inconclusive result with “equivalent.”

**Shown:** observed old runs took 38–84 minutes each; new concurrent key-pooling runs took 44.5–85.9 minutes each. Neither establishes a <30-minute future wave. Approximately six updates/s in a 50-step smoke is not a full-load rate. No current rental price or available host was inspected, so there is no defensible dollar quote. No money was spent.

**Untested — explicit admission calculation.** For 32 runs, concurrency C, common training FLOP cap B, measured full-load per-job rate f FLOP/s, checkpoint/eval overhead e, and setup s:

`T_wave = s + ceil(32/C) × (B/f + e)`.

Measure f at all curriculum modes, use the slowest lower-bound rate and include queueing, checkpoint writes, all evaluation cells and result collation. The future timing rehearsal is performed only after separate run authorization. A proposed half-long toy budget is `B=3.407362074846783e13` model FLOPs, approximately a 6k-requested-step scale, **not** a literal step limit. Longer-budget confirmation is a new registered budget, not an automatic extension of losers. Track B's initial learning cap is `B=1e13` model FLOPs per run, a feasibility screen with no promised competency; charge CPU regeneration separately.

Target end-to-end T≤1,500 s, leaving five minutes slack under Ben's rule. At C=32 and s+e=300 s, the toy requires f≥2.84e10 FLOP/s **per concurrent job**; Track B requires ≥8.34e9. These are required rates, not measured performance. At C=8 the queue multiplies training/evaluation batches and admission is much harder. More machines can shorten the roster, but cannot magically shorten one sequential training run.

For a later actual price quote r dollars/hour per machine and H machines, cost is `H*r*T_wave/3600` plus billed startup/storage/minimums. At a hypothetical r=$1/hour, one 25-minute host wave costs $0.417; that is arithmetic, not an available offer. If the fastest valid ≤30-minute configuration costs >$2, document that quote and the cheaper slower alternative before using Ben's stated exception. Unknown price/performance cannot satisfy the exception. If neither route is established, the wave remains unadmitted; do not silently reduce seeds, omit controls, or split one comparison into “waves” to conceal total time.

Every learning row below inherits this formula, 20–25-minute **target only**, and unknown actual dollar cost pending the full-load rehearsal. Functional B1/B2 rows target ≤5 CPU minutes/$0 incremental rental on an already authorized local host; this is unmeasured, not a booked resource. Current machine availability is not assumed.
