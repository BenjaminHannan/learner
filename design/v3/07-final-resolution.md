## Minimal pooled selector: complete implementation contract

**Untested — specification.** This replaces token pointing as the first request-head candidate. Retain the legacy 76-row workspace and its pooled-card bypass payloads, binder, slot masks, loop-step embeddings, ASK/HALT register 0, decoder and supervision. Replace only `Heads.query` with two independent attention selectors conditioned on register 1 and one `2d→k` composer. Use the selector matrices, null scorer and composer shapes in 01: 5,202 added parameters at d=32 or 82,242 at d=128, with the old query dormant and counted in allocated state. An optional token implementation must not be silently enabled.

Candidate keys `x_i` are the original contextual question rows and each fetched **pre-Think pooled value**; candidate contents `c_i` are the same vectors. For each head `h`, `a_hi=softmax((Wq_h z_1)·(Wk_h x_i)/sqrt(d))`, with the null scorer specified in 01, then `u_h=sum_i a_hi c_i` and `q=normalize(W[u_1;u_2]+b)`. No entity/relation/subject/object mask or role target. Do not use original token embeddings for a pooled evidence candidate: there is no selected token there. Pre-Think pooled values remain readable through the existing bypass without modifying mutable Think rows. Arrival/followed features and immutable token-row processing remain optional later additions, not part of this first contrast.

**Suggested:** call these *pooled address selectors*. They select a question/card representation, and the learned composer must extract the useful person/relation information. They do not copy a discrete person token. The evidence shows such information can be linearly recovered in learned runs, not that this training objective will learn the required extraction. Score card selection, first/second request person/relation correctness using a fixed diagnostic readout, and actual key-match accuracy separately. True token-pick accuracy is N/A in this arm. Freeze diagnostic readout training/calibration before evaluating held-out data; its role labels are diagnostic-only and never update the model.

Training keeps soft selector attention at temperature 1 throughout in the first pooled comparison. Report evaluation with both soft and hard head selection, but do not claim a hard selector if only soft works. The soft-to-hard schedule in 01 is a later isolated schedule comparison or part of a separately declared token prototype; it does not enter the first pooled request-head contrast. The standard hard card retrieval remains unchanged unless its credit route was separately selected earlier.

**Untested — token escalation.** To compare pooled versus token candidate content, first provision the same padded token-profile workspace in both arms with identical ordinary Think inputs and answer path. The pooled arm offers repeated immutable pooled values to the request head; the token arm offers the immutable per-token states/static embeddings specified in 01. Same masks, parameter count, row allocation and FLOP budget; the experimental factor is the content available to the request selector. This contrast does not also remove slots or binder, change question length, add bidirectionality, or enable strict answer copying. A successful direct comparison earns token evidence; failure earns no “missing role information” conclusion.

## What the probes show, and what they do not

**Shown:** [the independently regenerated arrival table](../../reviews/astra-design-2026-09-19/arrivals-results.md) includes all 160 key-pooling runs and all 30 entries in each probe. It supersedes the original audit's statements that local results were absent. Probe C restoration flags are true for all checkpoints. The probe JSON records 759.04 seconds for the main pass; the report estimates approximately 845 seconds including preparation. Ben's “about fourteen minutes” is consistent with that total. The run/test assertions are saved evidence, not checks rerun by Astra.

**Shown:** the 0.997–0.999 key cosines are **group means**, with some individual edited-line values near 0.961. Cosine 1 indicates the same direction for nonzero vectors, not necessarily the same vector. It also says nothing alone about whether a competing card crosses a ranking boundary. **Suggested:** withdraw a general value-dependent-key diagnosis. Do not equate approximate stability with an exact persistent address invariant; Track B uses explicit identity/address fields regardless.

**Shown:** learned card-key subject and card-value object readout are strong on fixed-layout LINK lines. Chance 1/6 refers to the in-story six-way restriction; the separate sixteen-way readouts have a different baseline. **Suggested:** pooled-first is justified. A poor fitted readout in stuck runs is consistent with representation failure but does not prove information loss or establish whether it caused the stall.

**Shown:** cards-removed accuracy is low; full-story question encoding helps when cards remain. **Suggested:** store access is necessary for the observed high accuracy of successful checkpoints in this intervention. “Store is the only route” is stronger than this experiment identifies: context can contribute jointly with cards, distribution shift can mask an alternative route, and the cast mask remains. The best constant answer is a reference baseline, not a lower bound on performance and not a universal chance model. Phrase the conclusion as **shown store dependence on this validation panel, with no demonstrated independent factual answer route through question states**.

**Untested:** the six-checkpoint relation-token probe described in the original handoff is still a different assay from the newly available subject/object probe. Do not mark its unavailable script/results verified by association.
