## Where the walkthrough overreached

**Shown:** the original pooled-role necessity claim is contradicted by successful linear readouts in learned runs. **Suggested:** this warrants pooled-first, not a conclusion that a learned pooled selector is already solved. The updated walkthrough correctly retreats on this point.

**Shown:** value-edit key cosine means are high, and stuck runs change first-card ranks frequently. **Suggested:** neither proves exact value-independent addresses nor identifies key drift as the cause of rank instability; the query was recomputed too. Explicit Track B addresses remain necessary for its temporal contract even if toy cosine is excellent.

**Shown:** removing cards damages the saved toy checkpoints and answers restore exactly. **Suggested:** “store is the only route” still exceeds the assay; joint context use, cast masks and intervention distribution shift remain. Best constant-answer accuracy is a reference, not a statistical floor. The probes did not measure answer correctness on value-edited twins.

**Shown:** the village reports concern 5.55M-parameter legacy contenders, answer-name-defined slices, different train/validation populations and heavy truncation. **Suggested:** neither a names failure nor a pointerizer benefit is isolated by their two seeds. Do not use them as evidence against stable identity or for token-level role selectors.

**Shown:** the soft-no-oracle screen changes multiple mechanisms, while registered ST changes nonselected-value gradients too. **Suggested:** success would justify a controlled follow-up, not a single-cause claim. The literal teacher-assisted/no-evidence-label cell is contradictory because teacher card selection is evidence supervision.

**Shown:** conditioning shortcut results on “learned one-hop” selects a treatment-affected subgroup. **Suggested:** its excellent conditional held-out counts are useful descriptive evidence, not a causal estimate of improved reliability. The historical held-out threshold near 50% also falls short of dependable behavior.

## Disposition of Fable's ten earlier findings

1. **Accept with limits:** fixed layouts confound role and position; inverse and reverse-link controls are useful. Freeze one head permutation on calibration data. Increasing relation count is a separate generator change, not an automatic fix.
2. **Amend:** causal token states lack future context, but a controller seeing the complete line can select based on later syntax. A poor local probe does not compel a bidirectional encoder.
3. **Accept the budgeting issue; amend arithmetic/repair:** complete lines and actual FLOPs must be charged. Noise cards can be ten tokens. Existing `_insert` accepts pooled cards; its guard is not evidence that token code already exists and crashes. Do not pin a gold hop using evaluator knowledge. A quoted 10–25× cost needs measurement.
4. **Accept cold-start/support risk; reject dominance claim:** exact marginalisation is not a proof that no other estimator can learn if it fails. The proposed random-retrieval and spurious-match rates rely on uniformity/count assumptions not established by saved initialization behavior. Never-told ordinary answer labels are legitimate; gold-dependent missed-fetch labels add privilege.
5. **Accept:** the registered ST term includes nonselected-value gradients. A detached-value follow-up isolates that direct route, with shared-key reader gradients still allowed.
6. **Accept:** strict toy copying cannot produce village weights-only answers. Keep separate output contracts and source accounting.
7. **Accept leakage controls/randomized attribution; reject proof from one run:** near-chance card-removal results from a single checkpoint cannot establish absence of every leak. The completed larger probe remains assay-specific.
8. **Accept bounded-metadata problem; amend release policy:** do not release a correction guard after a finite weights probe. One current record plus a history floor cannot represent arbitrary retrospective interval corrections; use bounded explicit coverage and fail closed when representation is insufficient.
9. **Accept deferring logit distillation; amend rationale:** teacher entropy and usefulness are unmeasured, and DER's benefits are not proved to depend only on visual class similarity. Regenerated replay consumes retained records, code/metadata and compute. Use it because it tests the immediate transfer question more directly, not because alternatives are mathematically doomed.
10. **Accept stronger gate and futility:** 77/80 has low power at true reliability 95%. The earlier critique's $30 cap is not established by this task; the actual rule is the 30-minute/$2 exception. Parallel machines shorten the roster, not each sequential run. Existing checkpoints have no causal-pair scores, so they cannot be counted as failing an unrun pair gate.

## Stop doing

**Suggested:** stop adding new modules before one comparator establishes the relevant deficit. Specifically stop treating gold-given reading as autonomous retrieval; interpreting a linear probe as causal localization; labelling teacher-selected cards label-free; bundling binder deletion, step deletion, pooling, credit, curriculum and token rows; using a DONE marker as a scored roster; describing nominal FLOP-clock budgets as literal steps; hiding soft full-store access or correction metadata from budgets; using fresh-name slices as isolated name tests; pooling toy and village results; rescuing failed seeds without counting original failures; retesting until a certificate happens to pass; and scaling memory tables before fair replay.

**Suggested:** also stop asking Fable to redesign everything at once. Request three prioritized problems, answer those concretely, and have it verify the answers. Leave genuine empirical unknowns labelled untested instead of expanding a design around them.
