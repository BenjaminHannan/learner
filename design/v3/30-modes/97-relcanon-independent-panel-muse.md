# 97 — Independent test panel for the relation canonicalizer (exp 63)

Exp 63 built `canon()`: an everyday relation phrase → canonical WebRED
relation name or abstain. It passed its own registered test (272/300
paraphrases, 0 wrong, 200/200 fabricated UNKNOWN), but the same agent wrote
the canonicalizer AND its test phrases AND set the pass marks after a
construction check. That is a construction check, not a clean test. Exp 97
is the clean one: a different agent, a blind panel, marks sealed before the
run, one scoring run against the frozen exp-63 module.

## Why this design

A canonicalizer that feeds the NOTEBOOK must be wrong almost never: one
confident wrong relation poisons facts. Its failure modes are (a) confident
mistakes on paraphrases, (b) firing on phrases that name no relation, and
(c) perspective flips (capital vs capital-of, follows vs followed-by,
owned-by vs owner-of). The panel targets exactly these three, with abstain
always available and never penalised — the design rule is "abstain rather
than guess", so the marks gate wrong answers, not abstention.

## Blinding protocol (the load-bearing part)

Forbidden before sealing: `fable_relcanon63_canon.py`,
`fable_relcanon63_testdata.py`, any alias/denylist table, exp-63 test JSONs.
Allowed: the 60 canonical relation names (+PIDs, from
`data/open/webred/frames/relations.json` top-60 by count) and plain
Wikidata label/description text per property (from the build cache's
`descriptions.en` fields only). I also read `fable_relcanon63_build.py`
(construction method, not content) to learn where the relation list lives.
The panel was generated by `scripts/fable_relcanon97_make.py`, which asserts:
300 paraphrases (exactly 5 per each of the 60 relations), 150 fabricated,
50 near-misses, 500 unique strings, and a relation-vocabulary stoplist
screen on fabricated items (reworded 7 substring hits, e.g. "brewed" →
"made", since "wed" sits inside "brewed").

## Trap taxonomy (near-misses, gold + rationale per item in the JSON)

Direction pairs: capital/capital-of, follows/followed-by (incl.
before/after phrasing), has-part/part-of, owned-by/owner-of,
member-of-sports-team / member-of-political-party / member-of (team vs
branch vs choir). Frame traps: born-in vs born-on, died-in vs died-on,
married-to vs married-in-a-chapel (venue, UNKNOWN), engaged-to (UNKNOWN),
mother/father verbs pointing at child, run-the-ferry (operator) vs
run-the-country (head of government), wrote (author) vs dreamed-up
(creator) vs built (developer) vs behind-the-camera (director), setup
(founded-by) vs going-in-a-year (inception), county in/cover/touch
(located-in vs contains vs borders), nation/citizen/origin/sport quad,
speak-at-home vs tongue-of-administration, studied-at vs guest-lecture
(UNKNOWN). Idioms and behaviours naming nothing: "a capital idea",
"part of the deal", "school of fish", "followed the band on tour",
"follows online". UNKNOWN golds were used only where no Wikidata relation
exists, never for out-of-panel real relations.

## Scoring contract (sealed in PASSMARKS.md)

Raw output coerced (tuple-first / dict-key / string), normalised
(lowercase, spaces/hyphens → underscores); a predeclared abstain set
(unknown, unsure, missing, none, …) counts as abstain. Correct = match to
gold; anything else concrete = wrong. K1: ≤3 wrong/300. K2: ≥147/150
UNKNOWN. K3: 0 wrong/50, abstain allowed. One run; FAIL stays FAIL.

## Outcome and reading

PASS: K1 2 wrong (28 correct, 270 abstain), K2 150/150, K3 0 wrong
(1 correct, 49 abstain). The safety shape replicates independently. But the
abstain rate (90% on fresh paraphrases vs 9% on the home panel) shows the
pass rests on caution, not coverage: everyday phrasing outside the alias
table is declined, not understood. For the notebook doorway that is the
right failure direction, but coverage work (alias growth with the same
zero-flip discipline) is where the next experiment should go.

## What it means

An independent panel confirms the canonicalizer is safe to query: it says
"don't know" instead of guessing, including on hostile perspective flips.

## What it does not mean

It does not show the canonicalizer understands relation language broadly —
9.3% of novel paraphrases were answered. Do not raise its authority (e.g.
auto-writing notebook facts) on this result.
