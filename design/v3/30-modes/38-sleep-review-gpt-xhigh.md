**Recommendation:** treat CardFold as a **partial positive result, not successful “sleep” yet**. It shows that **an externally discovered rule can generate fresh practice that is consolidated into weights while replay protects old skills**. It does **not** yet show that the model discovers the lesson itself, and the near-collapse at length 9–10 is strong evidence that the weights learned a bounded version of the behavior rather than the underlying algorithm.

The nominal numbers make that distinction sharp: S averages **96.3%** on unseen inputs of trained lengths versus **6.0%** for R, while old skills remain about **98.3%** after S. But S averages only **4.7%** at lengths 9–10. And because one preregistered seed was VOID, these averages should not be treated as a clean three-seed confirmation.

## 1\. The three biggest weaknesses

| Weakness | Why it matters | Cheapest useful experiment |
| --- | --- | --- |
| **1\. The software discovered the lesson.** | The strongest cognitive step—going from 20 episodes to `ROTL1 → FOLD → INC3`—was done by exhaustive program search, not by the learned system. The model only consumed training data afterward. | Train the **same network** on a second mode, `INDUCE`, where logs from other DSL compositions map to their primitive sequence. Hold CARDFOLD and several compositions out. At sleep, the model proposes programs; software may **check** them but may not enumerate them. |
| **2\. S confounds “having a lesson” with getting much more supervision.** | Equal gradient updates are not equal information. R sees the same 20 answers repeatedly; S gets 400 fresh labeled examples generated by an oracle-quality program. So the current result strongly establishes **data amplification**, not that an abstract lesson itself entered the weights. | Add an **O400 control**: 400 fresh oracle CARDFOLD examples sampled directly, with no lesson-induction machinery. If O400 ≈ S, the performance gain is explained by fresh supervision. A stronger later test is direct rule distillation: supply the symbolic rule but *no* fresh CARDFOLD labels. |
| **3\. The learned behavior is not systematic.** | Going from ~96% at lengths 4–8 to ~5% at 9–10 is exactly the failure expected when a transformer learns a finite positional strategy rather than the algorithm. One new composition also gives weak breadth evidence. | First change **only the positional representation** to list-relative position coupling. Keep the generated data, updates, replay, model size, and lesson fixed. Test 9–12 zero-shot. Then repeat across several held-out DSL compositions. |

The good part worth keeping is **replay**. S versus S0 is unusually clean: S retained the six old operations, while S0 drove them near zero. That is credible toy evidence for a replay requirement during consolidation, consistent with broader continual-learning results using rehearsal. [ACL Anthology+1](https://aclanthology.org/2024.emnlp-main.190/?utm_source=chatgpt.com)

## 2\. Let the same model induce the lesson

I would make **model-proposed DSL rule + deterministic verification** the first version.

The exact checker is not a second “judge model.” It is more like a unit test. There is still only one learned system.

### How

Give the existing network mode tokens:

```
<WORK>     input -> answer
<INDUCE>   episode log -> DSL program
```

During initial training, generate many meta-induction problems from your eight primitives:

```
examples:
[a,b,c,d] -> [...]
...
RULE: ROTR2 SWAP INC1
```

Crucially, split by **whole programs**, not by individual logs. CARDFOLD and other test compositions never appear as induction targets.

At sleep:

1. Feed the 20 episodes to the same model under `<INDUCE>`.
2. Have it generate, say, up to 32 candidate token sequences.
3. Grammar-mask decoding so candidates are valid DSL syntax.
4. Execute each proposed candidate on the 20 logged examples.
5. Accept the first candidate passing all 20.
6. If nothing passes, **no lesson is learned**; fall back to raw replay.
7. For research evaluation only, test the accepted candidate on 200 secret examples that were never available to the proposer or checker.

This mirrors a successful general principle from *Hypothesis Search*: have the model generate explicit hypotheses/programs and then validate them by execution rather than trusting a verbal guess. [ICLR Proceedings](https://proceedings.iclr.cc/paper_files/paper/2024/hash/a934282496e7b907f5d48d49bb4c9d7d-Abstract-Conference.html?utm_source=chatgpt.com) Program-synthesis work has likewise found value in separating learned proposal from exact verification. [Springer+1](https://link.springer.com/chapter/10.1007/978-3-031-65630-9_15?utm_source=chatgpt.com)

### Which approaches are realistic at 1–30M?

| Method | Feasibility from scratch | My use |
| --- | --- | --- |
| **DSL proposer → exact checker** | **High.** Even 1–5M may suffice because the output language is tiny. | **Try first.** |
| **Model-guided hypothesis search**: propose, see failure cases, propose again | **High at ~3–10M.** | Next step if one-shot proposals are unreliable. |
| **Generative replay** | **High at 1–30M**, especially with verification. | Good *after* a lesson exists; it does not itself prove induction. |
| **In-context → in-weights distillation** | **Plausible around 10–30M**, but much riskier from scratch. | Interesting v2 experiment. |
| Free-form English rule induction | **Poor first bet at 1–30M.** | Avoid initially; too much capacity goes into language rather than induction. |

Context distillation is conceptually attractive: if the model can answer CARDFOLD correctly when the 20 examples are in its context, train it so it gives the same answers after removing that context. There is recent theoretical work showing exact context-to-weight conversion in **linearized-attention** transformers, but that result does not establish that a normal tiny decoder can do it reliably. [Proceedings of Machine Learning Research](https://proceedings.mlr.press/v235/chen24r.html?utm_source=chatgpt.com)

Generative replay is easier, but there is a danger: a model can train on its own mistakes. Recent self-rehearsal work supports the basic idea while also making verification/filtering important. [ACL Anthology](https://aclanthology.org/2024.acl-long.77/?utm_source=chatgpt.com)

So for CardFold, **explicit DSL hypotheses are vastly easier to debug and falsify**.

## 3\. What seems to work for length generalization

There is no universal positional encoding that fixes this. The strongest 2024–2026 results increasingly say: **expose the task's algorithmic structure.**

### Task-relative positions / Abacus / position coupling

This is the most convincing family for your immediate problem.

McLeish et al. added embeddings corresponding to a digit's **logical position inside a number**, rather than relying only on its place in the text sequence. Models trained on at most 20-digit addition reached up to **99% on 100-digit addition**. [NeurIPS Proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/c35986bc1ee29b31c1011481b77fe540-Abstract-Conference.html?utm_source=chatgpt.com)

Cho et al.'s *Position Coupling* similarly assigns matching logical positions the same positional identity; models trained on 1–30-digit addition generalized to as much as 200 digits in that setting. [NeurIPS Proceedings](https://proceedings.neurips.cc/paper_files/paper/2024/hash/27aa3a0e6d63db269977bb2df5607cb8-Abstract-Conference.html?utm_source=chatgpt.com)

These are arithmetic results, so they do **not** establish that CardFold will work. But the mechanism is highly relevant: your operations act on **list positions**, yet the model currently gets generic sequence positions.

### Randomized positions

Randomized PE helps on average—Ruoss et al. reported a 12-point average gain across 15 algorithmic tasks—but it is not sufficient universally. [ACL Anthology](https://aclanthology.org/2023.acl-short.161/?utm_source=chatgpt.com) Your own experiment is now another example where random offsets did not solve the task.

Later work also found algorithmic length extrapolation to be extremely seed- and formatting-sensitive. [arXiv](https://arxiv.org/abs/2402.09371?utm_source=chatgpt.com)

### NoPE

NoPE can extrapolate farther than several explicit positional schemes, but ACL 2024 found that it eventually fails as attention becomes distracted. [ACL Anthology](https://aclanthology.org/2024.findings-acl.834/?utm_source=chatgpt.com) I would not make it your first intervention.

### FIRE

FIRE is a strong generic relative-position method. But arithmetic studies suggest that positional encoding alone is not the whole answer: formatting/index structure matters greatly. [arXiv+1](https://arxiv.org/abs/2310.04418?utm_source=chatgpt.com)

### Scratchpads

This is more interesting. ICLR 2024 showed that scratchpads can produce strong length generalization **when they make the underlying algorithm simpler**, while a poorly chosen scratchpad can actually hurt it. [ICLR Proceedings](https://proceedings.iclr.cc/paper_files/paper/2024/hash/45ed1a72597594c097152ef9cc187762-Abstract-Conference.html?utm_source=chatgpt.com)

ICLR 2025 combined task-specific scratchpads with position coupling and obtained about **2–3×** generalization on harder arithmetic settings. [ICLR Proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/c6c29e590e3c62e37e6b39cdd6baf2e8-Abstract-Conference.html?utm_source=chatgpt.com)

A CardFold scratchpad such as

```
input
-> after ROTL1
-> after FOLD
-> after INC3
```

is therefore worth trying later.

### Looped / Universal Transformers

Looped Transformers reuse the same block for an adaptive number of computational steps and substantially improved length generalization on iterative algorithmic tasks. [ICLR Proceedings](https://proceedings.iclr.cc/paper_files/paper/2025/hash/25cc3adf8c85f7c70989cb8a97a691a7-Abstract-Conference.html?utm_source=chatgpt.com)

But CARDFOLD has **fixed composition depth = 3**. Its required number of primitive operations does not obviously grow with list length. Therefore this is less directly matched to CardFold than position structure is.

A very recent 2026 preprint gets perfect length generalization with tiny recurrent/Universal Transformers, but it builds substantial circuit structure into the representation and computation. It is compelling evidence that recurrence plus the right structural representation can work, not evidence that an ordinary tiny decoder will discover that representation itself. [arXiv](https://arxiv.org/abs/2608.31067?utm_source=chatgpt.com)

### Easy-to-hard self-improvement

This is probably the most important second experiment. A 2025 study used a 14M transformer and progressively trained on the model's solutions to slightly longer problems; it generalized far beyond the original training range on addition, string manipulation, and maze tasks. Correctness filtering and gradual difficulty increases were crucial. [arXiv](https://arxiv.org/abs/2502.01612?utm_source=chatgpt.com)

But it is not true zero-shot length generalization: the model gradually receives training signal at longer lengths.

### My first CardFold change

**Add a list-relative randomized position embedding.**

For the element at logical list index i:

hi​\=etoken​+enormal position​+elist-pos(r+i)​

where r is randomly chosen each example.

Reset `i=0` at each list boundary.

That means the model sees:

- “third item of a list” as an explicit structural fact,
- many different embedding IDs representing “third item” because of random r,
- no information about which primitive or CARDFOLD rule is being used.

Do **not** encode the correct source→destination correspondence—that would leak the algorithm.

This is a much closer analogue of Abacus/position coupling than your current randomized global sinusoid.

## 4\. What should “a lesson” mean in the real system?

I would make this distinction strict:

> **A fact is something true about the world. A lesson is a reusable way of processing facts or solving problems.**

Examples:

- `"Paris is the capital of France"` → **fact**, notebook.
- `"If a question asks A's mother's employer, resolve mother first, then employer"` → **lesson/skill**.
- `"If relation R is verified transitive, two R edges can be composed"` → **rule**.
- `"Ben corrected X, so use the latest accepted correction"` → preferably deterministic notebook policy, not learned weights.

Mutable facts should remain notebook-grounded. Even if a later model memorizes them incidentally, its weights should never outrank a notebook correction.

### Sleep v1 → v2 → v3

|  | Input | Output | Transaction gate | Pass mark |
| --- | --- | --- | --- | --- |
| **v1: notebook consolidation** | Accepted taught facts, corrections, aliases, approved derivations | New append-only notebook suffix, normalized aliases/indexes, provenance | Construct candidate state separately. Verify hash chain, provenance, conflicts, and that no proposed/web fact became taught. Commit atomically or discard. | **100%** recovery of accepted facts on a fixed probe set and **0 unauthorized status promotions**. |
| **v2: weight consolidation** | Verified skill/rule + practice generated from it + old-skill replay | Candidate model checkpoint + lesson record pointing to evidence | Test new skill, all protected old skills, and notebook-grounded fact queries before replacing checkpoint. Any protected regression beyond threshold = rollback. | New skill **≥90% held-out**, with **≤2 percentage-point loss in every protected old category**. |
| **v3: model-proposed lessons** | Raw day's episodes/conversations + notebook | Same model proposes explicit rules/hypotheses; verified ones produce practice; candidate checkpoint | Proposal must first pass exact checks/human confirmation where available. Then candidate weights must pass the complete v2 regression gate. No verified proposal = no update. | On a held-out induction benchmark, **≥80% correct/equivalent lesson discovery and 0 false acceptance on corrupted/no-rule logs**, then satisfy v2. |

The important architectural rule is:

**Sleep never edits the live agent directly.**

It creates:

```
current state
     |
     v
candidate sleep transaction
     |
     +--> lesson verification
     +--> new-skill tests
     +--> old-skill regression tests
     +--> fact/provenance tests
             |
          PASS?
          /   \
        yes    no
        /       \
     COMMIT    DISCARD
```

That gives you a very strong invariant for the eventual persistent agent: **learning is allowed to fail; corruption is not allowed to commit.**

## 5\. The next experiment I would preregister

I would **fix the registered failure—length—before replacing the program search**. Otherwise you could successfully teach the model to discover `ROTL1 → FOLD → INC3` itself and still have a system that learns a non-general algorithm.

### CARDPOSITION-1

**Hypothesis**

> CardFold's length failure is substantially caused by the transformer representing generic textual positions rather than logical positions inside the list. Adding list-relative randomized position embeddings will improve zero-shot length extrapolation without harming trained-length CardFold or old operations.

### Arms

**A — S baseline**

Exactly the previous successful S arm:

- externally induced CARDFOLD lesson
- 400 fresh sleep examples
- 3,000 updates
- 50% old-skill replay
- existing randomized sinusoidal positions

**B — S + list-position**

Identical except for the extra list-relative randomized position embedding described above.

Nothing else changes.

### Three seeds

Use three preregistered seeds.

Before examining CardFold:

- old OP0–OP5 validation must be ≥0.95;
- a failing base seed is reported **VOID**;
- preregister replacement seeds in advance rather than choosing one after seeing outcomes.

### Evaluation

Use fixed unseen sets:

- length 4–8: 200 examples/length
- length 9: 500
- length 10: 500
- length 11: 500
- length 12: 500
- old OP0–OP5 regression set unchanged

No training example at length >8.

### Primary pass mark

B must achieve, **in every valid seed**:

ExactMatch9−10​≥0.50

while also satisfying:

ExactMatch4−8​≥0.90

and

OldSkills≥0.95.

Lengths 11–12 are secondary extrapolation results and must all be reported.

I would deliberately make **50%** the first threshold rather than 90%. You are moving from about **5%** nominally; a jump to ≥50% in all three seeds would be strong evidence that logical indexing attacks the real bottleneck. It still would not justify claiming the length problem solved.

### Interpretation

- **B passes; A fails:** positional/index representation was a major cause. Keep the change; next experiment is same-model lesson proposal.
- **Both fail:** stop trying positional variants. Move to an algorithmic reformulation—most likely intermediate-state scratchpads, then recurrent/looped execution.
- **Both succeed:** the original failure was unstable; replicate before claiming an effect, because recent work specifically finds length extrapolation highly seed-sensitive. [arXiv](https://arxiv.org/abs/2402.09371?utm_source=chatgpt.com)
- **B improves CARDFOLD but breaks old skills:** reject it. Sleep is transactional; new learning is not allowed to purchase ability by destroying existing behavior.

After that experiment, I would make **MODEL-INDUCE-1** the next wave: same network proposes the three-token DSL lesson, exact software only verifies it, and CARDFOLD plus several other compositions are held out by program rather than by example.

That sequence cleanly separates the two unanswered questions:

**Can the model store a genuinely length-general rule?**  
then  
**Can the model discover that rule from experience itself?**
