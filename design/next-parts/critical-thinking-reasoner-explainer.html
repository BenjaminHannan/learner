A reasoner that gets the most thinking per parameter

Design only. Nothing was trained or run. Every claim is tagged shown, suggested or untested in the full doc (design/next-parts/critical-thinking-reasoner-design.md).

1. Where today's pipe is narrow

Shown in code: the reader uses fixed word vectors with no context, and the output averages every question position into 8 vectors through 32 numbers. A long exact number could be smeared. That is a guess until the free checks run.

2. What the 128 saved answers show

Shown: all 113 wrong answers are numbers the model saw as training answers. When the right number was new, it never said it. Carry, borrow, seed and reader type made little difference. So in practice the model picks from numbers it has seen.

Update: a later test trained on 48,000 never-repeating questions (a rebuilt copy of the recipe on vast.ai). New answers still scored 0% and 4%, even though the calculator call was right about 90% of the time. So better data alone doesn't fix it. The exit that averages into 8 vectors looks like the bottleneck. The new first pick is a route that lets the answer copy the calculator's result directly.

Result: it worked. With the copy route, new answers went from 0% and 4% to 90% and 84%. Every remaining mistake is now a wrong calculator call, which is right only 60-69% of the time on new wording. So "think before calling" is being tested next.

Also shown in the pipeline code: the calculator call is chosen before the first thinking round. 127 of 128 rows called at loop 0. Thinking can't help pick the operation if the pick comes first.

3. More shape ideas from recent papers

  • Think before calling (our own data): block the calculator for the first 2 rounds so the core thinks before it picks. Zero weights.
  • State lanes (Hyperloop Transformers, 2026): 4 parallel copies of the thinking state. The paper reports matching plain models with about 50% fewer weights. It grows state, not weights.
  • Smaller step per round (two 2026 papers): each round moves only a quarter of the way. Testable today on saved puzzle models, on the CPU.
  • Canon layers (Allen-Zhu, 2025): each word mixes in its neighbours. About 2× reasoning depth in the paper, for 3k weights.
  • Ranks 5 to 8 and the parked ideas (fact table, world model for Minecraft, fast reflex) are in critical-thinking-shape-shortlist.md. All are untested for us.

4. The proposed shape

Five parts, each a separate test. The core never sees raw text, pixels or sound, so any encoder that outputs vectors can plug in. The talker only reads the notepad.

5. One change at a time

  • Pass marks and the result that would prove each change wrong are written and hash-sealed before each run. Two seeds each.
  • Example: C1 passes at ≥95% exact on 1 to 4 digit numbers, and means the squeeze is not the problem if it does.
  • Two failed changes aimed at the same problem mean we stop and ask outside models before trying a third.

6. Beating bigger models at our size

Same recipe at three sizes against a plain, non-looped model at 1×, 2× and 4× each size. "Improves with scale" needs all three: we beat the 2× plain model at every size, our curve is at least as steep, and extra thinking rounds still help at the largest size.

In the schematic the blue line would need to sit under the 2× line at all three sizes and not bend toward it. If the gap shrinks every step, the gain was a small-model artifact. The one measured point so far is the maze test: looped 51.0 vs plain 33.8 at about 1.6M weights, one size only.

7. Roadmap

  • No skill list for stage one. It is a proof of concept for the recipe, not the final skills.
  • Minecraft (long term, untested): the tool port becomes keyboard and mouse actions, each new frame re-enters as workspace vectors, and online guides arrive as notebook text. Nothing in stage one changes except keeping the interface modality-agnostic.

8. Decided and still open

  • Decided: talker stays 32 wide unless the pipe test fails; shared width is 256 with a (role, modality) tag per vector, matching vision (PR #22) and audio (PR #24); scaling uses the fair-scaling ladder (PR #18, 3 seeds per size).
  • Changed after checking design doc v5: the reader type (static or context-aware) belongs to the English pilot, so this design no longer picks one. The tests are a menu of separate decisions after the pilot, and the free checks run on the CPU only.
  • Ben said yes to studying the 128 saved answers for design only. They are never a score.
  • Open: which kinds of tasks go into the never-repeating training data, and the compute for the scaling test once it is reached.
