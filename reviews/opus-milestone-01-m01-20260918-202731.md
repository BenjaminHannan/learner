## In plain words (for Ben)

**What this milestone was for.** Before we try to make D learn better, we need tests we can believe. A *label* is the answer to a question, plus the teacher's *feedback* ("Yay, you got it!"). If a model can see earlier labels while answering a later question, it may be copying rather than reasoning. We call that a *leak*. *Label-free* means a model sees the questions but never any earlier answer or feedback. The answer to the current question is still used for training: it is the *target*, the thing the model is graded on.

**What worked.**

1. **One shared "cleaning" step now removes labels from the text before anything else happens.** That covers D and every transformer contender (A, B, C, E). Earlier, D's labels were only hidden after the text had already been turned into tokens. That left a hole: a name written only inside an answer could still get an ID in D's name list. We proved the hole is closed by planting a made-up name ("Zyxqo") only in an earlier answer and feedback. After the change, everything any model sees stays exactly identical. So does every prediction of a fixed model, down to the last number.
2. **We measured the old leaks on the real validation data (1,000 visits, 8,675 questions).**
   - **A (old convention): leaked.** A's old way of reading a question showed earlier answers in 7,675 of 8,675 inputs (88%). That is 34,801 earlier answers in total. The new default shows none, and all 8,675 new inputs passed an automatic check.
   - **D: the hole was real but empty.** D's old path turned out to be clean on real data: 0 differences. The village never writes a name only inside a label, so no name ever got through. The fix closes the hole for any future data.
3. **C's blind spot is fixed.** C is "A plus a keyword search over earlier lines" (the search is called *BM25*). The old C searched only lines before A's window, then shortened its own window to make room. The lines in between were invisible to both the search and the window. That happened in 62% of inputs. In 413 questions, a fact needed to answer the question was in that blind spot. Now every earlier line is either searchable or in view. The search finds 231 of those 464 missing facts.
4. **Unsafe scoring now refuses to run.** A saved model (a *checkpoint*) is scored only if its tokenizer, vocabulary, shape and data-cleaning version all match. That is "failing closed": when in doubt, refuse. All five old step-1 checkpoints are refused for official results, because they use the retired v1 tokenizer. We also closed a loophole: pointing the scorer at a different tokenizer file used to skip the tokenizer check.
5. **A final decision can't mix setups.** The code that compares models (the *verdict*) now refuses to mix label-free results with labelled ones. It also refuses results whose setup is unknown. It prints that it is **not** the full §9/§10 verdict, because the planned statistics aren't built yet.

**What didn't go smoothly.** Another agent was editing the village text generator (`learnlab/`) while I worked. That changed the test villages during my runs. One old test failed for a few minutes; it failed the same way with my changes removed, and it passes on that agent's latest version. I didn't touch its files. Someone should own that overlap.

**Why it matters.** From now on, a good score can't come from peeking at earlier answers. A comparison can't quietly mix incompatible setups.

**Cost.** $0 GPU rental; about 10 minutes of local CPU for tests and probes. No training was run.

### 3. Before/after leakage evidence

**(a) Hand-made visit (golden test, v2 tokenizer).** Lines: `Kelo walked…`, `Where is Kelo? [answer] the mill [feedback] Right, Zyxqo agrees.`, `Who walked to the barn? [answer] Rami`, `Rami walked to the barn.`, `Who is at the barn? [answer] Rami`.
- Legacy whole-line binding: name table `{0: Kelo, 1: Zyxqo, 2: Rami}`. The feedback-only name takes an ID and pushes Rami to ENT2.
- Label-free: `{0: Kelo, 1: Rami}`; `label_only_names = (Zyxqo,)`. The second question asks about Rami before Rami is visible, so its target stays plain tokens and is **flagged** unbound. The third question's target is ENT1.

**(b) Real village, adversarial perturbation.** Test fixture: 40 train + 24 held-out real visits. In the visit with the most questions, the first question's label was rewritten to `[answer] Zyxqo took the barn [feedback] No! Qwyxa says Zyxqo took it.`; separately, the last question's answer was rewritten.
- D inputs: `tokens, line_of, card_end, lengths, lm_mask, line_is_question, line_start, line_ents, q_visit, q_line, q_span, gold_lines, depth` and the name tables are **identical**. Only the rewritten question's target changes, and it is the only flagged target in the split. The legacy path's name table gains `Zyxqo`.
- A (`plain_input`), C (`lookup_input`: ids and recalled lines) and E (`pointer_input`: ids and name table) prompts are **identical** for every question from the rewritten one on.
- A fixed tiny D, and fixed tiny Core/E-shaped Cores, under `read_only`: answers, loop counts, first fetches and decoded texts are **identical**.
- With-labels (diagnostic) A prompts do change for later questions: the leak exists exactly where it is labelled.

**(c) Real data, large build `large-seed0-f78a540c1e8a`, validation split** (`artifacts/opus-m01-20260918-202731/probe.json`):

### 6. Contract changes (legitimate; old assertions kept where the behavior survives)

- **Shared label-free line form.** Earlier question lines now end at `[answer]` + newline for every contender, as D requires. Two contender assertions of "exactly one `[answer]` in a label-free prompt" became the stricter structural audit: no `[feedback]`, and nothing after any earlier `[answer]`. The old form survives as `lookup.label_free` (unused, documented legacy).
- **C candidates.** One assertion ("recalled lines precede A's window") now reads "precede C's window, and no gap". The old assertion is kept and still run under `candidates_rule="before-a-window"`.
- **Fail-closed scoring.** Tiny-model tests now pass `purpose="fixture"`, and their handwritten checkpoint configs record a preprocessing identity. Mechanics-only verdicts over fixtures need `allow_fixture=True`. `exp1.evaluate_checkpoint` defaults to label-free, so the old with-labels equivalence test names its regime. It now also checks the label-free pair, whose two prompt builders are independent.
- **Near/far** is cut over the regime's visible lines (§11.3).
