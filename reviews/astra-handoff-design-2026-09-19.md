## Decisions agreed today (treat as the brief; challenge any you think is wrong, with reasons)

**Diagnosis, stated at its proper strength.** Explicit addressing and routing helped wherever they were supplied (address keys 147 to 500 of 512 with supplied field positions; relation shortcut; one seed of the handoff mask). That three interfaces share one cause, or that one shared learned select-and-copy mechanism fixes all three, is a hypothesis; sharing must be its own comparison. The detached hard top-1 blocks answer-loss credit for which card was chosen, so answer-only retrieval is unestablished; answer and evidence supervision are both legitimate learning when disclosed. Phase order (answer-only gold phase before any search loss) is a plausible, not demonstrated, cause of stuck runs.

**Track A, learned lookup (card toy).**
1. Request head: fetched evidence enters the workspace as the line's token states, not one pooled vector (on "Mira LINK Oren" the second request needs the OBJECT, which a blended card vector cannot offer to a pointer); a who-selector and a relation-selector attend over question and evidence token rows, conditioned on workspace state, request = W[who; relation]; ASK and HALT keep their own register outside the request path; loop-step embedding removed; evidence rows carry arrival and followed-or-not features; evidence rows are immutable to Think, with an assertion; binder deleted (measure). Arms: baseline, relation shortcut as a supplied-location upper bound, pointer, pointer without token rows (cheap falsifier). Log first and second request correctness on person and on relation separately; selector pick accuracy separately from request-to-key match accuracy on the held-out relation. Train and test with varied relation position and question shape, unseen arrangements held out. Copying removes a bottleneck; it does not guarantee generalisation.
2. Answer path: select the evidence card by required person and relation (for multi-hop, the person resolved by the previous hop), then copy only from it; an always-available "no matching evidence" option independent of fetching NULL; verified by distractor and swap tests (owner, relation, currently applicable fact), never by clean both-cards-given reads.
3. Credit assignment for retrieval before any evidence-label-free claim: differentiable route first (soft read, straight-through), reward route second. The 2x2 {evidence labels on/off} x {teacher-assisted / fully own fetches}; the bottom row is meaningful only with a working credit route; evaluate every arm both soft and hard. "No evidence labels" means all four channels off (ASK targets, teacher insertions, gold-dependent early-answer weighting, gold count in the should-search target) with ordinary answer supervision on.
4. Supervision confounds to separate: answer supervision in three arms (baseline 0.2 weighting / `--early-ans 1.0` / final-loop-only), scored by swap tests; ordered evidence as a 2x2 (teacher order x ASK target); LM-loss weight current / reduced / zero after measuring per-loss gradient norms on shared parameters.
5. Stuck-run remedies tested separately: separate key pooling; search loss from step 0; an auxiliary "whose line is this" loss predicting the line's subject from every token state at or after the subject, one shared head. Use intermediate checkpoints to test whether card-representation collapse precedes the retrieval stall.
6. Curriculum: competence-gated transition using held-out retrieval on both hops, with a compute cap, runs that never qualify reported as failures; a final period at p_own = 1.0 tested as non-inferiority, after a recovery action exists.
7. Failure awareness: expose match score, margin, repeated retrievals; these matter only with tasks that need them (missing evidence, failed searches, variable fetch counts, cases where continuing helps / does nothing / harms).
8. Store dependence is tested by intervening on the same trained model (every factual path, including contextual question states; then restore); a separately trained no-store model answers a different question. If the reader smuggles facts, consider story-blind question encoding and state its cost (no pronoun or context resolution in questions).
9. Naming: the current Think block is a "bounded iterative lookup controller". A fair trial of extra processing needs tasks requiring evidence combination and variable depth, with retrieval budget and compute controlled separately. Checker (is the answer correct?) and stopper (is continuing worth more than stopping?) share inputs, keep separate targets; the stopper predicts from current state only; no compute penalty, ties go to stopping earlier; truncated rollouts are never evidence that more thinking cannot help; latent loops for now, decoded traces for inspection only.

**Track B, the thesis (starts now, in parallel).** A small persistent village with fixed question wording, stable identities, recurring facts, corrections, historical questions and a bounded card store, parser-assisted and labelled as such until Track A delivers a learned replacement. Identity: stable within a continuing world, derived only from information available to the learner (no simulator ids); shuffled working tags may resolve to it; separate namespaces across worlds; a spelling fingerprint does not resolve aliases or namesakes. Fact address `(world, entity, relation)` excludes the value; the record holds value, source, effective time, observation time, version; multi-valued relations and events need qualifiers; "newest wins" only within declared trust and time rules. Learned embeddings retrieve candidates and never define identity. Cards keep correction authority: a known correction overrides any consolidated answer immediately; weight repair comes later. Re-keying: frozen retriever first; any replacement trained in sleep, validated, swapped together with its index; never lazy. Extraction (zero, one or several facts per sentence, cross-sentence reference) is separate from retention (FIFO, LRU, reservoir baselines under real storage pressure; corrections and invalidation records protected; storage priority separate from permission to become a training target; surprise left out until prediction loss is informative). Order: version correctness first; then ordinary training v fair replay (current facts plus correctly time-labelled history) v ONE isolated consolidation mechanism, matched on total compute, retained information and storage including any diary or teacher snapshot; facts held in cards scored separately from facts learned into weights; consolidation verified with targeted lesions against equal-sized control lesions; sleep's jobs (repair, consolidation, practice, maintenance) tested separately. Knowledge slots: experimental; small table first with the published initialisation and query normalisation; 262,144 x 128 is about 33.6M value parameters, so equal-parameter baselines must count the table and optimizer state; scale only after beating replay and core baselines; interference measured by changing values, routing and core separately with fixed-routing and frozen-core controls. Diary: record generator and pattern-bank versions, configuration, RNG ranges, action history, non-regenerable inputs; verify by hash; charge regeneration compute to replay. Gauges early, fresh-task probes on disposable checkpoint copies.

**Village evaluation comes before any village verdict.** Paired worlds where only the relevant fact changes; question-only, evidence-removed and irrelevant-evidence controls; chance taken from per-type answer frequencies; fixed question wording for the next diagnostic milestone, unseen wording evaluated separately, paraphrases later expanded by grammatical structure with whole structures held out. Path from toy to village through the village generator, one difficulty at a time, earlier tests retained: simple facts, distractors and missing evidence, corrections, two-step questions, varied wording and pronouns, repeated visits. Test multi-token generation and two-card composition separately.

**Reporting and reliability.** One results table generated from run JSONs with checked metric definitions; a privileges table per arm with separate columns for pointer identities, architectural masks, parsed fields, gold-card labels, teacher insertions; conclusions qualified by budget, with learning curves at several matched budgets; shared data streams measure initialisation sensitivity and suit paired recipe comparisons, reliability needs independent data streams. 36/40 is a screen (one-sided 95% lower bound 78.6%); certification = define the per-seed gate, freeze the recipe, fresh training and data seeds, 77/80.

**Agreed order.** Mac runs stay paused; reporting repaired; saved-checkpoint probes; first soft-read wave as a screen only; resolve the supervision confounds; build the smallest justified mechanism; the persistent mini-village alongside; certification after the recipe is frozen.
