STRONGEST ATTACK: The cheapest system that passes every scored test is: writer = a template parser that maps the controlled-English definition into three 6-way slot codes (about 60 word types, one template family, so this is a lookup table), reader = a meta-trained interpreter for the 174-of-216 depth-3 programs, W = a three-token store. The proposal's own detector for the degenerate version of this ("Tier 2 at the nearest-class rate ... W holds an index") only works if query operands are discriminative. With six list primitives, a test program and its Hamming-1 training neighbours (two primitives shared) produce identical outputs on a large fraction of random operands (sorting/reversing/deduplicating commute or are idempotent on many short lists), so an index-over-training-classes writer scores far above chance on Tier 2 and the "nearest-class rate" baseline, if computed empirically on the same operands, rises with it, leaving a small, noisy gap at n = 500 over only 42 test classes (the proposal itself concedes "it may be noisy at 42 test classes"). Nothing in the excerpt filters Tier 2 operands so that the target program's output differs from every training program's (or at least every neighbour's) output. Without that filter, "Tier 2 passes" does not distinguish a compositional code from an index, and the headline claim that W "can persist a program ... in unseen compositions" is not established. Secondary: the training stopping rule keys on "Pool 2 exact match"; if Pool 2 shares programs or names with the Tier 2 test, checkpoint selection leaks evaluator information into the reported number.
ERRORS:
- "Kirsch et al. report ... that biasing the task distribution toward a fixed subset 'enables a smooth path from memorizing to learning' (R13-icl-vs-weights, extra); so the curriculum starts with 16 fixed names for the first two runs and then opens the name generator." The digest passage describes a fixed label permutation mixed into a fraction of EVERY batch throughout meta-training, not a sequential phase of fixed items followed by opening the distribution; the quoted words are also slightly altered ('enabling' in the source). The sequential version risks the opposite effect (Chan et al., R13 C1/extra: with enough repetition models 'move towards in-weights learning'), unless the 16 names are re-bound to random programs each episode, which the excerpt does not state.
- "Chollet's benchmark rule, that a task answerable by the same program that fits the teaching set has zero developer-aware generalisation difficulty (R9, extra)" is presented as a benchmark rule; in the digest it is the formal definition of developer-aware generalisation difficulty (II.2.1), and the benchmark rules (II.3.2) are about buying performance with data and priors. - "The reflection loss is the in-weights analogue of the support loss without which meta seq2seq dropped from 99.95 to 5.43 percent": the analogy is a hypothesis; the cited drop was for an external-memory attention model predicting support outputs, not for decoding stored content back into text through a linear delta bank.

GRAFT:
- Definition contract that removes any answer from the writer's input ('no oracle answer input, no RL heads, no discrete sampling'), killing the 'write the label' degeneracy identified in the draft.

The proposal's own claim ceiling ('composing familiar operations bound to a novel name, not acquiring a new procedure') is accurate and should be kept verbatim in the decision record.

STRONGEST ATTACK: The training stopping rule will manufacture null results, and the positive-control ladder cannot see it. The proposal stops "when Pool 2 exact match has not improved by more than 0.5 points across three evaluations spaced 1,000 steps apart" -- a 2,000-3,000-step window. A tiny GRU with T=8 and a 128x128 functional write runs on the order of 10^4 steps per ten-minute run on a 5070 Ti (my estimate), so this window is one to three minutes of training. In the same paragraph the proposal cites Kirsch et al. on "long meta-optimisation plateaus" (R13 extra: plateaus of roughly 35k steps during which unseen-task loss worsens) and the memorise-then-generalise transition; and Tier 2 -- the only detector of the index-collapse risk the decision record names -- is exactly the metric that sits flat at the nearest-class rate until that transition. So most seeds will be stopped on the plateau long before the 12-run ceiling, PC4 will be scored "writer training failed", and the interpretation table will file it as a "component problem" when it is an artefact of the stopping rule. The hard curriculum switch (16 fixed names for two runs, then an open name generator) makes it worse: the distribution shift at the switch is itself a period when Pool 2 does not improve, which can trip the rule immediately. Kirsch's intervention was a fixed-permutation fraction of every batch throughout training, not a two-phase switch. Nothing in PC1-PC4 tests whether the stopping rule would have killed a run that eventually converges; a no-early-stop reference seed run to the 12-run ceiling is required before any PC4 or Tier 2 null can be read.
ERRORS:
- Effective sample size at Tier 2 is wrong. "n = 500 per cell, the 95 percent binomial half-width is about 2.6 points at p = 0.9 and 4.4 points at p = 0.5" -- the arithmetic is right for 500 independent Bernoulli trials, but the proposal itself says Tier 2 has "42 test classes"; the 500 queries are clustered by program, so whether W holds a compositional code is a question about 42 programs, not 500 queries. The interval must be cluster-robust (or computed over per-program success rates); the 2.6-point half-width materially understates uncertainty on the headline claim.
- The stopping window contradicts the cited evidence. "stops when Pool 2 exact match has not improved by more than 0.5 points across three evaluations spaced 1,000 steps apart" is a 2,000-3,000-step patience, while the same paragraph cites Kirsch et al.'s plateaus (order 35k steps in the digest) as the reason for the curriculum. The rule terminates on the plateau it was designed around.
- Budget arithmetic omits trained ablations. "five seeds times 12 runs is 10 GPU-hours for the main system, roughly 40 GPU-hours including PC1, the constant-key ablations and the slot-memory comparison" -- the two-hop comparison (a)/(b)/(c) requires two extra meta-trained systems (constant read; constant read with extra computation) at up to 10 GPU-hours each, the byte-matched slot memory is another 10, PC1 is 5 (10 with the width retry), and PC2-PC4 are unbudgeted. A ceiling-bound estimate is 55-75 GPU-hours, not 40. Storage ("a few hundred megabytes") is fine.
- Sham-write null over-corrects. "subtract the sham-write null obtained by writing a definition for an unused name" -- a rank-1 delta write with learned 128-d keys has RMS overlap about 1/sqrt(128) = 0.088 with stored keys, so the sham write causes real interference as well as measurement noise; subtracting it removes both. Use it as an upper bound on the noise floor, or use the signed statistic only (which the proposal already prefers).
- Attribution slip: "Chollet's benchmark rule, that a task answerable by the same program that fits the teaching set has zero developer-aware generalisation difficulty" -- that sentence is the evidence digest's inference from Chollet's definition of developer-aware generalization difficulty (R9 extra), not a rule Chollet states about benchmarks. The digest's own wording flags it as an implication.
UNSUPPORTED:
- "The reflection loss is the in-weights analogue of the support loss without which meta seq2seq dropped from 99.95 to 5.43 percent" -- the numbers are verified (R3 C3), but the analogy is a hypothesis: Lake's support loss predicted outputs of in-context support items through attention; decoding a definition sentence back out of a linear 128x128 W through the frozen reader is a different, harder head, and the proposal gives no argument that it plays the same stabilising role rather than pushing W toward a verbatim text cache.
- "if PC1 fails after six chained runs, widen the reader once (hidden 256 to 512) and retry; if it fails again, stop and report that the reader cannot execute depth-3 programs at this scale" -- one GPU-hour per seed is thin for a from-scratch recurrent executor of depth-3 list programs with exact-match sequence output, and the diagnosis assumes width is the bottleneck when fixed T=8, the decoder, or the learning rate could be; the conclusion "cannot at this scale" is not licensed by one width doubling.
- "Tier 2 is the only detector and it may be noisy at 42 test classes" -- correctly self-flagged as a risk, but the proposal then reports Tier 2 with the n=500 interval as if it were not; no power estimate is given for detecting 'compositional code' vs 'index' at 42 programs.
- "A one-shot differentiable write into W can persist a program over known primitives ... and is applied by computation to inputs absent at write time" -- supportable only if the earlier (unseen) sections specify list-operand novelty at query time; from the visible fragment I cannot verify that operands, not just names, are held out.
GRAFT:
- Differentiable writer trained by post-write query loss with no oracle-answer input, no RL heads, no discrete sampling -- this removes the 'write the label' degeneracy and the REINFORCE variance in one stroke and is the single most important fix relative to the draft code.
- Fixed T = 8 in milestone one with learned halting deferred; the reasoning (ACT tau sensitivity, gameable expected-time penalties, R10) is sound and keeps the compute-vs-retrieval comparison clean.
- 'Restart differs from clear-only => hidden channel; bug' as an explicit hidden-channel equality check.
- Signed GEM-style backward transfer as the primary damage statistic with Chaudhry max-based forgetting as secondary, and the explicit E[max(0,eps)] = sigma/sqrt(2 pi) treatment of the draft's clipped statistic.
- Per-seed reporting with the rule that between-seed spread exceeding the within-cell interval means the result is seed-dominated and must not be summarised by a mean.
- The observation-to-interpretation table (which outcomes count against the hypothesis vs indicate a broken component), and the honest 'bridge stated plainly' paragraph that labels the milestone as composition bound to a novel name rather than new-procedure acquisition.
- The three-way two-hop comparison design (a) adaptive retrieval vs (b) constant read vs (c) constant read plus extra computation, with the paired sign-test floor of 1/32 across five seeds.
MISSING:
- No positive control for the stopping rule itself: the brief demands that null results be interpretable, but nothing tests whether the 0.5-point / ~3,000-step patience would terminate a run that converges later; at least one seed per condition should run to the 12-run ceiling without early stopping.
- Data separation between the stopping pool and the final test pool is not stated in the visible text: Pool 2 is queried repeatedly for stopping decisions; if Pool 2 is also the reported test, the reported numbers carry optional-stopping bias. A separate final pool (and whether the 42 Tier 2 programs are disjoint from Pool 2) is required by the brief's 'training, writer-reward, validation, and final-test data remain separated'.
- The uncertainty estimate ignores clustering by program class (42 classes) and no minimum number of programs or power calculation is given for the Tier 2 compositional-code-vs-index test.
- 'Achieved recall capacity' for the fair memory comparison is not specified in the visible text; only byte-matching of the slot memory is mentioned. The brief asks for both bytes and achieved recall capacity.
- The curriculum ('16 fixed names for the first two runs and then opens the name generator') is not a per-stage information boundary the brief asks for: which weights change during the fixed-name phase, and whether the 16 names can appear in any evaluation pool, is not stated.
- Budget does not account for running several tiny seeds concurrently on one 16 GB GPU, which is the obvious way to fit 55-75 GPU-hours into the wall-clock; nor for PC2/PC3/PC4 as separate trained conditions.
- Fragment-limited: the information-boundary table, exact teaching representation, and operand/composition novelty splits for the method example live in sections not provided to me; I could not verify them.
VERDICT: I would adopt this contract as milestone one, ahead of the facts-first milestone, because it is the only proposal on the table that tests something on the road to method learning while still being small enough to train from scratch: no pretrained LM, a 60-word controlled vocabulary, a 128x128 memory, a differentiable writer with no oracle input, and fixed T=8. But I would not run it as written. Three changes are mandatory before the first run: (1) replace the 3,000-step patience with a patience measured in whole runs (no improvement over four consecutive runs, roughly 40k+ steps) and run one seed per condition to the 12-run ceiling regardless, so a PC4 or Tier 2 null can be distinguished from a run stopped on the plateau; (2) convert the two-phase curriculum into a per-batch mixture (a fixed fraction of episodes drawn from the 16 fixed names throughout), which is what the cited Kirsch intervention actually was and which avoids both the distribution-shift stall and the index-collapse incentive of two runs on 16 names; (3) report Tier 2 with cluster-robust intervals over the 42 programs and hold the stopping pool disjoint from the final pool. Re-budget at 55-75 GPU-hours with concurrent seeds on the one GPU, and add one seed of PC1 run to the ceiling before concluding the reader "cannot execute depth-3 programs at this scale". With those changes the positive-control ladder does what the brief asks; without them the ladder diagnoses the stopping rule's own artefacts as component failures.

STRONGEST ATTACK: The headline claim, "a one-shot differentiable write into W can persist a program over known primitives," is satisfiable by W storing a three-slot categorical code (which of six primitives sits in each of at most three positions, roughly log2(216) bits per name) that the meta-trained reader decodes and executes. That is structurally the same achievement the brief rejected in the draft ("storing 24 numbers and applying an already-learned arithmetic operation"), upgraded from one stored offset to a stored tuple selecting among familiar compositions. The proposal concedes this in the "not supported" paragraph, but the interpretation table treats Tier 2 (unseen compositions at 42 test classes) as the only detector of index collapse, and the proposal itself admits Tier 2 "may be noisy at 42 test classes." Worse, the table's reading "Tier 2 at the nearest-class rate: W holds an index" is not the only explanation: a reader (theta) that cannot execute unseen compositions produces the same observation, and the excerpt does not show a positive control in which oracle program content is written into W and Tier 2 compositions are scored, which is the comparison needed to attribute a Tier 2 failure to the writer rather than the reader. Concretely this hits the Episode C Tier 2 test and the decision-record claim: a pass supports "W persists a tuple that selects a meta-trained composition," and a Tier 2 failure is uninterpretable between writer-collapse and reader-limitation without the oracle-content control.
ERRORS:
- "Chollet's benchmark rule, that a task answerable by the same program that fits the teaching set has zero developer-aware generalisation difficulty (R9, extra)" — misattribution. Chollet (II.2.1) defines Developer-aware Generalization Difficulty as a measure; the zero-difficulty statement is the digest annotator's gloss (a deduction from that definition), not a rule Chollet states, and it is not a 'benchmark rule' in III.1 or II.3.2.
- "Kirsch et al. report long meta-optimisation plateaus and that biasing the task distribution toward a fixed subset 'enables a smooth path from memorizing to learning'" — the digest (R13 extra) describes the intervention as 'a fixed label permutation for a fraction of each batch', i.e. a persistent mixture inside every batch, not a temporal curriculum of a fixed subset followed by opening the generator. The proposal's '16 fixed names for the first two runs' is an adaptation and should be labeled as the author's hypothesis, not as what Kirsch reports. The verb is also lightly reworded ('enabling' in the source).
- "benefit = accuracy on the new name's 500 queries after the write minus before (before is chance)" — pre-write accuracy is asserted rather than measured; a meta-trained reader with no entry for a novel name may have a systematic default output, so 'before' must be measured on the same 500 queries or the benefit number is biased.
- Mathematical statements checked and found correct: 95% binomial half-widths 1.96*sqrt(0.9*0.1/500)=2.6 points and 1.96*sqrt(0.25/500)=4.4 points; one-sided sign test with five concordant seeds p=1/32; E[max(0,eps)]=sigma/sqrt(2*pi) for zero-mean Gaussian eps; delta-write locality as one rank-1 subspace (I - beta k k^T has eigenvalue 1 with multiplicity d-1). No arithmetic errors in the excerpt.
UNSUPPORTED:
- "The reflection loss is the in-weights analogue of the support loss without which meta seq2seq dropped from 99.95 to 5.43 percent (R3-compositional, C3)." The Lake 2019 result concerns an in-context key-value memory with no weight writes; nothing in the digest shows that a 'what does NAME do?' reconstruction loss helps a writer into W. This is a design hypothesis by analogy and should be labeled and ablated, not presented as evidence-backed.
- "No oracle answer input, no RL heads, no discrete sampling: with the definition contract there is no answer to feed the writer, which removes the 'write the label' degeneracy the review found." It removes the oracle-label degeneracy only; the writer can still collapse to an index over meta-training definitions, which the proposal itself lists as risk (1). 'Removes' overstates; 'replaces one degeneracy with a weaker one that Tier 2 must detect' is what the evidence supports.
- "Tier 2 passes, content swap does not move the answer: counts against 'W carries the program'; the reader completes from theta." and "PC4 passes, Tier 2 at the nearest-class rate: W holds an index." Both interpretations assume the reader is not the limiting component; without an oracle-content positive control on unseen compositions, a Tier 2 failure is equally consistent with a reader that executes only meta-trained compositions.
- "Budget, as a hypothesis: five seeds times 12 runs is 10 GPU-hours ... roughly 40 GPU-hours" — correctly labeled as hypothesis; no evidence that a differentiable writer trained through post-write query loss on a depth-8 reader converges inside 12 chained ten-minute runs. The PC ladder makes a null interpretable but the convergence assumption is unsupported.
- "Learned halting introduces a confound ... that would contaminate the compute-versus-retrieval comparison." Plausible deduction from R10 (ACT sensitivity, expected-time gaming), but the digest does not show that fixed T is confound-free; a fixed T=8 could itself favour or disfavour the adaptive-retrieval arm depending on how many hops it needs. Should be stated as a design choice with a T-sweep, not as an evidence-backed requirement.
GRAFT:
- Signed GEM-style backward transfer as the primary damage statistic, Chaudhry max-based forgetting as secondary, and the sham-write null (write a definition for an unused name, measure the same statistic on the same probes) to subtract the sigma/sqrt(2 pi) clipping bias if any clipped reward is retained.
- The positive-control ladder with an explicit observation-to-interpretation table (PC1 reader, PC2 read-and-execute, PC3/PC4 writer) and project-level stopping rules (widen reader once, then stop and name the blocker).
- 'Restart differs from clear-only: hidden channel; bug' — treating restart-vs-clear equality as a hidden-channel check rather than a success metric.
- The three-arm two-hop comparison (adaptive retrieval vs constant read at equal depth vs constant read with extra computation) with a pre-registered 20-point gap and five-seed sign test, which respects the brief's distinction that a constant read does not prove recurrent computation is useless.
- Content-swap intervention on W (swap stored content between two names and require the answer to follow the content) as the causal test that W carries the information.
- Fixed T=8 in milestone one, deferring the recurrent-depth successive-step divergence exit (R10 C3c) until fixed-T results exist.
- Refusal to include a corruption-detection test when no observable evidence makes corruption identifiable, and explicit statement that Episode D's executor and audit log are practice-time tools absent at scoring.

- Fair memory comparison must report bytes AND achieved recall capacity; the excerpt mentions a 'byte-matched slot memory' but gives no achieved-capacity measurement (e.g. names recoverable at >=95% before interference) nor the total number of names written relative to the 128-dimensional key space, where the interference term eta (v - Wk)(k^T k') and the at-most-128 exactly recoverable associations bound become binding.

- A positive control writing oracle program content into W and scoring unseen compositions (Tier 2) is needed so that a Tier 2 failure can be attributed to the writer rather than the reader; it is not visible in the excerpt's ladder.
- Episode D's verification-signal origin is only gestured at ('the audit log and an executor'); the brief asks where the task and verification signal originate and what prevents confident internal claims from becoming facts. Note: only sections 4 (partial), 5 and 6 of the proposal were supplied to this judge; sections 1-3 and the information-boundary table could not be audited.
VERDICT: I would adopt this as milestone one, with three changes. First, reword the supported claim from "persist a program" to "persist a bound description that selects a composition of meta-trained primitives and is executed by a frozen reader on unseen operands," which is what the evidence can show and which the proposal's own 'not supported' paragraph already concedes. Second, add an oracle-content positive control on unseen compositions and a linear probe of the readout for per-slot primitive identity, so that Tier 2 failures separate writer collapse from reader limitation instead of being declared 'W holds an index.' Third, report the number of names written against the 128-dimensional key space, the measured key-overlap distribution, and a measured pre-write baseline, since the interference and benefit numbers are otherwise under-specified. The citations are used accurately except for two soft misattributions (the Chollet 'benchmark rule' gloss and the Kirsch curriculum), the mathematics checks out, and the brief's distinctions are respected where the excerpt lets me see them. The bridge to method learning (Contract D: three input-output pairs instead of a definition, same reader and W) is real but moderate: it upgrades instruction-following to induction over the same 216-program space, and the proposal is right to say the step to a genuinely new primitive is weak at this scale.
