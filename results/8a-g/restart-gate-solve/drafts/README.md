## What changed and why

**A. Probe checkpoint guard (bug fix).** `probe-resume` never checked that the checkpoint in `--keep` belongs to the job. The pack's README documents `--keep ...\work\g2fa4\ckpt-keep`, which holds g2fa4's accum-4 step 200, but without `--job` the probe picks the first job that is not skipped, which is g2fa8 (accum 8); `train.py` only emits a `resume_warning` on an accum mismatch (the config hash does not include `--accum`, so the hash cannot catch it either), so the probe would resume an accum-4 checkpoint under accum 8 and report a false FAIL. Now, after the cheap file checks and before anything is started or written, `probe_resume` reads `keep/step-<k>.json` and refuses (exit 2, message, no probe queue or folder created) if: its `step` is not `--step`; its `accum` differs from the job's accum (the `--accum B3G2=<n>` of the job's queue file, parsed by the new `queue_accum`; falls back to `accum` in plan.json; refuses if the two disagree, or if neither exists, or if the sidecar has no `accum`); its `config_hash` differs from the main run's own (full hashes of the sidecars in the run's `ckpt\`, else the 12-character prefix of the `resumed` events; if the main run has neither, the comparison is skipped and a line says so in supervisor.log). After each probe run, an `accum` `resume_warning` in the probe's events (new `Events.warnings`) makes the report FAIL with the reason and no statistics (other warnings, e.g. a code-id change, are only recorded in `resume_warnings` and shown in the .md). New pure functions: `queue_accum`, `main_run_hashes`, `keep_guard`.

**B. Mean-form reading and first-update diagnostic (additive).** `resume_probe_verdict` keeps the registered rule exactly (`verdict`, `n`, `d`, `limit`, `mean_abs_*`, `diff_*` are computed by the unchanged lines) and returns nine more keys: `first_r1_c`, `first_r2_c`, `first_r1_r2`, `Dbar`, `Nbar`, `ratio` (inf if Nbar = 0 and Dbar > 0; 1.0 if both 0), `mean_form_limit = max(0.02, 2 Nbar)`, `mean_form_verdict`, `lag1_autocorr` (of the signed R1 - R2 series; `None` for under 3 points or no variance; new stdlib `lag1_autocorr`, plain biased estimator). `Sup.md_probe` shows them under the heading "recorded beside (pre-registered mean form, not the registered gate)", after the table; a report in the old format still renders. The exit code and `verdict` are still the registered rule's.

**C. Trace-A mean item can be soft.** In `trace_a` the `resume_mean_abs` miss now goes through `miss('resume_mean_abs', ...)` like `resume_max_abs`, so listing it in `rules['soft']` records it in `soft_misses` instead of stopping the run. No default changed: with no soft list, or with today's soft list `['peak', 'resume_max_abs']`, `trace_a` returns exactly what the original returns (tested). Installer: new `--soft-trace-a-mean`, valid only together with `--soft-trace-a` (argparse error otherwise), which writes `soft = ['peak', 'resume_max_abs', 'resume_mean_abs']` (`SOFT_TRACE_A_MEAN`). Idempotency needed no new logic: `added_plan` compares the whole existing g2fa8 entry with the expected one, so the three variants (strict, soft, soft + mean) are mutually "differs from the expected entry" refusals in every order (tested both ways). The first redone update (0.01), NaN/Inf and the loss falling remain hard in every variant (tested with the most permissive list).

**D. `rejudge_probe.py` (new, stdlib only).** `python rejudge_probe.py PROBE-RESUME-<job>.json [--trace-a-mean 0.0282] [--trace-a-json TRACE-A-<job>.json|state.json]`. It recomputes everything from C, R1, R2 in the file (it does not need the new fields, so it also reads a probe made by the old supervisor), applies the pre-registered reading (text copied verbatim in the docstring, the output and the JSON), prints a plain-words paragraph plus the numbers and writes `REJUDGE-<job>.json` next to the input. The value v is `--trace-a-mean`, else `resume.mean_abs` of `--trace-a-json`, else 0.0282. Verdicts: INSIDE healthy noise (exit 0), UNRESOLVED (1), OUTSIDE (2); exit 3 for an unreadable file or a probe that did not judge (`why_fail` set, e.g. the accum refusal of change A). The restore check is exact equality with 0, so any nonzero first-update gap is OUTSIDE ("restore differs at the first update: ... do not read").

## Amendment 1 (PREREG-trace-a2.md, "Amendment 1", written ~22:05 UTC, after the CPU positive controls)

DRAFT, same status as everything above: nothing installed, committed or pushed; the pack is untouched; every new behaviour is opt-in or only recorded, so a plan.json written by the current installer behaves as before.

**Why.** The positive controls showed that the first redone update's loss is a forward pass before the optimizer step, so lost AdamW state and an off-by-one lr schedule give exactly 0 there and first show at the 2nd and 3rd redone updates (A1.1); and that a single ratio failure of the two-resume mean form is a heavy-tail draw, not proof of a fault (A1.3). So: two start-of-redo items in the running gate, the same early window in the reading gate, and a reading that says "measure more" instead of "broken" when only the ratio or the mean form fails.

**1. `trace_a` (running gate), opt-in rule keys in the job's `trace_a` dict.**
- `resume_early_abs` (float): hard item: max |dL| over the 2nd and 3rd redone updates (`d[1:3]`) must be <= it. The failure message names the two updates and the one that is largest ("early redone updates 102 and 103 ... differ by up to 0.0071, at update 103 (limit 0.005)"). It is a `why_fail` item, never released by `rules.soft` (tested with the key named in soft).
- `resume_exact_fields` (list): hard item: at the FIRST redone update, every listed field present in BOTH the earlier segment's train line and the resumed line must be equal (exact `==`; NaN equals NaN). An entry ending in `_` is a prefix (`plan_` matches `plan_rows`, `plan_gapped`, ...); any other entry is a field name (`rounds` does not match `rounds_total`). `loss`, `step`, `elapsed`, `seg` are never compared this way. Mismatches go to `r['resume']['exact_mismatch']` (field, earlier value, resumed value) and to `why_fail`; the fields actually compared go to `r['resume']['exact_checked']`. If none of the listed fields is in both lines, nothing is compared, `why_fail` is not touched and a note says so (the item must not pass silently without anyone seeing that it compared nothing; whether the real `train` lines carry `rounds` / `plan_*` depends on the model's aux dict, see below). **Superseded by the code-review fix round below (item 4): a listed field that is missing is now a hard failure.**
- `r['resume']['early_max']` is recorded ALWAYS when at least 2 redone updates exist (rule or not). This is the one change to the default output of `trace_a`: one extra key in `resume`. Verdict, `why_fail`, `soft_misses` and every other key are identical to the original function's for rules without the new keys (tested against the original function; the comparison helper `strip_early` drops only `early_max`).
- `resume_first_diff` and its default 0.01 are untouched (A1.2 is Ben's bar). The losses are compared exactly as before (the full train-line dicts are kept in addition, for the first redone step only).
- What a `train` event carries: `overlay/train.py` writes `jprint(event='train', step, loss, lr, elapsed, cap_hits, **aux)`. So `lr` is always logged; `rounds` and `plan_*` are logged only if the model returns them in its aux dict (the positive controls' `rounds`, `plan_rows`, `plan_gapped`, `drill_share` come from there; I did not check the real b3g2 model). The fake runner logs `lr` only. `elapsed` is a clock, which is why it is excluded.

**2. Installer.** New `--trace-a-early` (only with `--add-job g2fa8`; alone or with `--soft-trace-a [--soft-trace-a-mean]`) adds `resume_early_abs = 0.005` and `resume_exact_fields = ['lr', 'rounds', 'plan_']` (`TRACE_A_EARLY`, copied) to the g2fa8 entry's `trace_a`. No change to `added_plan`'s logic: it compares the whole existing entry with the expected one, so the six variants (strict, soft, soft + mean, each with and without `--trace-a-early`) refuse each other in every order ("differs from the expected entry"; all 36 ordered pairs tested; same variant again = idempotent, only the log file is new). The usage-error text for `--skip-g2fa4 / --soft-trace-a / --trace-a-early` without `--add-job g2fa8` changed to name the new flag.

**3. Probe (P1b).** `resume_probe_verdict` returns three more keys: `early_max` = max over probe updates 2 and 3 (e.g. 202-203) of max(|R1-C|, |R2-C|), `early_limit` = 0.005 (`EARLY_LIMIT`), `early_verdict` PASS/FAIL (`early_max` and `early_verdict` are None for under 2 updates; with exactly 2 updates only the 2nd counts). The registered `verdict` and all earlier keys are unchanged (the 1000-random-trace comparison with the original function still passes; it now expects 12 added keys). `md_probe` adds a line "early window (the 2nd and 3rd probe updates = 202 and 203, P1b): max |R - C| = ...; limit 0.005: PASS/FAIL" to the "recorded beside" block; a report from before the amendment (no `early_max`) renders without it. The probe's exit code is still the registered rule's.

**4. `rejudge_probe.py`: the amended reading (A1.3).** Docstring: the original pre-registered text first, verbatim, then "AMENDMENT 1" with the text this tool applies; the output prints both; the JSON holds `preregistered_reading` (original) and `amendment_1_reading`, plus `original_reading_verdict` (what the first version would have said, for comparison only).
- P1 (first update exactly 0 for R1 and R2) or P1b (early_max <= 0.005) fails -> OUTSIDE (exit 2).
- P1, P1b pass and P2 (registered max rule), P3 (Dbar <= max(0.02, 2 Nbar)) and ratio <= 2 hold -> INSIDE healthy noise if v <= max(0.02, 2 Nbar) (exit 0), else UNRESOLVED (window) (exit 1; verdict key `UNRESOLVED`).
- P1, P1b pass but P2, P3 or the ratio fails -> UNRESOLVED_CALIBRATE (exit 1; the text says to run 2 more resumes of step-200 and judge Dbar against L = max(0.02, 2 x largest pairwise mean among the 4 resumes)). A case the first version called OUTSIDE (ratio above 2, or the registered rule failing) is now this verdict when P1 and P1b hold.
- `--calibration PROBE2.json` (a second probe JSON of the same job, step, upto, with the same C; its R1, R2 are R3, R4): L = max(0.02, 2 x the largest of the 6 pairwise mean |Ri-Rj|), Dbar4 = mean over the 4 resumes of mean|Ri-C|; OUTSIDE if Dbar4 > L, else INSIDE if v <= L (v = the trace-A window value, L from the probe window), else UNRESOLVED (window). The calibration verdict replaces the 2-resume verdict (so a P2/P3/ratio failure of the first pair no longer matters, as the amendment says). **Narrowed by the code-review fix round below (item 3): the calibration is applied only when the 2-resume verdict is UNRESOLVED_CALIBRATE.** Two things not in the amendment text, flagged in the docstring: P1 and P1b are also required of R3 and R4 (a failure is OUTSIDE), and a second file with another job, step, upto or C, or one that did not judge, is refused (exit 3) rather than mixed. Exit codes: 0 INSIDE, 1 UNRESOLVED (either kind; stdout says "UNRESOLVED (window)" or "UNRESOLVED_CALIBRATE"), 2 OUTSIDE, 3 unreadable. `rejudge()` now needs at least 3 probe updates (the early window); a shorter list raises ValueError (exit 3 in the CLI).

**Tests (tests/test_gatefix.py, 6 new; the changed old ones are noted).** `t_trace_a_early_optin`, `t_trace_a_exact_fields`, `t_verdict_early`, `t_installer_trace_a_early`, `t_rejudge_amended`, `t_rejudge_calibration`.
