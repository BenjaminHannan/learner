Bench protocol (prof_train `abbench`, unchanged):
- 3 interleaved rounds, A, B, A, B, A, B.
- Each round is a fresh trainer on the same rows (batch seed fixed), with 10 untimed warm-up updates, then 40 timed updates in 8 chunks of 5.
- A round's value is the median of its 8 chunk s/update. An arm's value is the median of its round values.
- **Warm stretch** = the 40 timed updates after the 10 warm-up updates of each fresh trainer. Every speed number in this sheet is from the warm stretch.

## 2. Marks

**Mark 1 (win).** An arm wins only if all of these hold:
- it has 3 read rounds (mark 3);
- in each, B's round value < A's;
- median B ≤ 0.95 × median A;
- peak allocated memory of B ≤ 10 GB;
- mark 2 holds.

**Mark 2 (same maths).**
- `defer`:
  - **bf16 bar** in `abequiv`: relative loss difference ≤ 1e-4 and gradient cosine ≥ 0.9999, beside the rerun noise floor;
  - **and** E4 (`equiv`, 300 updates, pinned stochastic parts): mean |Δloss| over updates 101–300 ≤ 0.02, and the two means within 0.01.
  - `defer` is labelled **numerics-changing** whatever the result.
- `kvcat`, in `abequiv --deterministic` (CUBLAS_WORKSPACE_CONFIG=:4096:8 set before CUDA starts, `torch.use_deterministic_algorithms(True, warn_only=True)`):
  - if the baseline's own rerun is bitwise equal in bf16, kvcat must be bitwise equal too;
  - otherwise kvcat's relative loss difference and gradient relative L2 must each be ≤ the baseline rerun's;
  - failing both, it falls to the bf16 bar and is relabelled near.
  - Whatever the result, kvcat stays "exact-candidate" and is treated as numbers-changing in this run. K4 is information only.

**Mark 3 (normal speed: which rounds are read).** Each run (one A or one B of one round) belongs to a **setup**. A run is **normal** if all of (a)–(e) hold:

- (a) **Slow-machine reference per setup.** The run's round value is ≤ 1.10 × its setup's reference:
  - baseline accum 4: the fastest A round of D4 or AA;
  - defer accum 4: the fastest of D4's B rounds and K4's A rounds;
  - defer+kvcat accum 4 (K4's B) and both setups of D8: the fastest round of that setup within its own arm. These are labelled **secondary**.
- (b) **Chunk rule.** Each of its 8 chunks lies within 0.95–1.05 of the median of the same-numbered chunk across all runs of the same setup on that box. (Chunks within one run differ by design, because they draw different K; the same-numbered chunk replays the same updates.)
- (c) **Throttling.** No host-monitor sample inside its timed window (`timed_start_utc`..`timed_end_utc`) shows a throttle reason other than 0x0 or 0x1.
- (d) **CPU steal.** CPU steal is < 2% in every such sample.
- (e) **Trainer core speed.** The trainer core's MHz is ≥ 0.90 × the box's median trainer-core MHz over all timed windows, in every such sample. If the box does not expose a readable trainer-core MHz (the column is NA in every sample), rule (e) is **struck for that box** and the readout says so.

A round is **read** only if both its A run and its B run are normal. An arm with fewer than 3 read rounds is "regime-confounded". It is never read, and its outcome is "undecided" (§5). GPU utilization is logged in every sample and reported, but it is not a rule.

**Mark 4 (identical work).** Every A and B run of an arm must have the identical `rounds_seq`: the thinker rounds of every timed micro-batch, in order. A run that differs voids its round.

**Mark 5 (noise).** On each box, AA must show |median B / median A − 1| < 1%, using read rounds only. Otherwise **nothing on that box counts**.

**Mark 6 (replication).** D4 must meet mark 1 on two boxes on different hosts: a different `hostname` and Vast machine id. The two boxes must have the same image, torch version and CUDA version (from `*.launch.json` and `gr4_host.txt`); a mismatch means box 2 is not a replication. Each box is reported separately, with its host CPU model. Results are never pooled.

**Mark 7 (mechanism, deterministic counts, box 1's profiler runs).** For `defer`, all three must hold:
- stream syncs per update ≤ 300 (baseline ≈ 1,305);
- device-to-host copies per update ≤ 150 (≈ 745);
- kernels per update ≤ 0.65 × the baseline's in the same box.

A D4 speed result whose counts miss is reported as an **artifact**, not a win.

## 3. Predictions (each with what proves it wrong)

- **P1:** D4 ≥ 1.25× on each box (speed = median A / median B). Proved wrong if < 1.25×. **Framing kill:** the launch-bound framing is dead only if all of these hold on **both** boxes (each counting under mark 5), the same two-host standard as the win:
  - D4 < 1.10×;
  - mark 7 holds;
  - `defer`'s profiled kernel time per update ≤ 1.10 × the baseline's (box 1 profiler).

  If `defer`'s kernel time is > 1.10 × the baseline's, the verdict is "**defer is inefficient on CUDA**", not "framing wrong" (also needed on both boxes). A kill or inefficiency verdict on one box only, or one box winning while the other meets a kill condition, buys one more replication box (§5).
- **P2:** D8's speed ≥ D4's. Proved wrong if D8 < D4.
- **P3:** K4 between 1.00× and 1.10×. Proved wrong outside that band. (This replaces the solve report's "kvcat ≥ 1.03×".)
- **P4:** on the PC (a separate session, same marks), D4's gain is smaller than on the 4090. Proved wrong if it is larger. Not tested in this run.
- **P5:** `defer`'s peak allocated ≤ baseline + 0.5 GB.
- **P6:** R = the baseline's **profiled** kernel time per update (box 1, ms) ÷ the **unprofiled** in-box A median of D4 (ms per update). Predicted R ≈ 0.63. **The framing is dead if R ≥ 0.90**: the GPU was busy almost all the time and the update was GPU-bound.

## 5. What each result allows (the only uses of this run)

- **D4 meets mark 1 and ≥ 1.25× (P1) on both hosts** (with marks 2, 4, 5 and 7 holding): the production port of `defer` (solve report §4.1) may be written and reviewed, and a PC test may be bid for. The port is used **only in fresh runs started from update 0** under new run names. There is **no change to 8aB3G2A4/A8**.
- **D4 wins on one host only** (the other box below 1.25×, regime-confounded, or voided by mark 5), **or the hosts disagree** (a win on one, a kill or inefficiency condition on the other), **or a kill or inefficiency condition holds on one host only:** one more replication box under this same sheet, and nothing else.
- **D4 between 1.10× and 1.25×, or mark 1 fails:** no port. The next step is a GPU profile by code region, under a new pre-registration.
- **The framing kill holds** (P6 on box 1, or P1's kill condition on both hosts): `defer` and CUDA graphs are **closed as launch fixes**.
- **`defer` is inefficient on CUDA on both hosts:** not a framing kill; no port.
- **Mark 7 misses:** the speed result is an artifact. Debug offline, and no more rentals for this.
- **Mark 2 fails for `defer`:** `defer` is not used, however fast.
- **K4 and D8:** information only. The readout reports K4's GPU peak memory.
