How Premonition's model works

It reads a question, thinks in rounds on a numbered notepad, and answers. We follow one question all the way through.

  • Model: B2, the best whole model so far. Nothing pretrained.
  • Size: 3,302,481 learned numbers (small version); 10,890,041 (medium version).
  • Symbols it knows: 108 characters and special marks, as counted in the size.
  • Teal and orange parts are learned. Grey parts are ordinary code written by us.
Illustrative

Our example question

We follow this one through each part. 12 minus 5 is 7, then plus 3 is 10.

  • Made up for this page, in the style of the 200,000 practice questions. It is not a real row.
  • Real questions: 81 characters on average, longest 204. A batch is padded to about 161.

Read: every letter becomes a vector

The reader gives each character a list of 256 numbers that carries what it is, where it sits in its word, and what is next to it.

  • Input per letter: letter + position in the question + place code. The place code counts from the right end of the word: units 0, tens 1, up to 14. Spaces get code 15.
  • Two blocks of a 5-wide convolution, so each letter sees 4 letters left and 4 right.
  • Output: one 256-number vector per character, up to 208 characters. The thinker later looks at all of them.
Plain code

Hand-written helper: finds the numbers

Before the thinker starts, ordinary code (not learned) pulls each number out as an exact whole number. The model never has to read '12' digit by digit to use it.

  • Number finder: a plain pattern for runs of digits. It keeps the first 16 numbers, as whole numbers (capped at 10^18).
  • Word finder: a second helper marks where each word starts and ends, first 64 words.
  • Why this matters: it is part of the input path that does not have to work through the learned reader. An outside-calculator test has to remove it.

Workspace: 27 numbered slots

The thinker's notepad. Numbers from the question go in the first slots. Results of each step go in the last 7.

  • 16 number slots + 4 constants (1, 2, 10, 100) + 7 result slots = 27.
  • Each filled slot is stored as a 93-number code: 9 digit one-hots (units first), a sign, a valid flag and the size of the number. Plus the reader's average over that number's digits, plus its slot number.
  • The thinker can only read the workspace. It cannot write into it directly.

Thinker: 17 state vectors

The thinker's own memory is 17 vectors. Two of the 8 control vectors steer the work. The other 6 are scratch space that the thinker really uses.

  • 8 control + 9 register vectors, each 256 numbers wide (384 in the medium version).
  • Output heads read only control 0 and control 1 (from the code). Controls 2 to 7 only pass information through attention. Zeroing them at test time cost 1.6 points on pooled-5 and 7.8 on chains (99.4 to 91.6) on one seed (s200), so they are used.
  • Registers are tied to the 9 answer letters: 8 letters plus an end mark.

One round: look, talk, think

Every round the 17 vectors look at all the letters and all the slots, compare notes with each other, then pass through a small network. Eight rounds, same weights each time.

  • Small version: width 256, 4 attention heads, 2 blocks, hidden layer 1,228. Medium: width 384, 6 heads, 3 blocks.
  • Each round gets a stamp saying which round it is, so the same weights can behave differently each time.
  • Looping is fixed at 8. Running 16 loops scores 1.6 to 1.9 points worse.

Rounds 1 to 7: one calculator step each

Our example needs two steps. The thinker writes them one per round. A step is: which operation, and which two slots to use.

  • Control 0 picks one of 9 operations, then two pointers choose the operand slots (each a match between a 64-number query and the slot keys).
  • At most 7 steps, because there are only 7 result slots and one step per round.
  • Unused rounds are trained to say NOOP.
Plain code

Calculator: nine exact operations

It does the arithmetic exactly. The thinker only chooses what to ask it.

  • Exact whole-number maths. DIV only when it divides evenly. Anything that is invalid or 10^9 or larger is marked invalid.
  • The result goes back into the workspace as a new slot, so the next round can use it.
  • Proof it matters: with the calculator off, program questions score 0.6%. Swap ADD and SUB inside it and 99.9% of answers follow the swap.

After round 8: how to answer

One last vector decides what kind of answer to give and where to find it.

  • Mode head: 3-way choice (number, word, letters).
  • Answer pointer over the 27 slots. Word pointer over up to 64 words.

Talker: three ways to speak

The talker adds no thinking. It turns the thinker's final choice into text.

  • NUMBER: the learned part is the pointer. The digits are printed by a line of code.
  • WORD: the pointer is learned. Word boundaries come from the hand-written word finder.
  • LETTERS: the 9 registers each give one letter, units first. A learned gate chooses between a letter from the alphabet and a letter copied from the question.
  • Limit: 8 letters. Answers longer than that cannot be written.

Learned versus hand-written

The learned part decides. The code handles exact numbers and exact text, in and out.

  • Why it matters: if the calculator must be outside the model, the input and output paths have to be learned too. That is the test now proposed (T1), with a digit reading and writing check first (D0).
  • Both are untested. Today's 3.3M figure counts only the learned side.

How it learns

It practises 24,000 times on 200,000 questions, checks each try against the answer key, and nudges its weights.

  • Recipe: AdamW, learning rate 1e-3 with warm-up then a cosine fall to 10%, batch 256, bf16, shuffled order, from random start.
  • Teacher-forced steps: where a question has worked steps in the data, the thinker is told the right operation and slots each round. Only 11 arithmetic families have them.
  • Losses: operation, both operand pointers, mode, answer pointer, word pointer, and letter spelling with the copy path.

How we score it

Same-size models learn from the same questions. We compare on questions they have not seen.

  • pooled-5: 6,040 held-out questions across 5 splits (old, new answers, new sentence frames, new words, new wording).
  • chain-5: 1,000 multi-step questions. B2 gets 99.7 to 99.8. The step-writing text model gets 94.
  • Fair play: pass marks are written before any run, seeds are paired, and 6 fresh seeds confirm a win. In that confirm B2 led the plain model on all 6 seeds.

Proof the thinker decides

Break one piece and the answer breaks with it. That shows the thinker, not the talker, is doing the work.

  • Bars: swapping ADD and SUB makes answers follow the swap on 99.9% of rows. Another question's notes: 3.8% right. Shuffled state: 7.9%. No calculator: 0.6%.
  • One small leak: with zero thinking rounds it still got 6.8% on one seed (mark 5%). Plain B2 reads 0 to 10.8 on other seeds.

Where it still fails

It cannot yet learn a new kind of task from a few examples, and rule questions with no worked steps are weak.

  • Rule questions: fewshot_number_rule 9 points and rule_apply 6 points behind the step-writing model.
  • These are the families with no program in the data. The thinker has to solve them in its 17 vectors.

Size, counted honestly

Borrowed parts count. The Gemma version is 274.5M, almost all of it frozen and not ours.

  • B2: 3,302,481 (small), 10,890,041 (medium).
  • With EmbeddingGemma 2: 271,002,624 frozen + 3,500,881 trained = 274,503,505.
  • Shipped plan (not built): about 271M reader + 100M thinker + 25M talker.

Explain it in 30 seconds

It is a very small model that learns to plan steps for an exact calculator, then reports the result.

  • The claim: at 3.3M learned numbers it beats a plain transformer of the same size by 19 points on new questions (73.7 vs 54.4, 2 seeds).
  • The honest caveat: the number handling in and out is hand-written code, and it cannot learn brand-new kinds of task yet.
