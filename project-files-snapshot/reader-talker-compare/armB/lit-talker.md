# Cheap TALKER designs for Premonition (literature note)

Labels: [shown] = the paper reports it; [suggested] = my reasoning from the papers; [untested] = my guess, nobody measured it for this model.
Caveat: arXiv ids and paper facts are from memory, not re-fetched this session (no web fetch was done). Check ids before citing. Param counts are my arithmetic, assuming d=256 core, reader hidden width 2048 (my guess for LFM2.5-1.2B), reader vocab ~65k.

## 1. Pointer / copy mechanisms
- Pointer Networks (Vinyals, Fortunato, Jaitly 2015, arXiv 1506.03134). Output = softmax over INPUT positions (attention scores used directly as the output distribution). [shown] Output vocabulary grows with input length, so it handles items never seen in training (they solved convex hull, TSP with variable n).
- CopyNet (Gu, Lu, Li, Li 2016, 1603.06393). Mixes a generate-mode score over vocab and a copy-mode score over source tokens, in one softmax. [shown] Better on rare/OOV words in summarization and synthetic copying.
- Pointer Sentinel (Merity et al. 2016, 1609.07843). Gate (sentinel) mixes a pointer over recent context with the vocab softmax. [shown] Strong perplexity gains on rare words (WikiText-2).
- Pointer-generator (See, Liu, Manning 2017, 1704.04368). p_gen scalar (from context + state + input) mixes vocab dist and attention dist. [shown] Copies OOV words and facts; adds a coverage term.
- Why copy fixes unseen words (explains 0% -> 57%): [suggested] a plain output head can only emit tokens whose output embedding was trained. A never-seen answer word has no trained logit row, so a state-only talker scores 0%. A pointer scores "which prompt position", a content-independent address, so the answer word comes from the reader's own token, not from the talker's weights. The 57% (not ~100%) is then the part of the answers that are copy-able spans plus pointer accuracy; the other ~30 points from "all prompt words" [suggested] come from (a) answers made of several words / needing token-level reassembly, (b) computed numbers not in the prompt, (c) the talker being able to read which word the pointer should land on. [untested] which of a/b/c dominates; a per-answer-type breakdown of the 57 -> 87 gap would tell.
- Cost: pointer head = query proj (256x256) + key proj from reader states (2048x256) ~ 0.6M params; one dot-product per prompt token (<=160). Speed: negligible (one matmul). Loses: cannot produce words absent from the prompt (needs generate path or program/digit head). [suggested]

## 2. Small decoders, soft prompts, bridges
- Small AR decoder with cross-attention to reader states: standard encoder-decoder (Vaswani 2017, 1706.03762). Rough size at d=256, 2 layers, FFN 4x: ~0.8M/layer self+cross+FFN, plus cross-attn K/V projections from 2048-wide reader states ~1M/layer, so ~3-4M, plus embeddings (tied, trimmed 8k vocab: 2M; full 65k: 17M). [untested guess on arithmetic; sizes are mine]. Speed: answers are 1-5 tokens so 1-5 steps of a 2-layer net, cheap; cost is dominated by the reader pass already paid. Loses: unseen words only if it has a copy path; without one it has the same 0% problem as the state-only talker. [suggested]
- Reusing the big LM decoder: frozen 1.2B head has the full vocabulary, so unseen words are free, but each step runs the whole 1.2B (or at least needs its KV cache). This is the current expensive route. [suggested]
- Prefix-tuning (Li & Liang 2021, 2101.00190): trainable prefix vectors steer a frozen LM. [shown] ~0.1% params tuned, near full finetune on generation with a GPT-2 sized model. Prompt tuning (Lester 2021, 2104.08691) [shown] works better as model size grows.
- ClipCap (Mokady, Hertz, Bermano 2021, 2111.09734): maps a CLIP embedding through an MLP/transformer to a prefix of k vectors for a (frozen or finetuned) GPT-2. [shown] Competitive captioning with a light mapper. This is the closest published "latent -> frozen LM prefix" bridge: core state -> k soft tokens -> 1.2B decodes. Cost: mapper ~1-5M but decoding still runs the 1.2B per token. [suggested]
- LLaVA (Liu et al. 2023, 2304.08485): linear/MLP projector from vision features to LM embedding space. [shown] A 2-layer MLP projector suffices. Flamingo (Alayrac et al. 2022, 2204.14198): gated cross-attention layers inserted into a frozen LM, Perceiver resampler compresses inputs. [shown] Heavier (many extra cross-attn layers), not cheap.
- Takeaway [suggested]: bridges to a frozen big LM are cheap in trainable params but not in inference; they do not meet "cheaper, more specialized talker".

## 3. Structured / program outputs
- PAL (Gao et al. 2022, 2211.10435) and Program of Thoughts (Chen et al. 2022, 2211.12588): LM writes code, interpreter computes. [shown] Large gains on GSM8K-type math over free-text CoT, because arithmetic is offloaded. Toolformer (Schick 2023, 2302.04761): calculator calls. [shown]
- Neural Programmer (Neelakantan, Le, Sutton 2015, 1511.04834): soft selection of operations and columns, executed differentiably. [shown] Works on small table QA with an op set.
- NAQANet / DROP (Dua et al. 2019, 1903.00161): output heads for passage span, question span, count, and "add/subtract signed numbers found in the passage" (a signed 3-way choice per passage number). [shown] Much better than span-only on numeric questions; still low absolute scores, weak at multiplication.
- NumNet (Ran et al. 2019, 1910.06701): numerical-relation graph over passage numbers, same answer-head family as NAQANet. [shown] Improves DROP F1 over NAQANet.
- GenBERT (Geva, Gupta, Berant 2020, 2004.04487): inject numeric skills, generate digits. [shown] Digit-by-digit generation works if pre-trained on numeric data.
- Digit/number heads: Wallace et al. 2019 "Do NLP Models Know Numbers?" (1909.07940) [shown] digit-level/char encodings give better numeracy; xVal (Golkar 2023, 2310.02989) [shown] one-token number encoding with a scalar regression head; Abacus embeddings (McLeish 2024, 2405.17399) [shown] positional digit embeddings fix length generalization of addition.
- Design for Premonition [suggested]: head 1 = op class (copy-span, copy-number, add, sub, mul, div, ... ~8 ops), head 2/3 = two pointers into prompt NUMBER tokens, executor computes result, then a number formatter writes digits. Params: op MLP + 2 pointer heads ~1.5M. Loses: anything outside the op set, multi-step programs unless the core loops emit several. Its failure mode is explicit and debuggable (wrong op vs wrong operand). Gate on copy-vs-compute answer split in the data [untested].

## 4. Output-head cost cuts
- Weight tying (Press & Wolf 2016, 1608.05859; Inan et al. 2016, 1611.01462). [shown] Fewer params, equal or better perplexity. At d=256 and 65k vocab, an untied head is 16.8M, i.e. bigger than the whole 9M core. Tied saves the input table only if the talker also has an input table.
- Adaptive softmax (Grave et al. 2016, 1609.04309). [shown] Frequent-word cluster full width, tail clusters reduced dimension; 2-10x speedup in large-vocab LMs. Gain only matters when vocab is huge; irrelevant at 8k.
- Vocab trimming: Abdaoui et al. 2020 "Load What You Need" (2010.05609) [shown] dropping unused vocab rows of mBERT keeps accuracy while cutting 45%+ params. [suggested] For this task: keep digits, answer-word list from train, and reach the rest via copy. Trimmed 4-8k x 256 = 1-2M. Loses: any uncopyable unseen word.
- Reader tokens as "free vocab": the 1.2B LM's input embedding table already has all words. A pointer into prompt tokens needs none of the output table. [suggested]

## 5. Latent-reasoning models and their output heads
- Coconut (Hao et al. 2024, 2412.06769): feeds last hidden state back as next input embedding (continuous thought). [shown] Final answer is written by the same pretrained LM head (GPT-2 124M base). So the "talker" is the full LM; no specialized head.
- Huginn / recurrent depth (Geiping et al. 2025, 2502.05171): prelude + recurrent core + coda, 3.5B params, loops at test time. [shown] Coda ends in the full-vocab LM head (~65k vocab). Head is a normal tied-size softmax; not cheap by design.
- Tiny Recursive Model (Jolicoeur-Martineau 2025, 2510.04871): ~7M params, 2-layer net, recursion over latent z and answer y; [shown] the answer y is kept as a grid-token embedding and read out by a small output head (linear over the small token set, plus a halting head). Works because outputs are a fixed small alphabet (Sudoku/Maze/ARC grids). Not tested on never-seen words. [suggested]
- HRM (Wang et al. 2025, 2506.21734): ~27M, high-level and low-level recurrent modules; [shown] output = linear head on the high-level state per token, fixed small vocab.
- Perceiver IO (Jaegle et al. 2021, 2107.14795): latent array; outputs are produced by cross-attending a set of output QUERIES (one per desired output position) to the latent. [shown] Output size set by queries not by latent; decoder is one cross-attention + MLP, a few M params at d=256. [suggested] Fits our case: queries could be "answer slot k" embeddings that cross-attend to core state and reader states.
- Universal Transformer (Dehghani 2018, 1807.03819) [shown]: recurrent depth with ACT; output through ordinary head.
- Pattern [suggested]: tiny reasoners (TRM, HRM) have tiny heads because their output alphabet is tiny and closed. Big-vocab latent reasoners (Coconut, Huginn) reuse the big LM head. Premonition sits between: open vocab, but short and mostly copyable. None of these papers address copy of unseen words from a prompt.

## 6. Non-autoregressive / single-step answers
- Span extraction heads (BERT SQuAD, Devlin 2018, 1810.04805): two linear vectors (start, end) over token states; one forward pass; [shown] ~1.5k params of head on top of the encoder. This is the cheapest copy talker for contiguous answers. Loses: non-contiguous or computed answers.
- NAT (Gu et al. 2017, 1711.02281) and Mask-Predict (Ghazvininejad 2019, 1904.09324): parallel token output, [shown] some quality loss vs AR (multimodality), mitigated by iterative refine. For 1-5 token answers, [suggested] fixed answer slots with a length/stop class, each slot doing a pointer-or-vocab choice, avoids AR cost; the risk is slot coupling (e.g. "twenty" "three" consistency) [untested].
- Classification over a closed answer set plus pointer slot is single-step.

## My ranked picks (cheapest that should hold ~87%) [untested for all]
All three need a prompt-copy path because 0% on unseen words means the vocab head cannot be the only route.

1. Pointer-generator-lite with typed gate (~1-2M params). Core state (256) + reader token states projected to 256 give: (a) pointer over <=160 prompt positions, (b) tied small-vocab head (4-8k incl. digits, ~1-2M tied), (c) 3-way gate [copy | vocab | digit-number]. Emit up to ~4 slots with a stop class, one forward pass per slot. Why first: directly implements the 0%->57% fix, and the extra points toward 87 should come from letting the pointer read reader-contextual states (not just raw words) [suggested]. Total ~2M new params. Loses: multi-token words that the reader tokenizes into pieces are copied piece by piece (needs span start/end rather than a single pointer); computed numbers rely on vocab/digit path.
2. Tiny cross-attending decoder (2 layers d=256, tied trimmed vocab + pointer) (~5-7M). More expressive than 1, handles multi-word answers with autoregressive consistency and conditioning on previous words. Pointer-generator style output at each step. Cost: still 1-5 steps of a small net, orders of magnitude cheaper than the 1.2B head. Choose over #1 only if #1 stalls on multi-word answers. Total ~4M (decoder) + 2M (trimmed vocab) + 0.6M pointer = ~6-7M, close to the core's own size [untested].
3. Program-head (op + operand pointers + calculator + digit formatter) (~1.5-2M). Best generalization for arithmetic (PAL/PoT/NumNet evidence), and it makes copy and compute the same mechanism (pointer to numbers). Weaker for non-numeric word answers, so pair with the pointer head of #1 for those. Risk: needs program supervision (op labels, operand indices) that the current training data may not carry [untested]. This is the most "translating the core's state" in spirit, but it moves reasoning into the executor, which changes what the core is tested on; keep it as a separate experiment from the village model. [suggested]

## One-change-at-a-time suggestion [suggested]
Change 1 only: replace "all prompt words" input with "pointer over reader token states + small gate", keep everything else fixed. Pass mark set in advance: >=80% on never-seen answer words and no drop on seen words. Falsifier: if it stays near 57%, copy alone is not enough and the missing 30 points are computed/multi-token answers, which points to pick 2 or 3. Report per-answer-type accuracy (copied span / copied number / computed number / multi-word).

## Plain-language summary for Ben
A word the talker has never been trained to say is like a word with no key on its keyboard. A pointer lets it instead point at a word already written in the question and copy it, which is why adding one jumped 0% to 57%. The cheapest fix is a pointer plus a small gate, around 2M parameters. If answers that are computed (like 17+5) cause the rest of the gap, have the core choose an operation and two numbers to point at, and let a calculator do the arithmetic. Tiny reasoning models like TRM only get away with tiny output heads because their answers come from a small closed alphabet, which ours do not.
