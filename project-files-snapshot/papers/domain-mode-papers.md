## Choosing and making practice

- **Absolute Zero: Reinforced Self-play Reasoning with Zero Data** (Zhao et al., 2025 (NeurIPS 2025 poster per search)) https://arxiv.org/abs/2505.03335 [shown]
  - Found: One model proposes code-reasoning tasks and then solves them, and a code executor checks both task validity and answers. The proposer is rewarded for learnability: 0 if the solver's mean success is 0, otherwise 1 minus that mean success. Table 1 (Coder-7B variant) average rises 40.2 to 50.4 (+10.2); the 3B and 14B variants gain +5.7 and +13.2. Ablations on the 7B base: removing proposer training drops the average 46.8 to 45.4; removing reference-conditioned proposals drops math 38.4 to 33.1.
  - For us: The learnability reward is computed from the model's own sampled attempts plus the checker, so it needs no teacher or human choice of difficulty. The reference-conditioned ablation suggests anchoring generated problems to seed examples matters more than training the proposer itself.
- **R-Zero: Self-Evolving Reasoning LLM from Zero Data** (Huang, Yu et al., 2025 (arXiv v4 Feb 2026; ICLR 2026 listed in search results)) https://arxiv.org/abs/2508.05004 [suggested]
  - Found: One base model is split into a Challenger and a Solver that co-evolve by RL with no seed tasks or labels. Reported gains for Qwen3-4B-Base are +6.49 on math and +7.54 on general reasoning. The detail that the Challenger's reward comes from the uncertainty of a frozen Solver came from a search summary, not the fetched abstract; the fetched page gives no iteration count or other backbones.
  - For us: Offers a difficulty signal that the model can compute itself (solver uncertainty) to pick the next problem near its edge. It is not a checker, so the outside tool would still be needed to verify answers.
- **Self-Challenging Language Model Agents** (Zhou, Levine, Weston, Li, Sukhbaatar, 2025 (NeurIPS 2025 per search)) https://arxiv.org/abs/2506.01716 [shown]
  - Found: The agent explores tools, then writes its own task as an instruction, a verifier, a reference solution and failure cases (Code-as-Task). A task is kept only if the reference solution passes and the failure cases fail. Only 47.7% of candidates pass the instruction-plus-verifier check, 9.5% after the solution check, and 5.2% with the full filter. Llama-3.1-8B self-improvement raises the tool-use Pass@1 average from 12.0 to 23.5 using 800 self-made tasks; the text says 200 tasks slightly degraded test performance.
  - For us: Shows the yield cost of a self-check: most self-made tasks fail and are discarded, so the generator must over-produce. The 200 versus 800 result suggests a minimum task count before practice starts to help.
- **Language Models Can Teach Themselves to Program Better** (Haluptzok, Bowers, Kalai, 2022 (ICLR 2023 poster per search)) https://arxiv.org/abs/2207.14502 [shown]
  - Found: The model writes programming puzzles, a Python interpreter keeps only the solutions that verify, and the model is fine-tuned on the survivors. The abstract says test accuracy more than doubles on publicly available LMs; the number of models and problems is not in the abstract.
  - For us: The closest early precedent for the whole loop: the model writes checkable problems, a deterministic checker filters them, and the model trains on what survives. Spreadsheet formulas would need an equivalent evaluator as the checker.
- **Multi-task curriculum learning in a complex, visual, hard-exploration domain: Minecraft** (Kanitscheider, Huizinga, Clune et al., 2021 (arXiv; no venue listed)) https://arxiv.org/abs/2106.14876 [shown]
  - Found: Defines learning progress as the change in a task's success probability and uses it to order tasks in a multi-task Minecraft setting (Simon Says). The abstract says the learning-progress curriculum plus a dynamic exploration bonus learns much more efficiently than uniform sampling, but gives no speed-up or success numbers.
  - For us: Gives a basic rule for choosing the next practice task from per-task success history: prefer tasks whose success is changing, not tasks that are always solved or never solved.
- **Teacher-Student Curriculum Learning** (Matiisen, Oliver, Cohen, Schulman, 2017 (arXiv; no venue listed)) https://arxiv.org/abs/1707.00183 [shown]
  - Found: A teacher picks subtasks for a student, favoring tasks where the student's learning curve is steepest, and also returns to tasks whose scores are falling to counter forgetting. The abstract says the automatic curricula match or beat hand-designed ones on decimal addition (LSTM) and Minecraft navigation, and learn about an order of magnitude faster than uniform sampling; it gives no specific numbers.
  - For us: The steepest-slope rule plus a forgetting check is a direct design for the next-practice choice and the avoid-forgetting requirement. It needs only per-task score history from checked tries.
- **MAGELLAN: Metacognitive predictions of learning progress guide autotelic LLM agents in large goal spaces** (Gaven, Carta, Romac, Colas, Lamprier, Sigaud, Oudeyer, 2025 (ICML 2025, PMLR 267)) https://arxiv.org/abs/2502.07709 [shown]
  - Found: The LLM agent learns to predict its own competence and learning progress online, using semantic relations between goals so the predictions generalize to new goals. The abstract reports better LP prediction and goal prioritization in an interactive text environment, and calls it the only method that fully masters a large, evolving goal space; no numbers are given.
  - For us: Directly addresses a model predicting its own learning progress, so the same LM that writes problems can estimate which ones it will learn from next. Caveat: results are qualitative in the abstract.
- **Voyager: An Open-Ended Embodied Agent with Large Language Models** (Wang, Xie, Jiang, Mandlekar, Xiao, Zhu, Fan, Anandkumar, 2023 (arXiv; TMLR 2024 per search)) https://arxiv.org/abs/2305.16291 [shown]
  - Found: GPT-4 proposes an automatic curriculum, stores each verified program in a growing skill library, and refines code using execution errors and self-verification, with no weight updates. The fetched abstract reports 3.3x more unique items, 2.3x longer distances, and tech-tree milestones up to 15.3x faster than prior SOTA; one search summary gave 3.1x for the first figure.
  - For us: The transferable idea is the skill library: store checked solutions as named reusable skills and compose them, which helps avoid forgetting. The curriculum step runs on GPT-4, so a small model would have to take over the proposal role itself.
- **STaR: Bootstrapping Reasoning With Reasoning** (Zelikman, Wu, Mu, Goodman, 2022 (NeurIPS 2022 per search)) https://arxiv.org/abs/2203.14465 [shown]
  - Found: The model writes rationales for many unlabeled questions, retries the failed ones with the correct answer shown (rationalization), fine-tunes on rationales that reached a correct answer, and repeats. The abstract says it significantly beats direct-answer fine-tuning and matches a model about 30 times larger on CommonsenseQA. Arithmetic numbers and the plateau observation come from third-party summaries and were not verified on the paper.
  - For us: Shows the checked-tries-then-fine-tune loop. The catch: rationalization needs the correct answer, so for self-made problems the outside checker must supply an answer key, or that step is unavailable.
- **Mind the Gap: Examining the Self-Improvement Capabilities of Large Language Models** (Song, Zhang, Eisenach, Kakade, Foster, Ghai, 2024 (ICLR 2025)) https://arxiv.org/abs/2412.02674 [shown]
  - Found: Frames self-improvement as generate, self-verify, filter, distill, and argues it is largely governed by a generation-verification gap, which the authors say scales monotonically with pretraining FLOPs in a variant. The abstract gives no round-by-round or saturation numbers; a search summary's claim that gains level off after 2 to 3 rounds was not checked against the paper.
  - For us: Suggests a measurable stop signal: track how the model's self-verification accuracy compares with its generation accuracy, rather than a fixed round count. This is an inference from the framework, not a tested stopping rule.
- **Self-Evolving Curriculum for LLM Reasoning** (Chen, Lu, Kim, Zhang, Tang, Piche, Gontier, Bengio, Kamalloo, 2025 (arXiv v4 Oct 2025; COLM 2026 per search)) https://arxiv.org/abs/2505.14970 [shown]
  - Found: Treats choice of problem category as a non-stationary multi-armed bandit, with reward equal to the absolute policy-gradient advantage as a proxy for learning gain, updated by TD(0). The abstract claims better reasoning and harder out-of-distribution generalization across planning, inductive and math domains. Qwen2.5-3B numbers (AIME 0.075 to 0.10 over random) come from search summaries and were not verified on the page.
  - For us: A ready-made selector that picks the next category from the model's own learning signal, so no human sets the curriculum. It needs an RL training loop to produce the advantage signal, which a small model's loop may not have.
- **Bootstrapping Task Spaces for Self-Improvement (Exploratory Iteration, ExIt)** (Jiang, Lupu, Bachrach, 2025 (TMLR, Feb 2026 per fetched page)) https://arxiv.org/abs/2509.04575 [shown]
  - Found: Creates new task instances by taking intermediate partial histories from the model's own episodes and reusing them as new starting points. The authors call a fixed maximum iteration depth both costly and arbitrary. The abstract reports strong inference-time self-improvement on held-out tasks in math, multi-turn tool use and ML engineering, but gives no numbers and no stopping rule.
  - For us: Shows a way to make new practice problems from the model's own partial attempts, which needs no answer key. The depth argument is a reason to replace a fixed round count with a progress-based stop.

Not found: Looked for: learning-progress curricula, self-generated tasks checked by an executor, Voyager-style curricula with skill libraries, stopping rules tied to the model's own progress. Did not find: (1) any paper with a tested stopping rule based on the model's own progress; the yield-threshold stopping idea in arXiv 2401.06785 appeared only in a search summary and its abstract does not contain it, so it is excluded; (2) any measured result for a model in the 3M to 100M range running the full loop; the smallest reported model here is the 3B Absolute Zero variant (+5.7), and most results are 4B to 8B or larger; (3) the Oudeyer foundational learning-progress papers beyond MAGELLAN, Kanitscheider and TSCL. CURIOUS (arXiv 1810.06284, Colas et al. 2019) and the Portelas et al. survey (arXiv 2003.04664) surfaced in search but were not fetched, so they are not listed; OMNI (arXiv 2306.01711, LLM judgment of interestingness combined with learning progress) also surfaced but was not fetched. (4) Ground truth for the Voyager multiplier is ambiguous (3.3x in the fetched abstract, 3.1x in one summary). Most entries rely on abstracts only, not full PDFs; numbers for STaR arithmetic, SEC small-model results and the Mind the Gap saturation claim are from search summaries and are flagged in the findings. ## Tools, spreadsheets, not forgetting

- **Tool Documentation Enables Zero-Shot Tool-Usage with Large Language Models** (Hsieh et al., 2023 (arXiv 2308.00675)) https://arxiv.org/abs/2308.00675 [shown]
  - Found: Zero-shot prompts containing only a tool's written documentation matched few-shot prompts on existing benchmarks, and on a new dataset with hundreds of tool APIs they beat few-shot prompts without documentation. The abstract gives no numbers; model names and metrics are only in the full paper.
  - For us: Step (a): a model can be pointed at a new tool's docs with no demonstrations and start calling it, which covers first contact with the spreadsheet engine but not learning from practice.
- **Toolformer: Language Models Can Teach Themselves to Use Tools** (Schick et al., 2023 (arXiv 2302.04761)) https://arxiv.org/abs/2302.04761 [shown]
  - Found: The model samples API calls from 2 to 5 demonstrations per tool, keeps a call only if its result lowers the loss on the following text by at least tau_f (1.0; 0.5 for the calculator), then fine-tunes on the kept data. Math results (Table 4): ASDiv 40.4 vs 14.0 for GPT-3 175B and 7.5 for GPT-J; SVAMP 29.4 vs 10.0; MAWPS 44.0 vs 19.8; the calculator was called on 97.9% of math examples.
  - For us: Step (d): the keep-only-if-loss-drops rule is a self-judged way to select which tool-checked traces to train on, with no human labels.
- **Automating String Processing in Spreadsheets using Input-Output Examples** (Gulwani, 2011 (POPL)) https://www.microsoft.com/en-us/research/publication/automating-string-processing-spreadsheets-using-input-output-examples/ [shown]
  - Found: Synthesizes spreadsheet string-transform programs from a few input-output examples in a restricted string language (regex, conditionals, loops), taking a fraction of a second on benchmark tasks. It ranks candidate programs, flags noisy examples, and asks the user for outputs when an input is ambiguous; it shipped as Excel Flash Fill. No accuracy numbers are given on the page.
  - For us: Steps (a) and (b): a program that reproduces every example is a checkable spec, and asking when several readings fit is a model for when the mode should not guess.
- **SpreadsheetCoder: Formula Prediction from Semi-structured Context** (Chen et al., 2021 (ICML; arXiv 2106.15339)) https://arxiv.org/abs/2106.15339 [shown]
  - Found: A BERT-based model that reads header labels and neighbouring rows and columns predicts the next formula, reaching 42.51% top-1 accuracy, which the authors report as a considerable gain over baselines without table context. In a Google Sheets study it helped 82% more users compose formulas than a rule-based feature; the training corpus size is not in the abstract.
  - For us: Step (a): table headers and nearby cells give a self-checkable practice context (predict a formula, then verify it in the engine), but 42.5% top-1 shows formula prediction is far from solved.
- **FLAME: A Small Language Model for Spreadsheet Formulas** (Joshi et al., 2024 (AAAI; arXiv 2301.13779)) https://arxiv.org/abs/2301.13779 [shown]
  - Found: A 60M-parameter transformer trained only on Excel formulas, with about two orders of magnitude less data than the baselines, beat Codex Davinci (175B), Codex Cushman (12B) and CodeT5 (220M) in 10 of 14 settings on formula repair and completion (v2 abstract). Its pretraining corpus is still large, so it does not answer the few-hundred-example question.
  - For us: Sizing: a domain-specialised model at the 60M scale can beat much larger general models, so domain pretraining rather than scale is the lever to test for the 3M to 100M target.
- **SpreadsheetBench: Towards Challenging Real World Spreadsheet Manipulation** (Ma et al., 2024 (NeurIPS Datasets and Benchmarks; arXiv 2406.14991)) https://arxiv.org/abs/2406.14991 [shown]
  - Found: Built from 912 real questions taken from Excel forums; each instruction is graded against several generated test spreadsheets in an online-judge style, and the paper reports a substantial gap between state-of-the-art LLMs and humans in single- and multi-round settings.
  - For us: Step (b): grading each formula on several generated input sheets is a pattern for an outside checker that cannot be passed by hard-coding one answer.
- **Self-Instruct: Aligning Language Models with Self-Generated Instructions** (Wang et al., 2023 (ACL; arXiv 2212.10560)) https://arxiv.org/abs/2212.10560 [shown]
  - Found: GPT-3 generated 52,445 instructions and 82,439 instances, filtered for validity and near-duplicates; tuning on them gave +33.1 ROUGE-L on SuperNI (6.8 to 39.9), 0.9 behind InstructGPT-001 on SuperNI and about 5 points behind on human evaluation. Reported failure modes: only 54% of samples had all fields valid and 58% had a correct output, gains skew toward common tasks, biases can be amplified, and the method works best on large base models.
  - For us: Steps (d) and (e): the paper's own failure list (about half of raw samples wrong, skew, bias) is the drift risk that a checker gate and a fixed old-skill set must catch.
- **STaR: Bootstrapping Reasoning With Reasoning** (Zelikman et al., 2022 (NeurIPS; arXiv 2203.14465)) https://arxiv.org/abs/2203.14465 [shown]
  - Found: A 6B GPT-J model drafts reasoning with 10 few-shot examples, keeps rationales that reach the correct answer, fine-tunes, and repeats; CommonsenseQA reached 72.5% (vs 36.6% few-shot chain-of-thought), and arithmetic reached 89.5% after 16 iterations, while few-shot 2-digit addition was under 1%. The paper states GPT-2 could not bootstrap from few-shot reasoning even on arithmetic.
  - For us: Step (d): the closest precedent for the self-training loop, with the warning that a model with no correct few-shot tries cannot start the loop, which is a gate for the smallest models.
- **AI models collapse when trained on recursively generated data** (Shumailov et al., 2024 (Nature 631, 755-759)) https://www.nature.com/articles/s41586-024-07566-y [shown]
  - Found: Training generative models on unfiltered model output makes the tails of the original distribution disappear over generations, which the authors call model collapse, shown in LLMs, VAEs and Gaussian mixtures and described as irreversible. The abstract gives no numbers; the press-reported example is not used here.
  - For us: Steps (d) and (e): training only on the model's own unchecked outputs erodes rare cases, so the checker's pass/fail must gate what enters training.
- **Mitigating Catastrophic Forgetting in Large Language Models with Self-Synthesized Rehearsal** (Huang et al., 2024 (ACL long; arXiv 2403.01244)) https://arxiv.org/abs/2403.01244 [shown]
  - Found: Learning 5 SuperNI tasks in sequence on Llama-2-7B, backward transfer (forgetting) was -0.79 with self-synthesized rehearsal vs -3.02 with 10% real-data replay and -42.39 with no rehearsal; on 10 tasks it was -1.56 vs -4.03. The replay set is generated by the model and is about 10% of the original size. On Alpaca-7B, MMLU fell from 41.0 to 37.1, so general skills were not fully kept.
  - For us: Step (e): the model can write its own replay set from its own checked answers, which keeps old skills in training without stored human data, though general-skill loss must still be watched.
- **Learning without Forgetting** (Li and Hoiem, 2016 (ECCV; arXiv 1606.09282)) https://arxiv.org/abs/1606.09282 [shown]
  - Found: Before training on a new task, the old network's outputs on the new task's images are recorded and used as soft targets through a distillation loss, so no old-task data is needed. Old-task accuracy fell less than under plain fine-tuning (ImageNet to VOC and ImageNet to CUB, AlexNet), but frozen feature extraction kept old-task accuracy better still. This is a vision result, not a language-model one.
  - For us: Step (e): the old model's own answers on new practice problems can be the target that keeps old skills, a self-distillation form of rehearsal that has not been tested on language models or tool use.
- **Self-Improving Transformers Overcome Easy-to-Hard and Length Generalization Challenges** (Lee et al., 2025 (arXiv 2502.01612)) https://arxiv.org/abs/2502.01612 [shown]
  - Found: Standard transformers that iteratively train on their own correct solutions to harder problems generalize from 10-digit to 100-digit addition without apparent saturation, on arithmetic, string manipulation and maze tasks. Filtering for correct self-generated examples gives exponential out-of-distribution gains across rounds; model sizes and example counts are not in the abstract.
  - For us: Steps (c) and (d): an exact checker plus rounds of own correct solutions, ordered by difficulty, is a working pattern for small transformers on arithmetic, and it suggests the curriculum-by-difficulty rule for choosing what to practise next.

Not found: Searched for a paper where a 3M to 100M model learns a new tool or domain from a few hundred self-made, checked examples, and did not find one. The closest measured work (STaR at 6B, SSR at 7B, Self-Improving Transformers with sizes not stated) uses larger models or more data. No paper tested a rollback gate that undoes training when an old-skill check drops; LwF and SSR cover replay and distillation only. Full texts were not readable for Hsieh et al., SpreadsheetCoder, FLAME and SpreadsheetBench (abstract-level only).
