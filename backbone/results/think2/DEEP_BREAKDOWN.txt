== Notes (Oct 27, 17:35Z; no GPU used)
- shown: 83% of the depth 4-6 slice is three question banks: plan_get 32%, where_before 31%, compare_count 21%.
- shown: compare_count is near ceiling at every depth (about 96%), so it can't show a loop gain.
- shown: where_before is a paraphrase failure, not a depth failure.
  - It scores 18-33% at depth 3, which is a trained depth, and no worse at depth 4-5.
  - Validation asks "Where did X use to be?" (template fb-q.where_before-1). Training only ever asks "Before, where was X?" (template -2). Every bank uses held-out question templates on validation, by design.
  - More plain training makes it worse: depth 3 accuracy goes 41.2 (a) -> 22.1 (aplus) -> 18.2 (aplong).
- shown: plan_get is the only large bank where accuracy falls steeply with depth.
  - aplong scores 88 / 73 / 37 / 11 at depth 2 / 3 / 4 / 5.
  - Its answer is a multi-step action list, scored by exact match.
  - At depth 4, br's best loop count (33.8) is below aplong (37.3).
- shown: the oracle over br's 6 loop counts (78.41) is below the oracle over 3 separately trained plain models (78.93). There is no hidden "pick the right loop count per row" headroom beyond ordinary model-to-model disagreement.
- suggested: Addendum F's "depth 4-6" slice is a poor stand-in for "needs more serial compute". A loop test needs a measure where depth really is the number of serial steps, and where the question wording and answer length don't change with depth.
