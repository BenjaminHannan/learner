# Few-example ruler protocol

Sealed 2026-09-27 22:36 UTC, before source training or any maze panel scoring. This is a new test. It does not change xfer-1 or rsn-358x.

## Question and arms

How many **different** solved maze layouts does a model need before it solves unseen mazes, after practice on sums and Latin grids? Two paired seeds, 0 and 1, have identical examples and panels across four arms: source-trained loop, source-trained plain transformer, fresh loop, and fresh plain transformer. Fresh models start with random weights and receive normal gradient updates. The loop has two shared width-256 blocks, eight heads, 1,645,726 weights, a learned stop head, and a 48-round cap. Plain has eight distinct width-128 blocks, eight heads, 1,619,965 weights, one pass, and no stop head. The size gap is 1.57% relative to the loop. All weights and all inference-accessible persistent coefficients count. Raw replay has 128 stored sums and 128 stored grids per arm. Temporary puzzle states and raw stream examples are reported separately from weights.

## Data

Source training: 6,000 batches of 64 sums (1–4 digits) or 4×4/5×5 Latin grids with the xfer-1 legend format, AdamW 1e-3 with warm-up and cosine decay. No maze appears in source training, validation, learning-rate choice, or stopping-depth choice. Source guard uses 200 fresh 4-digit sums and 200 fresh 5×5 grids, each separately. The model receives tokens and fill slots only, no family ID.

New kind: Wilson uniform-spanning-tree perfect mazes, in the 358m token format, generated by code. A maze answer marks the unique path from start to goal and is checked by the 358m exact checker. Layout SHA-256 is computed from wall cells and size, omitting start/goal and answer. Both panel splits and all support and stream draws have distinct layout hashes, with no cross-overlap. For 7×7 the total possible layouts are limited, so the dev panel has 24 and the holdout has 48; 9×9 and 11×11 each have 300 per split. Every arm uses the same panels. The main score uses the 300-maze 9×9 holdout. The 7×7 and 11×11 panels are secondary. Panel counts and distinct-hash counts must be reported before size-specific conclusions.

The sealed support set has 64 distinct 9×9 layouts per seed, nested at k=1, 4, 16, 64. Each k starts from a clean copy of the starting net, has eight shuffled passes, and uses batches of at most 32. The separate stream branch also starts clean, receives distinct 9×9 mazes in batches of 32, and checks after 256, 1,024, 4,096, 16,384, and 65,536. Supports never appear in the stream. k=0 is scored before adaptation. Each seed's examples are shared across arms.

The loop uses xfer-1's kept maze recipe: four optimizer updates per batch, each with three no-gradient rounds and two gradient rounds, carrying a detached state between updates. There is no stop-head loss during maze adaptation. Plain receives four optimizer updates on the same batch. Plain's maze learning rate is selected from 5e-4, 1e-3, 2e-3 using only 64 steps on extra source puzzles and a separate source dev panel, before viewing maze scores. Loop uses 1e-3. All computation is fp32 CPU with autocast disabled. Record training wall time and optimizer updates.

For each 64-example and 65,536-example branch, score old kinds after maze adaptation. Then sleep exactly 512 optimizer updates, each on 16 replay examples: four sums and four grids sampled from fixed 128-example stores, and eight maze examples sampled from that branch's own examples. One weighted loss combines these shape-homogeneous groups in a single optimizer update. Sleep adds no new maze examples. Score both old kinds and mazes after sleep. Old panels are also scored before adaptation.

## Scores and order

At each rung, record exact `x of 300` on 9×9 holdout, both secondary sizes, mean inference rounds, cap-hit count, and the result at the fixed depth chosen on **source dev** from 8, 16, 32, 48. Learned stop fires from round 3 when its probability exceeds 0.5 and predictions have been unchanged for three rounds. A stop failure is a learned-stop score more than two percentage points below that source-selected fixed depth. Plain has one round.

`F_all` is the unweighted mean of 9×9 accuracy in percentage points over the nine positive rungs (four few plus five stream). `F_few` is the mean over k=1, 4, 16, 64. Report `F_few - cold`, the complete curve per arm and seed, and the report-only k=64 50% line. Report old kinds separately; `D_kind = old_before - old_after_sleep` in percentage points, for each sleep branch. A negative D means improvement.

Run order: (1) selftest and one-step gradient checks; (2) source train and source guard for both seeds and both trained architectures; (3) dev adaptation, with no recipe changes after seeing dev maze scores; (4) apply V1–V3 in PASSMARKS.md; (5) if V3 passes, run the holdout **once**, after all baseline dev branches finish; (6) independent blind recount from raw JSON and marks. If V3 fails, report INCONCLUSIVE and do not run the holdout or retune. Raw JSON and checkpoints stay in this artifact folder. RESULTS.md records the seal commit hash. No result is valid unless this file, both marks files, and the harness were committed before step 1.

## Plug-in contract for the design races

Use `python -B scripts/claude_fewex_bench.py ... --plugin importable_module`; no harness edit is permitted. A plug-in provides `Net(arm)` with `arm`, `weight_count()`, a PyTorch state dict, and `forward(tokens, positions)` returning 48 per-round `[batch,cells,vocab]` cell-logit tensors and 48 `[batch]` stop-logit tensors for a recurrent arm (one cell-logit tensor and an empty stop list for plain). `positions` is the binary fill-slot grid, **not** a kind label. It also provides `Practice(arm, seed, total_steps)` with `.net` and `.step(items)`; `tensors`, `ce_and_exact`, `train_loss`; and optionally `Learner(net, lr)` with `.net`, `.steps`, `.maze_batch(items)`, and `.sleep(mazes, seed, old_replay)`. The baseline learner is used if `Learner` is absent. An optional `infer_rounds(tokens, positions, n)` returns predicted token IDs and stop probabilities with shapes `[batch,n,cells]` and `[batch,n]` to reduce inference memory. Training and inference hooks see puzzle tensors and corrections, never true query answers or family IDs. A design with fast weights must include every persistent coefficient in `weight_count()` and disclose raw memory bytes. Tests A–C keep this harness, data, evaluation, replay, and pass marks fixed. Test A's episodic source training must also be given to its loop control.
