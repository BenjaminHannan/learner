# Equal-practice few-example ruler

Written 2026-09-28 01:59 UTC. This addendum was written **after seeing the old ladder's dev scores** in RESULTS.md (the old ruler was INCONCLUSIVE at V3). The maze holdout remains unopened. This revision is sealed before any score on the new ladder. The old protocol, harness, raw results, and marks stay available for audit; this addendum governs the new run.

**Shown:** the old k=1, 4, 16 and 64 branches received 32, 32, 32 and 64 optimizer updates, respectively, while the old stream received 512 by 4,096 examples and 2,048 by 16,384. **Suggested, untested:** unequal practice may have contributed to the old dev cliff. The new ruler isolates the number of different mazes while holding practice fixed; 2,048 updates is fixed now and will not be tuned after scores.

For each seed, generate one sealed, ordered pool of 16,384 distinct 9×9 Wilson-maze **layouts**, using the existing layout hash (walls and size; endpoints and solution excluded). Exclude every dev and holdout panel layout. Use nested prefixes of that same pool at k=1, 4, 16, 64, 256, 1,024, 4,096 and 16,384. Share each seed's pool and shuffle schedule across all four arms. For every positive rung, start from a clean copy of that arm's starting net and train for **exactly 512 batches of 32 mazes, with four optimizer updates per batch: 2,048 updates**. Cycle through the k examples in shuffled passes. A batch at k<32 repeats layouts to fill 32. Across the 16,384 training slots, each selected layout occurs equally often because every k divides 16,384. Save the cold k=0 score separately. A rung never inherits weights from another rung.

Keep the practised loop, fresh loop, practised plain and fresh plain arms in seeds 0 and 1; reuse the already qualified 12,000-step source checkpoints, without retraining. Keep the preselected learning rates (loop 1e-3; each plain seed's source-only choice), dev and holdout panels, old-kind panels, exact scoring, learned stopping and source-selected fixed-depth check, fp32 CPU, and the existing plug-in interface (`--plugin`, `Net`, `Practice`, optional `Learner` with `maze_batch`). The new harness is `scripts/claude_fewex_eq_bench.py` and reuses the old harness's scoring and learning pieces; the old harness is untouched. Run the unchanged 512-update sleep recipe on separate copies after k=64 and k=16,384; the latter replaces the old 65,536 branch. Score sums and grids before maze training, after each of these two rungs, and after each sleep. The k=64 sleep uses its 64 mazes; k=16,384 sleep uses its 16,384 mazes. Preserve the 128+128 old-example replay allowance, weight/round/cap accounting, and stop-failure rule.

`F_eq` is the unweighted mean of exact 9×9 panel accuracy (percentage points) across the **eight positive rungs**. Report each rung as x of 300 for each arm and seed, with 7×7 and 11×11 secondary counts, fixed-depth control, mean rounds and cap hits. `E50` is the smallest positive rung with at least 150 of 300 on 9×9; report it only, with “not reached” if none. Neither E50 nor the old 50%-at-64 line is a promotion gate. Holdout F_eq and E50 exist only if the dev validity gate passes.

V1 and V2 retain the existing qualified-source checks. **V3 usable ladder:** on the 9×9 **dev** panel, at least one of the four arms in at least one seed must have accuracy strictly above 10% and strictly below 90% on at least **three of the eight positive rungs**. With 300 items this means 31–269 correct at each qualifying rung. If V3 fails, report **INCONCLUSIVE**, stop and leave the holdout unopened. If it passes after all eight dev runs finish, score the holdout once for all arms and seeds, without any recipe or model selection, then obtain a separate blind recount from the raw JSON and marks.

The CPU estimate at seal is based on the prior concurrent runs: six completed old adaptation jobs took 49–77 minutes each with up to 2,048 stream batches plus the small branches. The new run has 4,096 maze batches per job and eight parallel jobs on a 10-core host, with about ten hours until 12:00 UTC. **Suggested:** CPU completion before 12:00 UTC is feasible. If a measured pre-score estimate overturns that, a separate GPU addendum must be committed before the first new maze score, with strict fp32, TF32 disabled, and CPU-equivalent smoke results; at most one rental and $4 may then be used.
