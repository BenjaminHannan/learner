# Research note: input-inferred, shared-core MoE for the next reasoner test

**Status, 2026-09-27:** literature and repository analysis only. This is a recommendation for a *new* experiment after AR1, not an amendment to AR1's pushed `PASSMARKS.md`. No model, preflight, training run, checkpoint, panel, or purchased compute was used for this note. A separate, pushed registration must precede any implementation test or run.

## Recommendation and reason for its rank

**Rank 1 for a next MoE test:** replace each dense block's feedforward activation with a **shared 512-channel core plus top-2 of four 128-channel routed groups**. The router is the *existing* four-way context distribution inferred from the visible request in `auto_model.py`; there is no task ID, additional router, added weight, frozen part, or per-skill copy. The model can combine two feature groups on one request and use a different pair on another. Shared attention, norms, output head, and the core feedforward channels remain live and trainable. Old and new requests get the same model and replay stream.

This is a hypothesis about reducing *where* later gradients overwrite old computations, not a claim that the architecture will meet the difficult marks. Shared attention and the core can still drift. The model may ignore the intended separation, select the same two groups for every input, or learn new mazes too slowly. I rank this above another fully frozen top-1 expert run because the repository has directly shown the latter's capacity and routing failures. I rank it above an isolated top-k neuron activation because it uses the already learned request context and retains a full-width common path. These are judgment calls, not measured outcomes.

## Evidence, in descending relevance

1. **Local, direct:** [e4 results](../claude-rsn358e4-20260927/RESULTS.md) found the oracle-ID dense model (1,646,750 weights) at mean total 470.17/600 and grids5 after C 128/200, while its near-size frozen top-1 expert arm (1,654,446 weights) reached 239.83 total and maze7 3.33/200. [e5](../claude-rsn358e5-20260927/RESULTS.md) improved assignment to the new group but maze7 remained 5.67/200. [e6](../claude-rsn358e6-20260927/RESULTS.md) let shared layers train, raising sums4 after B to 199.17 and maze7 after C to 98.83, while grids5 after C fell to 42.33. These are read dev scores with an oracle `env` input, so they do **not** benchmark label-free routing. They show a real tradeoff among trainable capacity, routing, and shared-path drift in *this* small loop.
2. **Primary papers, indirect:** [Masse et al., PNAS 2018](https://doi.org/10.1073/pnas.1803839115) report that sparse context-dependent activity can reduce sequential interference, especially with stabilization. Their gate receives a task-unique context signal; our visible-request inference is the unproven hard part. [Dai et al., ACL 2024](https://aclanthology.org/2024.acl-long.70/) test small routed experts alongside shared experts in much larger language models. Their result motivates a shared core and recombinable fragments, but cannot predict performance at 1.65M weights or on these three puzzles. [Rosenbaum et al., 2019](https://arxiv.org/abs/1904.12774) analyze the difficulty of learning routing and modules together, including collapse. [Bricken et al., ICLR 2023](https://arxiv.org/html/2303.11934v1) show task-free sparse activation can help continual learning, but also report dead neurons and optimizer-momentum problems; their ablations warn against assuming a simple top-k mask suffices. None of these papers validates this exact recipe.
3. **Inference from the above:** a common path may let sums and mazes borrow grid-era features while routed fragments have less cross-kind gradient overlap. Top-2 selection permits combinations instead of requiring each kind to fit in one narrow expert. This is the mechanism to test; it is not yet observed in this model. The brain analogy is selective use of shared and more specialized circuits. It is a design analogy, not a neuroscience finding about this network.

## Exact one-change implementation

Keep `AutoNet.embed_inputs` and its four trainable 256-dimensional context rows exactly as the common label-free front end in **both** new arms. For each request it already computes `p = softmax(mean(token_embedding + slot_embedding) @ contexts.T / sqrt(256))`; only visible tokens and answer slots enter. The new arm changes each of the two block MLP *forwards* while reusing its existing `Linear(256,1024)`, GELU, and `Linear(1024,256)` weights and biases:

```text
h = GELU(W1 LayerNorm(x) + b1)                    # 1024 channels per cell
J = indices of the largest two entries of p      # one pair per request
g_j = p_j / sum(p_i for i in J), if j in J; else 0
m = [ones(512), 2*g_0 repeated 128, ..., 2*g_3 repeated 128]
MLP(x,p) = W2 (h * m) + b2
```

Use fixed index order to break exact `p` ties. The request's gate is fixed across cells and recurrent rounds; `p` is recalculated only from that request's visible input, with no cross-request memory. Multiplication by `2*g_j` gives each selected group unit scale when `p` is uniform and leaves gradient to selected probabilities. Do not add expert-load losses, warm-start assignments, task-conditioned freezes, weight anchoring, optimizer changes, phase-dependent `k`, or extra router parameters: those would make this more than one candidate change. During training all 1,646,750 parameters still have `requires_grad=True`; zero gradient for a currently inactive routed channel is the mechanism, not a permanently frozen parameter. Implement the partition as slices of the *same* dense MLP tensors so state-dict size and initialization match the dense arm exactly. Shared channels are always active; the other 512 channels form four 128-channel feature groups. These groups are not four model copies and have no task names.

**Budget arithmetic:** each existing 256→1024→256 MLP has `256*1024 + 1024 + 1024*256 + 256 = 525,568` stored parameters. Its 1024 hidden channels are partitioned as `512 + 4*128 = 1024`, with no new tensor. The two MLPs remain `1,051,136` parameters; the other existing parameters remain `595,614`, including the four context rows (`4*256=1,024`), for **1,646,750** in each arm. Active routed width is 256 of 512 per request, plus the 512 shared channels, so 768 of 1024 hidden channels contribute per MLP call. This is a compute/capacity tradeoff, not a total-size advantage.

The old e4 expert recipe had four 256→256→256 paths with top-1 routing, a mostly frozen old network, and an oracle `env` embedding. In contrast, this proposal has a large common MLP path, four **128-wide fragments selected two at a time**, an already present request-derived gate, fully trainable shared attention, and old-kind replay. e4/e5 do not disprove that combination: e5's forced routing still left too little trainable capacity, while e6's trainable shared layers could co-drift away from frozen old experts. But e6 is a serious warning that live shared weights and even replay can break old grids. The proposal may repeat that failure; it does not make old skills immune.

## A clean next experiment, after AR1

Register **one architecture comparison** with fresh paired training seeds and fresh code-generated, never-read mixed panels before construction or testing. Use the same `PuzzleRequest(tokens,slot)` boundary, data generators, exact checker, 48-round stopping rule, optimizer, software/device, batch 64, and 6,500 steps for both arms. Fix the e4 full-replay allocation in **both**: A 2,500 grid steps; B 250 grid + 2,250 sum; C 75 grid + 75 sum + 1,350 maze. This is exactly 400 replay batches (325 grid, 75 sum), inside the user's ±10% bound. It isolates the proposed MLP gate from AR1's replay-timing intervention. AR1's final scores may inform whether this idea is worth registering, but must not change its marks, schedule, panels, or implementation mid-run. Do not reuse historical e4's oracle-ID 470.17 as the paired label-free baseline.

The new registration should retain the user-level hard targets: candidate mean grids5 after C **≥180/200**, every seed **≥160**; candidate mean sums4 after B **≥195/200**; candidate mean maze7 after C **≥ paired dense −10/200**; candidate mean C total **≥ paired dense +40/600**, preferably on at least five of six paired seeds as in AR1. Predeclare verdict precedence and exact six-seed integer-sum arithmetic, and keep new panel predictions unavailable for tuning. If fresh panels or six pairs cannot be afforded, call the work incomplete rather than lowering the bar. This note selects no scores and authorizes no run.

## Unlabeled mixed-test and mechanism checks

At each boundary, shuffle code-generated grids5, sums4, and maze7 into one stream and infer **one request at a time**, blank state each time. The model sees only `tokens`, `slot`, and their native geometry. No `env`, kind, target, `size`, `meta`, phase, panel name, path, batch neighbor, or answer checker reaches the model or gate. Save all per-round predictions and stop probabilities; freeze each selected answer from model outputs before the offline checker consults the hidden kind. Report exact own-stop score; fixed16 and any48 stay diagnostic only. The native geometries and token formats are distinct, so a success supports routing among these visible formats, not general semantic task inference.

Before training, verify parameter count and that gradients reach context rows, shared core, routed groups, attention, and heads on code-generated inputs. Poison hidden `env/size/target/meta` while holding visible fields fixed; outputs, gate probabilities, selected groups, and stops must be unchanged. Reorder, duplicate, and isolate mixed requests; every request's outputs and route must match bitwise. Ensure the old `R.tensors` path cannot be used for inference. After scoring, report group-use frequencies, distinct top-2 pairs, per-kind pair overlap, route changes across A/B/C, and old-grid score change; use hidden kinds for these **offline diagnostics only**. A collapsed route, high old/new group overlap, or B/C route drift would explain failure, not trigger an alternate gate or a rescued score. Include throughput as a report-only cost; slicing a dense MLP may not speed execution.

Key failure modes remain: the learned context distribution can collapse or latch onto easy shape cues; inactive groups can become dead; AdamW momentum and decay can move nominally inactive parameters; the 512 shared channels, attention, norm and stop head can still overwrite grid behavior; 768 active channels may be too little for mazes; and top-2 masks can flip when context vectors drift. Those are reasons for the paired test and route diagnostics, not reasons to revise AR1 or add unregistered fixes.
