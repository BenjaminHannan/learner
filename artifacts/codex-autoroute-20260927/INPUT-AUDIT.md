# Input audit for a label-free, fixed-size three-skill reasoner

**Scope:** read-only source/results audit, 2026-09-27. No code, checkpoint, model or test run was made. This note does not select a plasticity algorithm or register an experiment. The parent owns the one candidate change and must commit/push its PASSMARKS before any model or test run. New work remains only under `artifacts/codex-autoroute-20260927/`.

## What the e4 path actually supplies

The sealed e4 runner imports e3, which imports X (`scripts/claude_rsn358e4_replayall.py:26,50-60`; `scripts/claude_rsn358e3_replay.py:36-37`). X imports MR, T and I2 (`scripts/claude_rsn358e_moe.py:43-48`); MR imports the 358i/G/A2 chain and the maze generator. These imports patch the live R/E modules: G appends a two-row visible legend to each Latin grid (`scripts/claude_rsn358g_run.py:33-44`), MR appends `mazes` to `E.ENVS` and installs maze checking (`scripts/claude_rsn358m_run.py:35-49`), T patches `R.Net`'s state norm/stop head (`scripts/claude_rsn358t_run.py:57-76`), and A2 replaces `R.evaluate` with the v2 stop rule (`scripts/claude_rsn358a2_run.py:27-61`). I2 also patches autocast and training-gradient logging (`scripts/claude_rsn358i2_run.py:39-87`). Import/order provenance matters; citing only e4's wrapper misses these effective methods.

**Direct task-label leak:** `R.tensors` creates `env = E.ENVS.index(items[0].env)` for the *entire batch* (`scripts/claude_rsn358a_run.py:168-173`). `R.Net.embed` adds `self.env(env)` to every token position (`scripts/claude_rsn358a_run.py:71-97`). Thus e4's dense and MoE arms receive an oracle task ID. In a mixed same-shape batch, the first item's hidden `env` silently determines every item's embedding; shuffling can change predictions without changing a request. Passing a dummy ID only at test time creates a train/test input shift. A genuinely label-free baseline and candidate need the **same** task-blind training and inference boundary; historical e4 numbers are context, not an eligible label-free baseline.

**Answer/shape paths:** `R.tensors` also materializes `it.target` as `y` even when evaluation discards it (`scripts/claude_rsn358a_run.py:169-173`; A2 evaluator `:40-48`). The current model is not shown consuming `y`, but a defensible inference interface should not create or pass it. `Item` also carries `size` and `meta`; the checkers use metadata (sum operands, grid puzzle/names, maze start/goal) *after* prediction (`scripts/claude_rsn358a_envs.py:73-78,198-218`; `scripts/claude_rsn358m_maze.py:92-113`). Keep that evaluator-only. The existing batch constructor needs rectangular equal-shaped items; mixed grids5, sums4 and maze7 cannot be directly stacked. Their native visible shapes are **7×5** (grids5 plus legend), **3×5** (sums4), and **7×7** (maze7). There is no padding or attention mask in `R.tensors`/`Block.forward` (`scripts/claude_rsn358a_run.py:62-67,168-173`), and the stop head averages all cells (`scripts/claude_rsn358t_run.py:69-72`), so naive padding would change both reasoning and stopping. A homogeneous-by-shape microbatch or one-request-at-a-time call can preserve the original geometry, but must restore the shuffled output order and must not group by hidden kind.

Visible format still strongly identifies these three distributions: sums use three rows and digit tokens; grids carry symbol tokens plus a legend; mazes use a square wall/start/goal layout whose marker IDs reuse operator tokens (`scripts/claude_rsn358a_envs.py:35-40,64-71`; `scripts/claude_rsn358g_run.py:33-41`; `scripts/claude_rsn358m_maze.py:28-30,70-89`). Learning from *visible puzzle content and geometry* is legitimate label-free inference. A good score on these distinct formats alone does not establish semantic task inference under ambiguous or reformatted inputs. Any explicit shape→kind or token→kind dispatch would be handwritten routing and outside this task.

**Scoring:** e4 `X.score` calls the patched `R.evaluate` separately for each *named* dev panel (`scripts/claude_rsn358e_moe.py:113-120`; `scripts/claude_rsn358a2_run.py:32-61`). That is not a mixed-request harness: shuffle all requests before inference and recover panel totals only afterward. Moreover, e3's wrapper changes active expert groups after score calls for its eq arm (`scripts/claude_rsn358e3_replay.py:110-121`); do not reuse such a mutating score hook as a neutral inference interface. The primary `right` is exact correctness at the model's own v2 stop: first round from zero-based 2 with `q>0.5` and three identical successive predictions, else round 48. `r16` and `any` are report-only; `any` checks all rounds with the oracle and must never select the answer. The evaluator's `E.check` may use hidden `env/meta/target` **only after** the one selected prediction and stop are fixed. Its `grid_of` reshapes by item geometry (`scripts/claude_rsn358a_run.py:222-224`), which is legitimate output interpretation. Neither checker success, a guessed kind, nor a dev score may feed another model round or decide which weights run.

## Minimal legitimate common boundary and tests to preregister

Expose only each request's `tokens`, `slot` (the visible answer-location mask), and their H×W geometry to one small dense model. Never pass `Item.env`, `size`, `target`, `meta`, panel name, phase, checker choice, seed, file path or batch neighbor to its forward path. A conservative exact-budget implementation can instantiate the **unchanged 1,646,750-parameter** small dense network with its four-row env table but feed the **same fixed env index for every training and inference item**. This leaves some counted rows unused; disclose that capacity cost. Both baseline and candidate must use precisely that common input rule, one checkpoint, the same code-generated e4 streams/panels/seeds/replay schedule, and **no** per-skill snapshots or auxiliary learned weights. If the parent instead chooses a different task-blind embedding replacement, account for every parameter and make it common to both arms; the candidate's plasticity mechanism remains its sole experimental difference. The original e4 `R.tensors` must not be called on inference requests because it reads the hidden ID and target.

Predeclare these software controls before a run, using code-generated data only and no blind panels:

1. **Hidden-field poison:** hold `tokens/slot` fixed; permute or falsify `env`, `size`, `target`, `meta`, panel key, phase and request order in evaluator-side records. Predicted tokens and all 48 stop probabilities for the same request must be bit-identical. Score only against the untouched ground truth after inference. Include conflicting first-item `env` values to catch `R.tensors`' batch-wide leak.
2. **Mixed-batch independence:** interleave grids5/sums4/maze7 in random orders. Compare each request alone versus the proposed microbatch path, including first/last positions, duplicate requests and different batch neighbors. Require identical outputs and stops and exactly restored request order. If batching introduces padding, test valid-cell outputs and stop probabilities against unpadded singles; otherwise use no padding. A crash on mixed shapes is an integrity failure, not a score of zero.
3. **Format-cue disclosure:** after registration and before fitting, show the three native H×W and token/slot statistics and a simple *diagnostic* shape-only kind accuracy, never deploy that heuristic as a router. Use fresh code-generated diagnostic probes with shape/slot distractors or matched-size representations, if the same checker remains valid, to measure reliance on superficial cues. If no valid ambiguity probe can be made, narrow the claim to these visibly distinct puzzle formats rather than calling it general task-agnostic routing.
4. **Budget and evaluator separation:** assert exactly 1,646,750 stored model parameters for *each* arm at every phase; count any learned preprocessor/router, cache or adapter toward that total. Assert one live checkpoint, no per-skill state, no model call with labels or `y`, and no `E.check`/oracle feedback before outputs and own-stop round are frozen. Recount fixed16/any as diagnostics, not primary scores. Hash public model inputs before/after hidden-field poisoning and inspect an inference call trace for `env`/`target` use.

Historical e4 dense full-replay used A/B/C steps **2,500/2,500/1,500**, replayed **250 grids batches in B** and **75 grids + 75 sums batches in C**, and used seed-48000 dev panels already read in prior work (`scripts/claude_rsn358e4_replayall.py:7-18,33-48`; `artifacts/claude-rsn358e4-20260927/RESULTS.md`). Its dense after-C mean was **470.17/600** across seeds 3–8, including **128/200 grids5** and **150.33/200 maze7**. e4's frozen equal-size experts learned poorly; e5's forced warm routing did not resolve that; e6's shared training lifted new-skill learning but dropped old grids to **42.33/200** (`artifacts/claude-rsn358e5-20260927/RESULTS.md`; `artifacts/claude-rsn358e6-20260927/RESULTS.md`). These are prior **labeled-input dev** findings, not predictions or a candidate choice for the new label-free run. Ben's goal is a learned reasoner that improves, retains, and carries skill across kinds while beating same-size plain models; a scripted router or extra snapshots would miss that goal (`design/v3/30-modes/ben-goals-2026-09-26.md`). R2 snapshot isolation is an engineering yardstick only and is not build-eligible under this fixed-budget, no-task-ID boundary.
