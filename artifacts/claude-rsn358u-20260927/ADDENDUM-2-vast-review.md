# rsn-358u addendum 2: vast kit fixes after the Thread manager's review (sleep research thread, written 2026-09-27 13:30:52 UTC, before any run)

Additive to ADDENDUM-1-vast.md. Marks, seal and commands are unchanged. The Thread manager reviewed kit 474ed5a32 at 13:27 UTC.
1. **Destroy only after a verified copy.** At the end the rental makes a sha256 manifest of every file in W/. The Mac copies everything back and checks each file against that manifest. It also checks that SEAL-run arrived and that each of the 8 runs has a sealed final.pt whose Mac copy matches, or was recorded by drive.sh as DIED. Only then is the instance destroyed, by its exact id, and confirmed gone. If the check fails twice, the instance is STOPPED instead (GPU billing ends, its disk keeps the files), END says <reason>-STOPPED-NOT-DESTROYED, and the collect job prints FLAG-DIRECTOR. A budget or time stop in the middle of training therefore stops the instance rather than destroying it.
2. **A lost host is stopped, not destroyed** (HOST-FAIL after 20 min with no ssh), so a late network glitch cannot throw away trained nets.
3. **The Mac's ssh key is attached** to each new instance (`vastai attach ssh <id>` with ~/.ssh/id_ed25519.pub, re-sent every 80 s until ssh answers, as rent-rv390b does). The start stops before renting if the key file, the vastai CLI or uv's python 3.12 is missing.
4. The offer search also requires inet_down >= 200.
5. **If the Mac guard dies** (restart), each collect job checks whether it is alive and starts it again from its own copy. There is no timer on the rental itself: stopping an instance from inside needs a vast key on the rental, which this kit never sends.
