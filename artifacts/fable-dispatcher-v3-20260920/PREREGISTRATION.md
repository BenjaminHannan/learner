# Dispatcher v3 — train through three hops, test four to eight (Fable + Ben, written 2026-09-20 ~09:25 EDT before any registered v3 run)

Shown so far. v1 (final-answer reward, 1–2-hop training): 64/64 on 1-hop, 2-hop, held-out 2-hop in 3/3 seeds; three-hop 48/0/15. Call cost 0.01 (registered): padding gone in 3/3 seeds; three-hop 64/0/64 of 64, edited three-hop pairs pass in seeds 0 and 2; seed 1 keeps the operation pointer on position 3 (2,3,3,3) until the cap. Supervised ceiling: 0/64 on three-hop in 3/3 seeds. Ben's point: on minimal 1–2-hop executions several rules are indistinguishable ("next operation = previous operation + 1" vs "two after the asker"; "latest result" vs "first result"), so which one a seed learns is luck.

ONE change versus the call-cost run: the training stream contains 1-, 2- and 3-hop questions (uniform; terminal relation 10 only ever in 1-hop; pairwise-distinct chains; 6-person worlds). Unavoidable companions, disclosed: a new additive world/question builder and new frozen panels (manifest sha256 5c9b4507cf4197beccd933d2cb27b424cbbec13bdbb0f774d8b3bd9ca83867e7; the frozen operator answers 7,296/7,296 chain stages on them, so every failure is the dispatcher's). Kept: architecture (15,522 params), K=16, entropy 0.2->0.02, lr 3e-3, 6,000 updates, call cost 0.01, training cap 4 calls, final-checkpoint-only, seeds 0,1,2 with operator v1-seed-1, incomplete = failed. Time cap 1,700 s per job (wave < 30 min). Evaluation cap 16 calls, no retraining. The build agent's dev budget was not spent, so whether the rl arm learns the 1–3-hop stream at all is itself untested; low final training reward = optimisation failure, read separately from generalisation.

Pass marks, every seed separately, 64 units per cell, 16-person worlds with pairwise-distinct chains: answers >= 58 AND strict path >= 58 (subjects, operations, stop point and every returned token correct; voluntary stop, no cap hit) on every cell k = 1..8, practised and held-out terminal; the six 6-person cells (k = 1..3) at the same marks; k = 5 held-out changed-link / changed-value / irrelevant-edit pairs >= 58 pairs. The unseen-length claim rests on k = 4..8 only. Success on k <= 3 is in-distribution for length (held-out relation still unseen at depth >= 2).
Registered follow-ups on the same seeds, each ONE switch off, run only after the primary is scored: `--no-recent-flag`, `--no-offsets`, `--call-cost 0`.

Predictions: (a) final training reward >= 0.95 in 3/3 seeds; (b) seed 1 now passes three-hop; (c) at least 2 of 3 seeds pass every k = 4..8 cell; (d) about even odds that all three pass everything; (e) if a seed fails, it fails from some length onward (a cliff), not uniformly, and the diagnosis will isolate one component; (f) removing the recent-result flag will hurt more than removing the offsets.
Readings: all pass -> shown on this toy: a learned controller trained to length 3 executes lengths 4–8 with correct paths and voluntary stopping, using a supplied tool interface (canonical query format, entity/operation validation, relative-offset and recent-result features). Not general intelligence; the lookup tool was trained with intermediate labels. Partial -> report the first failing length per seed and the failing component; no claim of length generalisation.
