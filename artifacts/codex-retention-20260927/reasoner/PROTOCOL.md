Practice order: grids (4×4/5×5), then sums (1–4 digits), with an optional maze phase (5×5/7×7) only after both primary grid-to-sum runs finish, if time permits. Each of the first two phases gets exactly 2,500 AdamW steps, batch 64, the original learning-rate/warm-up/cosine schedule and random loop-round schedule. No replay. The next phase begins from a **full trainable clone** of the previous phase's final weights; the previous phase's complete state is frozen and saved.

Independent held-out panels contain 200 grids5 and 200 sums4, generated from seed 92,027 for training seed 27 and 92,028 for training seed 28, separate from the practice seeds. Training inputs identical to held-out inputs are rejected and resampled; rejection counts are logged. The panels are not used for stopping or model selection. Report the existing exact checker at its learned stop point (`right`) and at fixed 16 rounds (`fixed_rounds[16]`). The primary mastery threshold is at least 190/200 on grids5 after phase A and sums4 after phase B, using the model's own stop point. Retention success requires grids5 at least 190/200 via the grid snapshot after phase B, and exact equality of its weights and predictions before and after B. The newest mutable B model is also scored on grids5. Score all planned panels regardless of result. If the mastery or retention thresholds fail, report that candidly.

Routing uses the caller-supplied `Item.env` identity, already represented in the model input. This is task-aware serving with one full model snapshot per skill, so total storage and serving capacity grow linearly with skills; it is not a learned router or a same-size task-agnostic solution. The registry must reject unknown identities. After serialization and restart, issue alternating grid, sum, grid requests and verify exact equality of actual predicted tokens and stop probabilities, along with the frozen grid panel score. CPU versus MPS throughput is benchmarked first using the same model/training step. The faster feasible device runs the experiment. Maze phase is contingent on the measured runtime, targeting a total of roughly 45 minutes.
