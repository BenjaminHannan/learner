# Independent saved-checkpoint recount — software verification

**Status:** registered only when this exact file is committed before `recount.py` runs. The parent owns that commit and execution after R2 seeds 31 and 32 finish. This verifier does no training and is not a new scientific experiment or a regrade of R1/R2.

Read only the four registered result/checkpoint pairs: R1 seeds **29, 30** from `reasoner/seed29`, `reasoner/seed30`; R2 seeds **31, 32** from `r2/seed31`, `r2/seed32`. Recreate the original 200 grids5 and 200 sums4 panels for each seed from `92000+seed` using the original code generators. Use same-device **MPS only**, Torch eval/inference mode, batch 50, 48 rounds. If MPS or an input is unavailable, stop as **INCOMPLETE**, never count a scientific failure.

Compute each item's outcome directly from canonical `loop_rounds`, `claude_rsn358a2_run.stop_round`, `claude_rsn358a_envs.check`, and canonical grid reconstruction. Do **not** call R1's `score` or `exact_outcomes`. Recount both A and B snapshots on both panels. Record own-stop correctness, fixed-round-16 correctness, any-round correctness, and stop round per item, in panel order, with no puzzle text. For grids compare A versus the newest B model and A versus the known-ID routed A snapshot; keep lost and gained separate. Re-evaluate grid/sum/grid from saved snapshots and after independent reload, including token and stop-probability equality on the first 16 items. Reject an unknown task ID in the verifier's typed route.

Treat a checkpoint path logged by the original host as provenance: require its final artifact-relative suffix to match the registered seed/kind, record that original path, and load the current checkout's canonical artifact file. Record each loaded file's SHA256 and require it to remain stable across reloads. Check snapshot metadata (`arm=dense`, `size=small`, correct seed/kind/step), exact model state keys, **1,646,750** parameters per snapshot, state SHA256 as logged in each phase, checkpoint file byte size as logged, and total two-snapshot bytes/parameters. Compare every recomputed score field and itemwise count with the matching rows in `result.json`, including R1/R2 reported isolation and restart controls. Recompute R1 and R2 seed criteria and their aggregate classifications from their own registered marks. R1 remains **INCONCLUSIVE** because seed 29's A score is 174/200, even if verifier PASSes or R2 later PASSes. R2's result is never used to alter R1.

Statically follow import-time local Python imports recursively from the canonical X model, A2 scorer and R1 runner, including X's MR/T/I2 imports and their monkey-patch chain; exclude function bodies and `__main__` blocks that are not imported into the evaluator. Compare every discovered local source byte-for-byte against each run's recorded `software_head`. Check the R2 runner separately for R2 runs and against registration commit `57d6f5cfdb7a6416e1c41beb52ac9c778dcd95a7`, and compare the committed R2 marks. Record source hashes and any mismatch. Record the verifier's Torch version and require equality to every run's logged Torch version before loading a model. The result should distinguish observed checkpoint scores from the theoretical identity of serving the same immutable A checkpoint: this test cannot reconstruct an unsaved historical in-memory state or prove arbitrary task routing. It verifies saved artifacts, same-device behavior and report consistency.

## Verification mark and launch guard

**VERIFIER PASS** only if all four inputs are complete and every available score, metadata, hash, byte/count, itemwise transition, typed-route and classification comparison matches. **VERIFIER FAIL** is any mismatch; write `recount.json` with per-check booleans, integer counts, itemwise arrays and mismatch messages, then exit nonzero. This is a finding about reproducibility or reporting, not a change to the registered experiment's verdict. **INCOMPLETE** covers unavailable MPS or missing/unfinished inputs.

The runner requires `--passmarks-sha` naming a full commit whose `verify/PASSMARKS.md` bytes exactly match this file, before any model import/call or output creation. Immediately after that gate it creates only a fresh `verify/recount-<commit-prefix>/` directory, refuses overwrite, and writes `RUN-NOTE.md` with `date -u`, machine, PID, software HEAD, committed marks SHA and exact command. It records its own source hash in `recount.json`, updates that JSON after each completed seed, and ends with UTC end time and wall time. On a post-gate exception it retains completed-seed recounts, writes `CRASH.txt` with the traceback, and records final status in `recount.json`. The parent must not launch while R2 is running. No PC, watcher, cloud, download, spending, keys, training, or new dataset is needed.
