# Independent read-only audit: request-scoped retention serving

**Verdict: INCONCLUSIVE for live MiniCPM5-1B.** The exact original base is absent locally. I inspected `implementation/retention.py`, `chat/retention_chat.py`, the preregistered C1 marks, the existing tests, and the original LoRA definition. This review changes no existing file and makes no dl-9 or learned-routing claim.

## Material findings

1. **C1's real-model parity check is not implemented by the live CLI.** `PASSMARKS.md` requires base logits and greedy output compared bit-for-bit with an independently loaded unwrapped base, and adapter-on output compared with the original unwrapped LoRA. `chat/retention_chat.py:153-175` generates base, always-on, and scoped replies through the *same wrapped model* and compares decoded text. A shared wrapper, load, tokenizer, or configuration error can affect all three paths without being detected; different logits can also decode to the same reply. The CLI can show internal route agreement, but cannot by itself support C1's real-model PASS. Keep the live result INCONCLUSIVE until those independent references, matching precision/device and prefill-logit comparisons, are added to a later authorized run.

2. **The claimed base revision is only a directory-name check.** `chat/retention_chat.py:80-88` accepts any directory named `87179e5c1f455ef22e6223592d2d61351b525bfc` with `config.json`, and `:150` records that name as `base_revision`. Neither weights nor tokenizer, chat template, config contents, or custom model code are fingerprinted. `RequestScopedAdapter.base_digest()` (`implementation/retention.py:122-132`) hashes model tensors and buffers, but not those other inputs and is only compared within the same loaded process. Pin and verify the actual snapshot contents before calling a later result the original base. The saved-adapter SHA check at `chat/retention_chat.py:103-115` does not close this gap.

3. **MPS precision differs from the saved adapters' original base.** The CLI loads `float16` on MPS and `float32` on CPU (`chat/retention_chat.py:86-88`); dl-5 used a `bfloat16` base. The scoped and control paths within one CLI run share precision, so this does not itself prove broken bypass. It does mean their answers and loss counts are not directly interchangeable with dl-5's bfloat16 measurements. A later result must record the actual dtype and separate internal route parity from historical-score comparison.

## Scope, cache, and state assessment

- **No direct base-bypass flaw found in the intended LoRA path.** `_ScopedLinear.forward` returns `self.base(x)` before touching A/B, dropout, or scale when off (`implementation/retention.py:49-53`). It retains the original B2 arithmetic when on. The constructor rejects a trainable non-adapter parameter, including the wrapped base, and preserves A/B state-dict key names (`:65-90`). The original `claude_blurt2.add_lora` freezes base parameters before inserting the LoRA layers. The code-only tests cover poisoned inactive A/B, key parity, save/reload, and a trainable shared parameter; the absent 1B is still untested.
- **Request isolation is sound within its documented synchronous boundary.** `ContextVar` routes are nested/restored via tokens, and the lease invalidates deferred work after scope exit (`implementation/retention.py:24-36,92-120`). `generate()` refuses caller-supplied `past_key_values` and `cache`, establishes one route around the whole synchronous decode, and `chat/retention_chat.py:118-128` tokenizes afresh for each path. This guard is for the supported entry point; arbitrary external helpers or model-specific mutable cache state are outside the proof. Do not claim safety if a caller bypasses it or passes precomputed state through another API.
- **Published adapter weights are not version-isolated during replacement.** `chat/retention_chat.py:103-115,153-160` loads s8 then s9 into the same wrapped model in a sequential CLI, which is safe for that serial loop. `RequestScopedAdapter` itself has no lock or immutable snapshot for A/B; an external service that calls `load_state_dict` or trains the published adapter while another request decodes could mix versions despite correct `ContextVar` routing. Keep model/adapter versions immutable for the full request, or serialize replacement. This is a deployment constraint, not a demonstrated defect in the current single-threaded CLI.
- **The manifest is caller-trusted.** `read_manifest` checks row shape and hashes the bytes but does not establish that rows are the complete 300-item panel or fresh, disjoint grid states (`chat/retention_chat.py:50-65`). The external `domain_id` makes routing deterministic and tests bypass mechanics; it cannot establish learned-gate recall, false-positive rate, or guarantees for arbitrary prompts. Any future report must verify manifest provenance and scope claims accordingly.

No live 1B run or fresh test was performed for this audit. C1 remains **INCONCLUSIVE for real 1B serving**; the code-only parity findings remain software-only.

## Repair resolution — 2026-09-27

The findings above describe the earlier runner. The repaired `chat/retention_chat.py` now captures compact references from the unwrapped base and the original unwrapped B2 LoRA before installing `RequestScopedAdapter`. It compares scoped off/on/off output token IDs, SHA256 hashes of the **entire prefill logits tensor**, and hashes for six cached decode-score tensors under the same selected device and dtype. Each seed uses one model at a time. It defaults to `bfloat16`, records any explicitly selected dtype, requires exact saved A/B keys, and refuses existing summary or reply-sidecar paths.

The runner also requires a separately supplied file-hash manifest already committed at HEAD. It checks every local snapshot file, including weights, configuration and tokenizer files, plus the loaded model/tokenizer and serving entry-point code. These checks establish consistency with **trusted, reviewed expected hashes** in that manifest. They do **not independently authenticate** that those hashes came from the named Hugging Face revision, nor prove behavior if files, tokenizer state, configuration, dependencies or in-memory model state change after verification. The external domain ID still tests bypass mechanics only; it is not learned routing.
