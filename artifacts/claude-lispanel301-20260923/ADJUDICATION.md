# Adjudication: p301-094

Sided with label_B. The turn states two facts about the speaker: one attribute with no matching name in relation-names.txt, and a birthday. The key listed only the birthday. The frame spec says `facts` lists every fact the turn mentions, including ones that must not be saved, and note 2 in frame-spec-notes-301 says a relation not in the table gets `rel: "other"`. So the unlisted attribute belongs in the frame as an ASSERT fact with rel "other" and the value exactly as typed. Deciding what gets saved is the write compiler's job, not the listener's. With this frame the compiler saves nothing for the turn: the "other" fact fails its relation-in-table check, which blocks the whole turn, so both facts go to ask-back. The key's frame would have saved the birthday.
