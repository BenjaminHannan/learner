EXP 261 BRIEF: the ear with a checker. A second model checks every fact the ear wants to save, and this replaces the margin gate. The director wrote this on 2026-09-22 at 20:05. OPUS-RULES.txt (same folder) applies in full.

This is the one diagnosis-driven follow-up to 257's registered FAIL. 257 stays FAIL.

Why: the director's review of 257 (category level; the 257 panel is TEST-ONLY for you, so never open it)
- The v4.1 ear alone reads well. With the brake and no gate, it gets 98 of 112 facts exactly right (87.5%) and 39 of 40 questions.
- It also makes 12 wrong saves, and every one of them is confident. The director swept the gate threshold tau from 0 to 9.3 on 257's own predictions:
  - wrong saves only fall 12 → 8 (tau 2) → 4 (tau 9.3), while recall falls 87.5% → 69.6%;
  - no tau reaches the bar of at most 1 wrong save.
- The margin gate holds back frames the ear is ~99% sure of. For example, the top reading has probability 0.995 and the rival 0.003. So the gate mostly costs right facts.
- The confident wrong saves are semantic mistakes that a reader who understands the sentence would not make:
  - a pretend turn ("let's say …") saved as fact;
  - a goal ("training to be …") saved as a current job;
  - "A's husband is B and he works as …" with the job given to A;
  - a lowercase check-question ("… right", "so …") saved;
  - "our …" giving the subject "Our" instead of the speaker.
- Every new kind of example we add to the training data fixes some old kinds, and a fresh panel then shows new ones. A checker that actually reads the sentence should catch all these kinds at once, instead of one data class per kind. (This is Ben's "dreamer + checker" idea: the ear proposes, a second model checks.)

The one change: replace 257's margin gate with an entailment checker, plus one mechanical fix, the speaker canonicaliser.
1. Speaker canonicaliser. For subjects of TEACH and ASK frames, map these words to "me", ignoring case, before anything else: i, me, my, myself, mine, we, us, our, ours, ourselves. Nothing else changes. (Ben's rule: there is one user, so "our dog" is the user's dog.)
2. Checker. For every TEACH frame the brake keeps:
   a. Render a claim sentence H with one fixed template: "<S>'s <relation words> is <V>." <relation words> is the table v2 name with underscores turned into spaces; "me" becomes "the speaker". You may add a short fixed list of nicer templates (for example "<S> lives in <V>." for city, or "<S> works as <V>." for job), written before the seal from the relation table. Never write templates from any panel.
   b. Ask Qwen3.8-27B one fixed yes/no question at temperature 0. It is already on BensPC; see the llama-server notes below. Write the question before the seal. It must say:
      - "Message from the speaker: «<turn>»";
      - "Claim: <H>";
      - "Does the message state this claim as a real, current fact that the speaker believes?";
      - answer NO if the claim is only asked about or checked (including "…, right" and a "so …" check without "?"), pretend or hypothetical ("let's say", "imagine", "suppose", "what if"), a plan, goal or wish ("training to be", "wants to", "is going to"), denied, or about a different person than the message says;
      - "Answer with one word: YES or NO."
      Turn off thinking mode. Read p(YES) from the token logprobs (normalise YES against NO).
   c. Save the frame if p(YES) ≥ theta. Otherwise hold it back as UNSURE, exactly where 257's gate put its UNSURE frames.
   d. The checker only keeps or holds back. It never adds, edits or reorders a frame. ASK frames are not checked (questions never write).
3. theta. Pick it on dev before the seal with 257's sealed tau rule: the most recall at ≤ 1% wrong saves on dev; otherwise the lowest wrong rate, with ties going to the smallest theta. Write the theta curve into PASSMARKS.
   Dev is 257's dev split with the v4.1 predictions (artifacts/claude-smolear257-20260922/dev/), plus a NEW checker dev set that you write yourself, in your own wording:
   - at least 30 turns for each of: pretend/hypothetical, plans/goals, check-questions without "?", "A's R is B and he/she …", and "our"/"we" owners;
   - plus 60 plain true facts, so that false rejections show.
   Qwen may write practice sentences. Never read, copy or rebuild items from any TEST-ONLY panel (earpanel235, earpanel235b, earpanel257, earpanel261); you know 257's failures only at the category level written here.

# 261b: decision notes (director, 2026-09-23 01:45 UTC)

## Ruling 1: a narrower relation counts as right for a broader gold relation (scorer rule, from the relation table)
- Relation table v1 already says `pet` has `narrower: ["dog", "cat"]`, and `dog` and `cat` are their own relations.
- The 261 scorer only accepted `relation_aliases`, so a save whose relation was the species word was counted as a WRONG save against gold `pet`.
- Director review of 261's wrong saves (category level): 6 of 9 were this kind: right owner, right name, species relation.
- Rule from now on: a TEACH frame whose relation is listed in the gold relation's `narrower` list (table v1/v2) counts as a hit, not a wrong save. Panel specs from 261b on also put the species word used in the turn into `relation_aliases` for pet gold.
- 261's registered FAIL stays FAIL. This rule is not applied to 261 retroactively.
- Open check: "What is my pet?" must find facts stored as dog/cat. This is a separate question, not part of 261b.

## Ruling 2: 261's one follow-up is 261b, the mixed-case span guard
- The real meaning errors left in 261 (category level): 2 typo leaks, where a lowercase typo word got glued onto a capitalised name inside a stored subject or value, and 1 "so ..." check with no "?". The checker approved all 3.
- 261b adds one mechanical rule after the checker. A TEACH frame whose subject or value mixes a Capitalised word with a lowercase non-particle word is held back as UNSURE. Particles are de, da, van, von, der, la, le, del, di, bin and al. All-lowercase spans (lowercase chat) and all-capitalised spans pass. Whole relation-word values such as jobs are exempt, by table value_kind.
- Registered on a fresh blind panel, earpanel261b. earpanel261 was read by the director for this diagnosis, so it is spent for 261b.

EAR PANEL 261b SPEC. The director wrote this on 2026-09-23 (copied from the earpanel261 spec with the changes marked NEW). It is shared by the blind panel writer and the exp 261b builder.

Folder: artifacts/claude-earpanel261b-20260923/
- panel.jsonl (150 lines)
- make_panel.py: holds the items by hand, writes panel.jsonl deterministically, and runs the self-checks
- README.md (TEST-ONLY; category level only)
- SEAL.sha256.txt, made from the repo root with:
  shasum -a 256 artifacts/claude-earpanel261b-20260923/panel.jsonl artifacts/claude-earpanel261b-20260923/make_panel.py > artifacts/claude-earpanel261b-20260923/SEAL.sha256.txt

Schema (exactly as panel 257)
- Each line is exactly {id, family, turn, gold, clear, notes}.
  - id: "e261b-001" … "e261b-150", in family-block order.
  - turn: one user chat turn.
  - gold: a list of frames. [] means nothing may be saved.
  - clear: bool. false when a second reading is also defensible.
  - notes: a string holding the risk tags (R1 … R12, "lower", "typo", "noq").
- TEACH frame: exactly {act: "TEACH", subject, relation, relation_aliases, value}.
- ASK frame: exactly {act: "ASK", subject, relation, chain, relation_aliases, chain_aliases}.
  - chain: null for one hop. For two hops it is [first relation, second relation]; relation is then the second one and subject is the start person.
  - chain_aliases: null for one hop. For two hops it is [aliases of hop 1, aliases of hop 2]; the second list equals relation_aliases.
- subject and value: the exact words from the turn, in the same case. "me" stands for the speaker, which includes "our"/"we"/"us" owners (Ben's rule: there is one user).
- NEW: for a pet, relation is "pet" and relation_aliases must include the species word the turn uses (dog, cat, rabbit ...) as well as pet, animal and companion.
- relation: a plain English snake_case name (city, employer, workplace, job, boss, sister, spouse, language, hometown, place_of_birth, pet, school, neighbour …). relation_aliases lists accepted alternatives. Keep one fixed alias list per relation in the generator.

Families and exact counts (150)
- plain_teach 25
- varied_teach 30
- full_names 15
- questions 25
- chain_questions 15
- no_save 25
- corrections 15

Risk quotas. Tag each item in notes. All wordings are new; never copy an example from this spec word for word.
- R1, pronoun reference across clauses: at least 8 turns across varied_teach and full_names. Gold subjects are the resolved names.
- R2, questions shaped like statements: at least 8 turns in no_save with gold [].
  - Include tag questions ("…, right", "…, isn't it") and "so …" checks.
  - At least 5 have NO question mark (lowercase chat style).
  - Plus at least 3 statements that contain a question word but state a fact (TEACH gold, in varied_teach).
- R3, the verb decides the relation, not a noun in the value: at least 6 items. Teaching or coaching at a School, College or Club means workplace; studying at one means school.
- R4, compound family relations (step-, half-, -in-law, grand-, great-): at least 6 items across families. Gold keeps the full relation.
- R5, everyday relations beyond the core list (housemates, instruments, favourite foods or sports, hobbies, teachers, doctors, neighbours): at least 8 items across families.
- R6, two-hop questions whose first hop is a relative: at least 5 of the chain_questions.
- R7, first-person plural owners ("our", "we", "us" + a relative, pet, home, workplace or neighbour): at least 6 items across the teach families. The gold subject is "me".
- R8, plans, goals and wishes ("training to be", "wants to be", "is hoping to", "is going to", "plans to move to", "will start at"): at least 6 items.
  - At least 3 are in varied_teach, where another clause of the same turn states a real current fact. Only that fact is gold.
  - At least 3 are in no_save, where the whole turn is a plan or wish (gold []).
- R9, pretend and hypothetical turns ("let's say", "imagine", "suppose", "pretend", "what if", "say that"): at least 5 in no_save, with gold [].
- R10, plural relatives naming two people ("my two sisters, A and B, …", "both my cousins, A and B, …"): at least 4 items. Gold has one frame per person for the relation, plus any other stated fact for each person.
- R11, appositive relatives ("my cousin A lives in B", "A's friend B works at C"): at least 6 items. Gold holds the relative frame AND the other fact.
- R12, a pronoun after "A's R is B and he/she …" where the pronoun refers to B: at least 4 items. The later fact's gold subject is B, never A.

The rest spreads over:
- plain facts, pets, jobs, languages and birthplaces;
- full names of 2–4 words;
- corrections, which hold only the new value (a negated old value is never in gold);
- lowercase and typo'd chat: at least 15 turns in all.
- NEW, R13 typo next to a name: at least 8 teach items where a misspelt everyday word (not a name) sits right next to a name ("livs", "werks", "bron"). Gold holds the clean name spans only.
- NEW, R14 all-lowercase names: at least 6 teach items typed all lowercase with lowercase names; gold keeps the lowercase spans.
questions and chain_questions include at least 5 lowercase or no-"?" questions.

"""Exp 235b -- choose tau on the OWN dev set only (before the seal; the 235b panel is not opened).

Rule (from the brief): the tau with the most exact-TEACH recall subject to
wrong-save rate <= 1 %. Ties -> the smallest tau.
  recall          = saved TEACH frames matching a gold TEACH frame / all gold TEACH frames (all dev rows)
  wrong-save rate = saved TEACH frames matching no gold frame of that row / number of
                    non-question dev rows (rows whose gold has no ASK frame)
Grid: 0.0 .. 15.0 step 0.1.

python claude_smolear235b_tau.py --dev DEV.jsonl --preds PREDS.json --out TAU.json

def gold_frames(lines):
    out = []
    for f in E.parse_frames("\n".join(lines)):
        if f["act"] == "TEACH":
            rs = f["relation"].split("/")
            out.append(dict(act="TEACH", subject=f["subject"], relation=[rs[0]], value=f["value"],
                            aliases=[rs[1:]]))
        elif f["act"] == "ASK":
            out.append(dict(act="ASK", subject=f["subject"], relation=f["relation"],
                            aliases=[[] for _ in f["relation"]]))
    return out


def evaluate(rows, preds, tau):
    agg = {}
    for row in rows:
        p = preds[row["id"]]
        gold = gold_frames(row["frames"])
        g = B.gate(row["turn"], p["raw"], p["greedy_lp"], [tuple(x) for x in p["beams"]], tau)
        arms = {"A_raw": [f for f in E.parse_frames(p["raw"]) if f["act"] in ("TEACH", "ASK")],
                "A_brake": g["kept_brake"], "A": g["saved"]}
        nonq = not any(f["act"] == "ASK" for f in gold)
        for arm, fr in arms.items():
            th, tx, tn = S.match(fr, gold, "TEACH")
            for key in ("all", row["tag"]):
                a = agg.setdefault(arm, {}).setdefault(key, dict(rows=0, nonq=0, gold=0, hit=0, wrong=0,
                                                                  unsure=0, guard=0))
                a["rows"] += 1
                a["nonq"] += nonq
                a["gold"] += tn
                a["hit"] += th
                a["wrong"] += len(tx)
                if arm == "A":
                    a["unsure"] += len(g["unsure"])
                    a["guard"] += len(g["guard"])
    for arm in agg.values():
        for a in arm.values():
            a["recall"] = a["hit"] / a["gold"] if a["gold"] else None
            a["wrong_rate"] = a["wrong"] / a["nonq"] if a["nonq"] else None
    return agg
