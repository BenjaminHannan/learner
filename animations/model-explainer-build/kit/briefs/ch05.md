# ch05 — The calculator and the call writer (kicker "Part 5 of 14", title "Asking the calculator for help", accent call)
Target: 11-14 scenes, 240-300 s. Use coral for the call writer and slate for the calculator.

Must cover:
1. Where we are; why a calculator: arithmetic is exact in code, slow to learn in a network; the rule: hand-written code may run only as an outside tool the model CHOOSES to call.
2. The call writer: after each round it reads control vector 0 and either writes a call or writes nothing ("no call"). 8 operations: add, sub, mul, div, mod, min, max, cmp. A call is plain text like `sub 12 5`. Show all eight with a one-line meaning each (look up exact semantics, e.g. div only when it divides evenly, in tool.py behaviour described in MARKS-D0-T1 / D0 results; if you cannot verify a meaning, show the name only).
3. How numbers get into the call: the copy trick. A learned pointer picks the last digit of a number in the text; the code copies letters one step left until a learned stop-copy head says stop (or the string starts); used for 98% of written operands and 91.5% of answers on every T1SDR seed (FINISHED sec. 4 table). A number NOT in the text is written letter by letter in 21 slots, last digit first.
4. The calculator: plain Python, 0 learned numbers; takes the call as text, replies as text, or `?` if invalid. The reply line `sub 12 5 = 7` is read by the letter window and added to the thinker's notes; the question is not re-read.
5. Timing today vs B3: in T1SDR/H1, first call follows round 2, call k follows round k+1, up to call 7 after round 8; rounds 9-32 cannot call. B3 group 1 (built, never run): a call may follow any round from 2 to 32, tape holds 16 calls, and in training a quarter of rows put 0-2 think-only rounds before each call. The project owner chose "any time".
6. Evidence the calculator-outside design works (tested): T1SDR matched the model with the calculator inside over 6 copies: pooled-5 +0.62 (range of likely error -0.23 to +1.46), chain-5 99.6-99.8 (mean 99.72; the older model 99.4-99.7); with the calculator switched off, program questions score 0.0 (MARKS-D0-T1 Record 13). Swap test (the calculator's ops are swapped; do the answers follow?): holds on 5 of 6 copies; the 6th copy's checkpoint was lost so it is unscored. The leak mark was missed as sealed and cleared by the project owner. Present these exactly.
7. What is still hand-written (brown chips): the op word picked from a fixed list of 8 (so a tool added later could not be called); the number finder; span copy rules; "last letter first" writing. Group 2 (built as code, never run) makes the call writer write the WHOLE call as letters, operation name included, so a new tool can be called (domain mode needs this: ch12).
8. Honest picture of status: calculator outside = tested at 3M only; Gemma + outside calculator together = never run; any-round calls = never run.
9. Recap.
