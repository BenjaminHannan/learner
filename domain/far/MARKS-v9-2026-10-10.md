## The one change (v9, from v8)

Before day 1 the model calls one new outside tool, the swap tool (`domain/far/widen.py`, the same for every domain), on its
help page:
- ring 1 = the help page;
- ring 2 = every single swap of a well-formed piece of a help example (whole tokens, brackets balanced) for a well-formed
  piece of any help example, kept when the domain's tool runs it within the model's caps (the same checks a practice
  problem passes), one example per digit shape;
- ring 3 = up to 3,000 single swaps on ring-2 examples (the run's own random stream), kept by the same rules.
Each new example keeps the kind of the help example it was made from. Each practice and quiz problem then picks a ring
evenly among the rings that hold its kind, an example evenly within it, and is varied and checked exactly as before
(addendum A10). New constants, the same for every domain: `widen: crossover`, `widen_rings: 3`, `widen_ring_max: 3000`.
Everything else is v8: per-tool add-on (rank 8), the model's own switch, all other constants unchanged.

Autonomy level: as A11, Level 1. The swap tool is a fixed, domain-free outside tool called at a fixed point; it reads only
the help page and the domain's tool; no panel, DEV row or person step. The model's own scores still pick the practice mix
and the stop night.

Disclosed: chosen after seeing what the far split asks for and the diagnosis above. So v9 is scored on a **fresh panel
draw**, `panel/sheet.v3.jsonl` (sha256 16d7f872f82403cb330f285017bdca710e33cc088a96c1320ebc40db9b60ae17) and
`panel/rpn.v3.jsonl` (sha256 a03d4b30a8b13b6e12b793b01e03a1ee4dfed264ff13cb7475970a84117d50f5), seeds 91021 and 91022, same
