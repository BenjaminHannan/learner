## Fixes applied before any LT-2 row is used (from the panel)

## Row format (all rungs; format v2 as in LT-1)
Prompt = context sentences + question sentence + options suffix " (a/b/c)" (rows.options_suffix(id): per-row hash-shuffled order of
true/false/unknown), <= 208 chars including the suffix, only chars of the checkpoint vocab. Answer in {true, false, unknown}, labels exactly
balanced in thirds per file (and per depth for R4/R5). Words from the LT-1 lexicon (149 entities, 1,407 predicate words); no
(entity, predicate) literal of the query appears in a distractor. Each row carries meta.program so an independent solver can verify it.
130,000 train rows per rung; eval files 1,200 rows each. The labels are re-derived from the TEXT by an independent solver for every
row of every file before use (must agree on 100%).

| rung | context | question | label rule | eval files |
|---|---|---|---|---|

## Training recipe (the LT-1 marked recipe, unchanged)
Continue the parent for at most 8,000 updates: 25% of every batch from the rung's train file, 75% from the sk200k curriculum, lr 1e-4
constant after 100 warm-up updates, batch 64, AdamW as the original, grad clip as the original, mix_frac 0.25; course seed s in {1, 2}.
Eval on the full dev (and wording) files every 250 updates on GPU; on CPU a 400-row prefix every 250 updates plus a full-file eval at
the stop point. A run STOPS EARLY when its marks (below) are met at two consecutive evals and the full-file eval confirms them.

## Marks (fixed now)
Run passes rung r when, at some eval at or before 8,000 updates, ALL of: dev accuracy >= 90% (R5: the LT-1 G-PASS bars instead: gate depth 0-1 >= 80%,
depth 2 >= 65%, depth 3 >= 55%); wording accuracy >= 80% where the rung has one (R4: gate-d1 >= 75%); model >= count baseline + 25 points.
- Rung PASS: >= 5 of 6 runs pass. Rung FAIL: <= 1 of 6 pass at 8,000 updates. MIXED: 2-4 of 6 (no conclusion; recorded as such).
- R0 falsifier: < 50% dev accuracy at 2,000 updates in >= 5 of 6 runs -> the answer-pointer interface itself cannot learn a label at
  this share; stop, fix the interface first, read no other rung as a learnability result.
- The learning limit of the 3M model under this recipe = the first FAILing rung. Reported per rung: mean, spread (min / max) and worst run of
  dev accuracy at 2,000 / 4,000 / 8,000 updates; updates to pass; count baseline; non-logic in_dist of the stop checkpoint within 1.0 point of the parent
  (PASS only needs it reported; a drop > 3 points is flagged).
- Reported, never gated: new-words eval (held-out entity and predicate words), per-label recall, the panel's counterfactual probes
  (swap the queried name / delete the supporting sentence) on every passing checkpoint (a pass must move with the content).

## Next steps, decided by the outcome (one change at a time; the change is pre-registered after the read)
- R0 falsifier fires: fix the interface (single hypothesis, own marks), no further rung.
- First FAIL at rung k (k >= 1): the single next change is dose (share 25% -> 50%), then updates, then lr, each its own read; mixtures of rungs
  (rung k-1 + k) as a curriculum after that.
- R5 PASS: the LT-1 transfer test (arms C / L / P, V / N / J marks, >= 5 seeds per arm) is re-sealed and run. Not before.

## Addendum 1 (2026-10-14 ~7:50 AM ET, written BEFORE any LT-2 training result existed; rung-0 runs had started but logged no eval)
Implementation details fixed now. None changes a threshold or a rule above; each only makes a sentence above exact.
- Venue of rung 0: the cloud container's CPUs (3 runs at a time, 1 thread each), not the Mac. Same code, same marks, same free CPU; it removes the wait for Ben's
  Mac session. The Mac is not used for LT-2 unless it is needed later.
- Stop/pass thresholds are computed per eval file from that file's train-fitted count baseline (negation-word count + sentence count lookup, fitted on the
  rung's train file): dev >= max(90, baseline + 25), wording >= max(80, baseline + 25). Example: on rung 1 the lookup scores 2/3 (it cannot see "unknown"), so
  the dev mark there is ~91.7%.
- R5 reading of "+25": gate by-depth bars (0-1 >= 80, 2 >= 65, 3 >= 55) AND whole-gate accuracy >= gate baseline + 25. The dev file is reported, not gated.
- Eval files: R0 dev + wording (gated), newwords (reported); R1 and R2 dev (gated), newwords (reported; their "wording" file only repeats the dev wording
  because plain sentences have no templates, so it is built but not used); R3 placebo_dev + placebo_test_wording (the LT-1 files, same seeds 12/25/26, so
  byte-identical to the sealed hashes); R4 dev + gate (gate = held-out wording, depth 1, 1,200 rows); R5 gate (1,608 rows = 134 per depth x label), dev and
  deeper (800 rows, depths 4-5) reported. R4/R5 have no new-words file (the logic lexicon hold-out is not built).
- F2 as built: joint matching of (distinct predicates, singleton predicates, sentence count) per depth across the three labels, which is stronger than matching the
  singleton count alone; the lookup attack on that triple is asserted <= 37% on every R4/R5 eval file at build time. Eval files also exclude every train prompt.
- Falsifier (R0): read on the dev eval at exactly 2,000 updates (CPU: the 400-row prefix); a run that stopped early on its marks counts as above 50%. The driver
  fires it as soon as 5 of 6 runs are below 50% at 2,000 updates (or it is certain they cannot be).
- Per-run PASS counts only evals on the WHOLE file (CPU: the confirm at the stop point and the final eval). A run that meets its marks once on a 400-row prefix but is
  never confirmed is recorded as "near", not as a pass.
- GPU agreement check, made exact (same intent as "same seed, 200 updates, eval within 1 point"): after training, chaotic float divergence between devices
  makes mid-learning evals differ by many points even when both paths are correct, so the check is (a) the SAME checkpoint decoded on CPU and on GPU over the
  same 400 dev rows: accuracy gap <= 1.0 point and >= 98% identical predictions; and (b) the GPU run's training-loss window at update 250 within 3% (relative) of the
  CPU run's window at the same update, same seed, same rows. Both must hold before any GPU result counts.
- Seeds for the row files: rung r base = 100 + 10 r: train base, dev +1, wording +2 (R4/R5 gate), newwords +3 (R5 deeper).
- Counterfactual probes (reported only; logic_transfer/probes.py) for rungs 0-2: R0 swap the stated answer word / delete the answer sentence; R1-R2 swap the
  queried entity to an unseen one (gold unknown) / flip the query's "not" / delete the supporting fact (gold unknown). Gold of every edited row is re-derived by the
  independent reader.
- Money: this thread appends its row to /mnt/project-files/vast/SPEND.md before any rental (none rented as of this addendum). The Mac-venue sentence in "Compute and
  money" above is superseded by the first bullet here.
