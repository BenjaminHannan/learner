## What is tested and why this way

- Model: T1SDR (custom_io model 'tool', 3,314,132 params, outside calculator), parents s200, s201, s204
  (/mnt/project-files/checkpoints/cio-1007/). The G1 model (Gemma front) cannot run off the PC (Gemma runs live on
  every batch; weeks on CPU), but T1SDR uses the same skills curriculum and the same "variant" split that holds G1's
  unpractised-wording misses.
- Logic practice: program-checked first-order forward chaining (package logicgen/): rules "every P is Q", "no P is
  Q", "anything P and Q is R", "anything not P is Q", "if e is P then e is Q"; facts with negation; query -> true /
  false / unknown; depths 0-3 in training; fresh nonsense or common words per problem; >= 12 templates per rule kind,
  1/3 held out; 1-3 distractors incl. near misses; <= 208 chars; every label checked by the forward-chaining checker.
  This is procedurally generated data, NOT a new teacher model (fits the "no new teacher" rule).
- Rows are trained answer-only with NOOP calls, exactly like the existing syllogism/prop_eval families, because this
  model has no text-writing channel for steps (its only call writer is op + two numbers). The proof steps are kept in
  the row file. Disclosed against Ben's no-answer-only rule: no target the model can produce is cut.
- No hand-written logic goes inside the model. An outside logic tool is NOT tested in LT-1 (see "Tool" below).

## Arms (continued training from each parent; lr 1e-4 constant after 100 warmup, batch 64, AdamW as the original)

- C: 100% curriculum replay (sk200k train, the parents' own data). The 25% "extra" slots come from a separate
  curriculum stream, so the other 75% is identical to L and P batch for batch.
- L: 75% curriculum + 25% logic rows (train split).
- P (placebo, "depth-0 look-alike"): 75% curriculum + 25% rows with the same contexts, templates and answer words as
  L, but every query is answered by reading one stated fact: true = stated, false = opposite stated, unknown = neither
  stated nor derivable. No row ever labels a derivable atom wrongly. L - P therefore isolates multi-step chaining.
  Known property: P is a lookup task and easier; a surface-feature classifier (no exact-match features) scores 49%
  on P rows vs 40% on L rows (majority 33%). Both learning curves are logged so the difficulty gap is on record.
- Pair = (parent, course seed). Within a pair, all arms share the curriculum stream.

## Stage G: feasibility gate (runs first; s200, arms L and C, 8,000 updates, checkpoint every 1,000)

Scored on held-out wording ("gate" split, 400 items per depth 0-3, labels balanced within depth) and on the
rule-first generator (test_sampler, a different generator). Chance is 33.3%.

- G-PASS (logic learned): the first checkpoint k where ALL hold: held-out depths 0-1 >= 80%; depth 2 >= 65%;
  depth 3 >= 55%; rule-first depths 2-3 pooled >= 50%; non-logic in_dist within 1.0 point of the parent.
  That k becomes the dose D for every arm and parent.
- G-PROVED WRONG: at 8,000 updates held-out depth 3 < 45% OR rule-first depths 2-3 < 45%. Then LT-1 stops: "this
  model does not learn chaining from answer-only practice at this dose", and transfer is not read.
- Between: one more try with ONE change, logic share 25% -> 50% (P matched), same gate marks.
- Reported, not gated: logic dev (train wording) by depth; depths 4-5; per-label accuracy within each depth; the
  surface-feature audit numbers; P's own accuracy on its held-out wording (expected >= 95%).
- V and the other transfer numbers of the gate pair are NOT looked at until the screen is scored.

## Stage S: screen (3 pairs: s200, s201, s204 x course seed 1, arms L, P, C at dose D)

Measures (big dev, 200 rows per family x split cell; exact match, custom_io's own scorer):
- V-all (primary, Ben's literal claim): variant-split accuracy pooled over the 29 NON-logic trained families.
- V-text and V-calc: the same, split into non-logic families where >= 50% of dev rows parse to a calculator program
  (V-calc) and the rest (V-text). The split is computed from the dev rows by logic_transfer/score.py BEFORE any arm
  is scored and written to the results file.
- N (near): the 5 logic-flavoured trained families (syllogism, prop_eval, rule_apply, kin_chain, order_chain),
  variant + vocab + frame splits pooled.
- H (harm): non-logic in_dist accuracy.
- Reported only: answer, frame, vocab splits; never-trained families (floor, 1.3%); round-1 NOOP rate on calculator
  dev rows per arm; answer-word histograms (yes/no/true/false/unknown) per family per arm; train loss on each slice.

Screen -> confirm (go only if ALL): mean(L - P) on V-all >= +0.75; mean(L - C) on V-all >= +1.0; L - P > 0 on >= 2
of 3 parents; G-PASS. OR: V-text mean(L - P) >= +1.0 with all 3 parents positive. Also: if the per-pair SD of
L - P on V-all is > 1.5, the confirm cannot reach a verdict at these marks: report "underpowered", don't run it.
Otherwise stop and report "no sign of transfer at the screen".

## Stage F: confirm (6 pairs = 3 parents x course seeds 1 and 2; only if the screen says go)

Statistics: per-pair differences on identical items; paired t over the 6 pairs (df 5); also the 3 parent-level means,
which must share sign for "confirmed". (The 6 pairs are 3 parents x 2 course seeds, a loose reading of the project's
">= 6 paired seeds"; the all-parents sign rule is the guard.)

- V PASS: mean(L - P) >= +1.0 AND mean(L - C) >= +2.0, both with 95% CI above 0; parent-level L - P > 0 for all 3;
  H holds.
- V PROVED WRONG: the upper 95% bound of mean(L - P) on V-all < +1.0.
- V-text PASS: mean(L - P) >= +2.0, CI above 0. PROVED WRONG: upper bound < +1.0.
- N PASS: mean(L - P) >= +3.0, CI above 0. PROVED WRONG: upper bound < +1.0 (then "helps with stuff" is dead at
  this size, since logic would not even help its nearest neighbours).
- H: mean(L - C) >= -1.0 and mean(P - C) >= -1.0 on non-logic in_dist. Fails -> any gain is reported with the harm.
- P check: if mean(P - C) <= -1.0 on V-all with all 3 parents negative, the placebo carries its own harm; then
  L - P is inflated, only L - C is reported, and nothing is confirmed.
- Anything else: "inconclusive".

## J: far-transfer joins (exploratory, confirm phase only)

The L9 learn test (domain.far.learn_probe, arm LB, rows train-rows-l9.jsonl, 4,000 updates) from the L and P
checkpoints of the confirm. Read F4 (test joins, 420 items) at 500/1,000/2,000/4,000. "A lead worth its own test" if
L - P >= +4 on all 3 parents; "dead" if L - P <= 0 on 2 of 3. F5 (far, ~1.5%) is at the floor and is reported only.
Reason for demotion: one identical rerun differed by 2.6 points, so the J CI half-width is about 3.4 even at 6 pairs.

## Tool (not in LT-1)

An outside logic tool that parses English would put the hard part (turning text into rules) in hand-written code, so
it would test nothing about the model. An honest tool (a fact store the model fills with span-copy calls) needs more
than the 7 call rounds this model has for most problems. Zero-training follow-up: count how many generated rows fit
in 7 two-argument calls; >= 60% of depth <= 3 rows -> a tool test is possible; < 30% -> needs more rounds first.

Opus: gate passes by 8,000 updates 40%; V confirmed 5%; no arm separable on V ~60%.
