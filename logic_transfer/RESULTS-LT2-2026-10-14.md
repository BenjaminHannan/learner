# LT-2 results: can the 3M model learn logic? (10-14-2026, all times ET)

## Plain version (for Ben)
We built a staircase of logic puzzles and trained the 3M-parameter model on each step, six runs per step, with the pass marks fixed before any run.
- Step 1 (one fact, one question): the model reached the bar in 5 of 6 runs when we gave it twice the usual share of puzzles, after roughly 100,000 to 250,000 practice puzzles (4 of 6 under the stricter "twice in a row" rule). That step can also be passed by a shortcut (comparing first letters), so it is a weak sign of logic.
- Step 2 (several facts, pick the right one): 0 of 30 runs passed across the first five versions of the recipe (the standard one, twice the share of puzzles, twice as long, three times the learning rate, and a version with only two facts; that last one scored 66 out of 100 on the main test ("dev") against a pass mark of 90, and 21 out of 100 on the tricky puzzles against 80). A tricky puzzle names a person in one fact and a property in a different fact (for example "Uma is daxtar. Hank is vemmip. Is Uma not vemmip?"), so the right answer is "unknown". The sixth version gave the two-fact step three times as long (24,000 training updates, finished 6:53 PM). Across its six runs the average was 79 on dev (pass mark 90) and 50 on the tricky puzzles (pass mark 80). One simple cue (the two facts differ in "not") already gets 17 of the 32 tricky puzzles, so a score near 50 is not progress by itself. Five runs ended at dev 70-84 and tricky 22-63. One run (s200-s2, started from the s200 starting model) cleared both pass marks (dev 93.0 and tricky 90.6) at two checks in a row, after about 624,000 puzzles; it is the only one of six, so the verdict stays FAIL. Suggested, not shown: at least one run learned to pick the right fact, slowly. Untested: whether the other five would get there with more time, whether the starting model matters (both s200 runs are the two best, which falls on one starting model by luck 20% of the time), and whether the pass repeats.
- Steps above: step 3 stayed at chance, step 4 stayed at or below a simple counting baseline, and step 5 could not be read (the rented GPU box crashed ten times).
This shows the model did not learn it reliably with this training, not that it cannot. Cost: the whole Vast account fell about $11.9 (of the $50 weekly cap) since the 10-13 top-up, which includes other threads' boxes; the logic line alone used about $10 of its $15 stage cap; the last box is destroyed. I would stop 3M runs here and only run the same steps on a bigger model next (the roadmap thread owns that; no bigger model exists yet).

Reading (corrected after review): the model reads the polarity of a matching fact (92.5% right when it commits on rows where the fact matches), but says "unknown" on only 38.0% (235 of 618) of the word-missing unknown rows and 20.8% of the hard rows. Hard rows are answered "unknown" less often than word-missing rows in all six runs (gap 17.2 points; about 2 row-sampling errors, since all runs share the same 32 hard rows; the gap grew during training from about 3 points before update 2,000 to 12 at 6,250-8,000). In the four R2 variants that gap was only 1.6-5.0 points, so there the hard-negative score mostly measured how rarely the model says "unknown" at all.
A rule that reads the matching fact's polarity and says "unknown" only when a word is missing would score 86.5% on this dev file (the model scores 66.1%); the model's "false" on 59% of hard rows is about what the polarity of one partly matching fact predicts (56-66%). So the pattern is an unfinished, graded match detector [suggested; its rule was not probed: untested], not a finished binding and not a clean "partial match plus a lean".
The dev rise in R2a (4,000 -> 8,000) is true / false recall (true 65 -> 76, false 64 -> 89); "unknown" recall (31.5 -> 34.0) and hard (29.7 -> 20.8) did not rise. Dev 90 alone can be reached by a rule that never binds (86.5-91.7%), so only hard >= 80 would show binding. Dev changes over the last 1,000 updates (+4.4, -0.3, +5.4, +7.3, +2.8, +4.9) are within 1-3 standard errors of a 386-row eval; the last-2,000 changes (+3.6 to +9.6, all six) are the firmer sign of a rise.
