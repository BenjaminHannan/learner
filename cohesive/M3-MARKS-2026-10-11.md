## Why a screen first (shown, read in code)
In the T1SDR loop (custom_io/models/tool.py `run`, lines 313-324) some Linear layers run **before round 1**: the
reader's keys and values (`core.*.kv` on the reader output X and on S0) and the word keys are computed once, then
reused every round. M1's pieces change all 28 Linear weights, including those. A skill choice made inside the loop
cannot change what was computed before the loop. So M3 on T1SDR only works if each piece keeps its skill with its
before-the-loop parts removed.

## The one change
For each of the five M1 subjects (s200 parent, same runs and final checkpoints as M1-MARKS-2026-10-10.md), take the
run's final checkpoint and put the **parent's** values back in every Linear weight whose layer is called before the
first round's first thinker block on a real batch (found by tracing: forward hooks record the order of Linear calls on
one DEV batch and one batch of that subject's panel; a layer counts as before-the-loop if any call to it comes before
the first call to `core.0.qkv`). Everything else stays as the final checkpoint. No training.

## Marks (per subject, then overall)
- **P1 skill stays with in-loop parts only:** near score of the trimmed checkpoint alone on its own panel (scored and
  decontaminated as M1 scored "final alone near") >= the untrimmed final alone near - 3. Proved wrong for that
  subject: below final alone near - 10. Ben's hair-miss rule (one question) applies.
- **M3-0 passes** if P1 passes for all five subjects. Then M3-1 (the in-loop gate trained by loss, its own marks
  before it runs) is built on the in-loop parts. **If any subject is proved wrong**, per-round picking waits for the
  ship model (reader keys recomputed per round, or pieces kept out of before-the-loop layers by construction) and
  M3 on T1SDR stops; that goes into the design as a shown fact.
- In between (some FAIL, none proved wrong): M3-1 runs only on the subjects that pass.

## Reported, not gated
The list of before-the-loop layers and the share of each piece's numbers they hold; far score trimmed vs untrimmed;
DEV pooled score of each trimmed checkpoint vs the parent.

## Prediction
P1 passes on all five (about 60% sure): the skills are mostly in how the thinker runs and the answer heads, not in the
reader keys. Most at risk: py and invoice, whose questions are long and lean on reading.

One parent, one seed (200), cloud CPU only.

### Addendum M3-0b, about 12:20 AM ET 10-11 (after M3-0's result, before any M3-0b run)
M3-0 result (m3-0/RESULT.md): PROVED WRONG on all five by the rule as written. But the rule was mis-specified (my
error, found in the result): a thinker block runs its cross-attention (`q`, `o`) before its self-attention (`qkv`), so
"any call before the first core.0.qkv" also caught `core.0.q` and `core.0.o`, which run every round inside the loop
(and not `core.1.q`/`core.1.o`). The trimmed set was therefore not "before the loop". M3-0 is kept as run and reported.
**One change:** the before-the-loop set is the layers whose output is computed before round 1 and reused:
`k_word`, `k_wc`, `core.0.kv`, `core.1.kv` (the trace's list minus `core.0.q`, `core.0.o`). The kv layers are also
used inside the loop on the tape; trimming them there too is the conservative reading. Same P1 marks, thresholds,
scoring and verdict rule as above.
Reported only: the same with only the word keys trimmed (`k_word`, `k_wc`), to tell word keys from reader keys.
Prediction: M3-0b is still proved wrong on at least three subjects (about 70% sure): the reader keys are how the
thinker reads the question, and a new subject is mostly a new way of reading it.
