## 1. The picture in one paragraph (for Ben)

Today the model is a brain with a lot of helpers stuck on the outside: a separate "is this my new subject?" checker,
a separate "will I get this right?" guesser, a separate copy of the whole brain for every new subject, three different
ways of practising, four different ways of not forgetting, and a script that decides when it sleeps. The one-model
design keeps one brain and turns every helper into something that brain does itself: it **reads** everything as letters,
**thinks** in one shared workspace, **speaks** every action (tool calls, notes, answers, moves) with one voice,
**knows itself** through one small self-sense read from its own thinking, keeps its **skills on one shelf** inside the
brain that it picks from itself, and **lives one day-and-night loop**: practise by day, learn safely by night.

## 3. The one model

Five organs, one state. Each existing part becomes a job of one of them.

### 3.1 Senses: everything comes in as letters
Gemma plus the letter window read the question. Tool replies, notes, help pages, game screens and the model's own
earlier notes all come in the same way: as letters on the tape, read by the same reader (B3 already does this for
calculator replies, **shown**, tool.py:164-212). No part gets a private input channel.

### 3.2 Brain: one looped thinker, one workspace
The shared blocks loop over one workspace (8 control rows plus the memory rows). Each control row has a named job:
- control 0: what to do next (today the call writer's row; in group 2 the writer reads the whole workspace),
- control 1: what I believe the answer is, and how sure I am (answer heads, H1's stop, and SB-2's planned guesser),
- controls 2-7: free working rows; no head reads them today (**shown**, ledger.py:131-132).
If GX experts pass, the blocks' MLPs become experts and the router reads the same workspace (**shown** in PR #57's
code: router = Linear(256, 52) on the layer-normed state).

### 3.3 Voice: one writer for every action
Group 2's byte writer already writes both tool calls and answers, with the tool picked by the first word
(**shown**, b3g2.py:61-93). The one-model design extends the same writer to every outward act:
`add 3 4`, `note ...`, `sheet B2*C3`, game moves, `practice <subject>`, `sleep`, and `answer <text>`.
Writing `answer ...` is the decision to stop thinking, so the separate stop threshold goes away (stage M6). The 25M
English talker, when it exists, is this same writer grown larger, not a second network (proposal for the talking
session, via the coordinator).

### 3.4 Self-sense: one small readout of the brain's own state
One small readout of the workspace with a few outputs, all trained on the model's own records. "Right" and "settled"
read control 1, where H1's stop already sits and where SB-2 puts the guesser, so no new row is needed; "skill" reads all
eight control rows (stage M1 tests whether that beats the reader's mean):
- **right**: chance my current answer is right (today: the outside guesser, L4; SB-2 tests this head),
- **settled**: safe to stop now (today: H1's stop head, L6),
- **skill**: which shelf piece to use, or none (today: the outside switch, L2),
- later **progress**: is this getting better with practice (today: the motivator head, L5).
These are one organ because they are one question asked four ways: "how am I doing on this?" The dopamine signal
(right minus guess) and the practice picker (edge, progress) are computed from it with fixed rules, like AdamW.
**Rule (shown by SB-2 and SB-2b, 10-11): the self-sense watches the brain but does not train it.** Its gradients stop
at its own input, as H1's stop head and M1's skill readout already do. Trained into the shared body, the "right" head
read worse than a frozen probe (AUC 0.536 and 0.523 against 0.585) and an old skill slipped (seq_next 85 -> 72.5 / 75).

### 3.5 Skill shelf: skills live inside the brain, picked by the brain
A new subject gets a small low-rank piece on the shared blocks (today's rank-8 add-on, 135,488 numbers at 3M,
**shown**). Instead of a second checkpoint plus an outside switch, all pieces sit on one shelf inside the one model,
and the self-sense's **skill** output picks which piece (or none) to use for each question. If the guarded main brain
learns subjects well enough on its own (main brain SB-1), the shelf becomes the brain's short-term memory: pieces are
folded into the shared blocks at night and the shelf is emptied (stage M4). Either way there is one model file.

### 3.6 One life loop: day and night
- **Day**: answer; when free, practise. The self-sense picks problems at the edge of what it can do; tries are checked by
  tools or the world (calculator, sheet, RPN, Python runner, game); checked tries are kept. One engine for domain mode,
  ST1 and sleep's records (closes L7).
- **Night**: one guarded update (the K-FAC guard if the main brain's full run passes) on kept tries plus replay of what
  the self-sense says it is losing; then fold shelf pieces into the brain if that test passes (closes L8, L9).
- The model asks for practice and sleep by writing `practice ...` and `sleep` (closes L10). The training code is an
  outside tool it calls, which the no-hard-coding rule allows.

### Risks (what could make this design wrong)
- R1 (M1/M3) The brain's state may not tell look-alike questions apart any better than the reader's mean does. The
  dopamine D0 probe found the thinker's state did not help the guess (Brier 0.284 vs 0.265 with reader features only,
  **shown**). If M1 finds the same for the skill choice, the self-sense should read the reader as well as the workspace.
- R2 (M4) Folding may forget old skills the way plain nights do (v2: drop 4.19, 7 families fired, **shown**); the guard
  is the main brain thread's result to reuse.
- R3 (M2) A self-sense trained with gradients into the brain may bend the answers (SB-2 sends gradients in; H1 detaches
  on purpose). SB-2's G2/G3 marks test this.
- R4 (M5) The ship model's 3M run has not happened; the life loop on it cannot be scored before the PC is free.
- R5 The K-FAC guard and the sleep recipe are training rules, like the optimizer. Counting them as "learned" is a choice
  (suggested reading of the no-hard-coding rule: hand-written rules for how weights update are allowed, as AdamW is).

## 6. Size rule
The shelf counts in the size: every piece the model carries is counted in the whole-model number, as Gemma is. At 3M a
piece is 135,488 numbers (4% of the trained part, **shown**). Five pieces = 677,440 numbers, smaller than one extra
brain copy (3,314,132 each, **shown**): parent + five copies = 19.9M numbers, one model with a five-piece shelf = 4.0M,
about 5x smaller (arithmetic).
