M1 puts all five pieces on **one shelf inside one model**: the parent's weights, five rank-8 pieces (each piece = the
difference between that run's final checkpoint and the parent, which is exactly rank 8 per changed layer, shown for
stats: 28 of 101 tensors differ, all with rank min(rows, 8)), and one **skill readout** that picks, for each question,
one piece or none. The readout is fit once from the model's own records and is saved in the same file. No outside switch,
no second checkpoint.

## Arms (both fit once, same rows, same fixed settings)
- **T (the one tested): the brain's own workspace.** Features = the 8 control rows of the parent's thinker after its last
  round on the question (8 x 256 = 2,048 numbers), standardised with the training mean and spread.
- **R (comparison, reported only): the reader's mean**, as today's switch: the mean over the question's letters of the
  parent's reader output (256 numbers), standardised (domain/route.py `features`).
- Readout: a 6-way softmax (none, sheet, rpn, stats, invoice, py) on the standardised features. Adam lr 0.01, 400
  full-batch epochs, L2 1e-4, seed 0 (route.py GATE values, fixed before any routed result), each class weighted to the
  same total weight. Decision = the largest of the six (no threshold).
- Training rows (the model's own records only; no panel or DEV row): class k = unique prompts of run k's row events
  with source own or tool (route.py's rule); class none = unique prompts of the five runs' diary row events.
- The model's answer to a question = the parent's answer if the readout says none, else the answer with piece k on.

## How it is scored
Per-question hits of the parent and of each run's final checkpoint come from domain/analyze.py (`score_one`,
`in_dist_one`, cached). The one model's hit on a question is the hit of the checkpoint its readout picks. Before any mark
is read, an equivalence check runs the single saved shelf file directly on 300 panel questions (60 per subject, seed 0)
and 200 DEV rows: its answers must match the picked checkpoint's answers on at least 99% of them. If that check fails the
code is fixed first; it is not a result.

Sets: the five panels above (decontaminated as each run's own analysis did); the skills DEV in_dist file (1,360 rows,
sha256 f975d9fb312c02d7...); the look-alike old-skills panel lookalike-old.v1.jsonl (800 rows, 8 variants); the held-out
look-alike panel lookalike-old-heldout.v1.jsonl (reported).
