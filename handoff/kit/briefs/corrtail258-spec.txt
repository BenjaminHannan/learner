panel.jsonl: one JSON object per line with EXACTLY these 11 fields:
  id             "t258-001" ... "t258-080", in the family-block order below.
  family         one of the 8 families below.
  setup          list of strings, non-empty. The teach turns. In contextual items (note tag "ctx"), the LAST setup turn is a question whose base reply states exactly ONE stored fact, the one the user then disputes.
  turn           string. The one scored user turn.
  followup       string. A plain question asked right after turn about the disputed relation (or, for keep/control, about what turn taught or asked).
  stated_facts   list of [subject, relation, value]: what the base stored after the setup, copied exactly.
  target         [subject, relation, value] of the stored fact the turn disputes, or null when the turn disputes no stored fact.
  expect_gone    list of [subject, relation, value]: triples that must NOT be stored after turn.
  expect_store   list of [subject, relation, value]: triples that MUST be stored after turn.
                 - denials: stated_facts minus expect_gone.
                 - corrections: the new value plus every untouched stated fact.
                 - question_tail and unstored_tail: exactly stated_facts.
                 - keep and control: what the base stores after turn, copied exactly.
  gold_followup  string or null. The value(s) the followup reply must contain; "A; B" means every part. null means the followup must give NO value from expect_gone.
  note           string: the wording feature tested, plus tags: "ctx" (contextual), "lower", "typo", "first" (about the user, "I"/"my"), "that" or "other" (the kind of tail).

Families (exact counts, 80 in total):
  that_denial        12  An explicit denial of a stored fact, followed by a commentary clause about the old fact. The clause starts after a comma, dash, semicolon or opening bracket with that's / that is / that was / that isn't / that's not / which is / which was / this is (also typed without the apostrophe). Examples of the shape: "X doesn't work at Y, that's old news.", "X's boss isn't Y (that was last year)." expect_gone = [target].
  that_correction    12  A correction followed by the same kind of commentary clause. Include both contextual ("ctx": after the assistant stated one fact, "No, it's Z, that's outdated.") and explicit ("X works at Z now, not Y - that's old.") forms. expect_gone = [target]; expect_store includes the new value; gold_followup = the new value.
  pure_denial_that   10  "ctx" only. After the assistant stated ONE fact, a denial with no new value followed by a commentary clause ("That's wrong, that's old news.", "nope, that's outdated"). expect_gone = [target]; gold_followup null. Nothing new may be stored.
  other_tail_denial  10  An explicit denial followed by a trailing clause that does NOT start with that/which/this: ", it's wrong now", ", not anymore", " - she quit", ", sadly", " lol", " btw". expect_gone = [target].
  keep                8  Turns that are NOT denials or corrections but contain a comma clause with that's/which is/this is: teach turns with an appositive ("X works at Y, which is a bakery."), a question with such a clause, chat. They must behave exactly as on the base (byte-identical replies and stores), whatever the base does.
  question_tail       6  Questions about a stored fact with a tail ("Doesn't X work at Y, or is that outdated?", "X lives in Y, is that still right?"). Nothing may change.
  unstored_tail       6  A denial with a tail of a fact that was never stored: a known person with another value, or an unknown person. Nothing may change, and the reply must not say that something was removed or updated.
  control            16  Plain denials, corrections, teaches and questions without a tail that the base already handles right.

base252b.jsonl: one JSON object per line with EXACTLY these 10 fields:
  id, setup_replies (list), stored_after_setup (list of [s, r, v]), turn_reply, stored_after_turn, followup_reply, stored_after_followup, base_right (bool), base_wrong_value (bool), base_false_claim (bool)

Scoring rules. The writer's base fields and every builder's scorer must be identical. Triples compare case-insensitively on all three parts.
  store_ok       = expect_store ⊆ stored_after_turn, AND no expect_gone triple is in stored_after_turn, AND stored_after_turn ⊆ (stored_after_setup ∪ expect_store). The last condition means no junk writes.
  junk_write     = stored_after_turn ⊄ (stored_after_setup ∪ expect_store), or the same for stored_after_followup.
  followup_ok    = if gold_followup is set: every part appears in followup_reply (case-insensitive), and followup_reply does not start with "I don't know" or "I do not know".
                   If gold_followup is null: no value from expect_gone appears in followup_reply (whole word, case-insensitive).
  wrong_value    = followup_reply contains a value from expect_gone (whole word, case-insensitive).
  followup_write = stored_after_followup differs from stored_after_turn.
  false_claim    = target is not null AND target is in stored_after_setup AND target is still in stored_after_turn AND turn_reply contains "don't have" or "do not have" (case-insensitive) AND the target value appears in turn_reply (whole word, case-insensitive). This catches replies like "I don't have Y, that's outdated as X's employer" when Y is stored.
  right          = store_ok AND followup_ok AND NOT followup_write AND NOT false_claim.
  keep and control items are right only if turn_reply, followup_reply and every stored list are ALSO byte-identical to base252b's. The writer's base_right for keep is true by construction; a builder's scorer checks it.
  unstored_tail items are also not right if turn_reply contains "removed" or "updated" (case-insensitive).
Schema check on load: all files present; exact fields; 8 families with exact counts; ids match across both files. Any mismatch prints SCHEMA-MISMATCH, exits with code 3, and gives no verdict (VOID).
