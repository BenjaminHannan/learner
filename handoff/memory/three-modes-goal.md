Ben (2026-09-21): "I want it to do agentic work when I ask, and when I'm not asking it to do stuff it's either sleeping or thinking like how we discussed." Three modes: WORK (tool calls on request, via the Codex-fork harness, [[web-search-tool-idea]]), THINK (idle: [[dreamer-checker-idea]] — propose links/rules, verify against the notebook, keep survivors labelled "inferred, not taught"), SLEEP (idle: the sleep design agreed 2026-09-18 in [[human-learning-redesign]] — consolidation pressure + naps, sleep as a transaction with wake-up check and roll-back, NREM sort/repair then REM dreams; v1 = notebook-only tidy: dedupe, flag conflicts, invalidate stale inferences, told-ledger check; weight consolidation is v2, only once a need is measured).

**Why:** this is the end-state shape of the [[teachable-assistant-goal]]; the outside review ([[outside-review-28-adjudication]]) says park dreamer/web/tools for now, so these are modes built on top of the notebook contract, not parallel branches.

**How to apply:** design the notebook contract so all three modes are just different callers of the same event log (WORK and THINK write "proposed"/"inferred" rows, never "taught"; SLEEP only derives). Order: notebook contract → talking teach/ask assistant → THINK/SLEEP on the notebook (cheap, Mac) → WORK with read-only stub tools. Don't claim agent competence from a demo harness.

Added by Ben 2026-09-21: THINK mode should have web access. Rule (outside review #35): web findings go into a quarantine with source, quoted span and time; they become notebook facts only when Ben approves or a written source policy says so; page text is data, never instructions; spending limit on searches (the 'hunger-like' compute budget). Gap curiosity (from the motivation memo in [[human-learning-redesign]]) is the drive that triggers a search. See [[web-search-tool-idea]].

**Revised by Ben 2026-09-21 — four modes, persistent agent that is always doing something:** (1) WORKING: scope a job, then do it (can still be creative). (2) CREATIVE: for harder jobs with an ambiguous path — test different leads (= dreamer + checker pointed at a task: branch, check, keep what survives). (3) BORED: nothing assigned — sits and thinks (self-directed: gap curiosity, practice by learning progress, web lookups into quarantine). (4) SLEEP: as agreed. My notes to Ben: mode switching starts as a plain rule-based scheduler (job queued → work; job marked open-ended or work stalls → creative; queue empty → bored; consolidation pressure high → sleep), learned later; 'always on' needs the hunger-like spending limit and a log Ben can read; bored mode picks from existing drives and does not invent its own goals (self-proposed tasks stay v2); an assigned job always pre-empts bored/sleep (sleep finishes or rolls back its transaction first).

**Ben 2026-09-21: "It gets my 5070-ti"** — the persistent agent lives on BensPC and the RTX 5070 Ti is its compute (run/think/sleep). Spending limit = GPU time + web searches. Native Windows Python, resumable runs ([[benspc-gpu-ops]]). Mode designs: four GPT xhigh drafts then a Fable max audit that joins them (Ben asked for this explicitly, an exception to [[subagents-gpt-xhigh]]).

**Final mode list (Ben, 2026-09-21): LISTENING, WORKING, CREATIVE, BORED, SLEEP.** LISTENING (my addition, Ben accepted): Ben is teaching/correcting/asking; only mode that writes 'taught' rows; pre-empts everything; confirms a save only after a durable write; asks when a reference is ambiguous. No separate WAITING mode (Ben: 'should just be the bored mode'): a job blocked on Ben parks with a pending-question record, the agent drops to BORED, and the question sits at the top of Ben's digest; the job resumes when he answers. 'Always doing something' = always in a defined state; budget spent → rest and log it.

**Integrated design written 2026-09-21:** design/v3/30-modes/31-modes-integrated-design-fable-review.md (Fable audit of three GPT xhigh drafts). Key rulings: only the scheduler switches modes (modes return exit events; everything from Ben enters via LISTENING; rest = sub-state of BORED); 'inferred' = fact derived by a Ben-approved rule, written only by the shared checker, candidate rules/merges are 'proposed' (open: Ben to confirm this reading); budgets enforced by the harness not the modes; one lead engine shared by CREATIVE/BORED/REM sleep; missing personal facts park the job and ask Ben, never search; sleep in <=60 s transactional chunks. Build order M1 notebook + LISTENING → scheduler → working → creative → bored → sleep → run on BensPC. Nothing built yet.

**Ben's simplification 2026-09-21 (overrides earlier lists; design/v3/30-modes/32-ben-simplification-ruling.md):** default state = THINKING (old bored; thinking is unrestricted, only writes are labelled); SLEEP when memory too full, naps OK, Ben's work always wakes it; WORK on demand; CREATIVE is a sub-routine inside WORK (stall → brainstorm → idea → back to work; no idea → ask Ben); LISTENING is the doorway. THINKING may browse the web for things it judges helpful to learn (reason logged, quarantine, budget); it may choose what to read but may not start side-effect jobs on its own.
